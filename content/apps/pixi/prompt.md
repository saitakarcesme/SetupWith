# Pixi setup prompt

Set up Pixi from the official prefix.dev installation guide (https://pixi.prefix.dev/latest/installation/). Detect Windows, macOS, or Linux, architecture, shell and profile files, package managers, existing Pixi binary and home, Conda or Mamba configuration, `.netrc`, keyring providers, global tools, cached packages, and workspaces containing `pixi.toml`, `pyproject.toml`, `pixi.lock`, or `.pixi`. Prefer Homebrew, Winget, Scoop, MSI, or a checksummed standalone release. If using the official script, download and inspect it first; do not pipe network content into a shell or bypass PowerShell execution policy automatically.

Install the Pixi binary without initializing a workspace, editing shell profiles, generating completion, authenticating, solving, downloading, or creating environments. Preserve manifests, lockfiles, channel order, platform constraints, environment directories, caches, global manifests and trampolines, configuration, credentials, shell activation, tasks, CI files, and every uncommitted change. Apply only approved channels, target platforms, environments, or global tools, and preview exact manifest plus lockfile diffs before mutation. Never mix an installation method's self-update mechanism with its package manager.

Treat workspace tasks and package build scripts as arbitrary code. Stop before `pixi run`, `exec`, `shell`, `install`, `update`, `upgrade`, `reinstall`, `import`, `build`, `upload`, or dependency changes. A normal install may update both the lockfile and environment; use locked or frozen behavior only when explicitly requested and explain the difference. Never disable TLS verification, embed credentials in a channel or download URL, print `.netrc`, enable a subprocess keyring without review, trust an unknown channel, or send secrets into cache keys and logs. Global tools add executables to PATH and require separate approval.

Verify artifact checksum, `pixi --version`, resolved executable, installation method, Pixi home and PATH precedence. Inspect an existing workspace with read-only metadata and list commands that do not solve, install or run tasks; do not create a sample environment because package execution is not required to validate installation. Confirm no network request, manifest, lockfile, environment, cache, global trampoline, credential, shell profile, completion or Git state changed. Roll back only the binary and setup-owned PATH entry, preserving Pixi home, environments and caches; never invoke the documented clean commands or recursively remove managed data automatically.
