# Blender setup prompt

Codex, inspect the operating system, architecture, shell, GPU hardware, drivers, existing Blender installation, preferences, add-ons, asset libraries, workspaces, and render devices before changes. Use Blender’s official signed installer or archive for supported macOS, Linux, or Windows platforms; Homebrew Cask is acceptable on macOS when it already manages desktop applications. Ask before administrator access, replacing an application, changing file associations, installing add-ons, downloading assets, enabling scripts, or modifying GPU drivers. Preserve startup files, user preferences, add-ons, templates, recent files, and asset catalogs. Configure only `render_engine`, `asset_library_path`, `default_workspace`, and `gpu_backend` when supplied. Validate that the requested engine and backend are supported by detected hardware; do not silently enable experimental features. Add asset libraries through Blender preferences without moving existing files. Verify application launch, `blender --version`, background-mode execution, preference loading, GPU-device detection, and rendering of a temporary built-in scene to a disposable output path. Do not open or modify user `.blend` files. Rollback restores backed-up preferences, removes only add-ons or asset entries created here, and uninstalls only the application channel added in this run. Finish with a structured summary of package source, GPU, engine, workspace, assets, verification, approvals, and rollback.
