# Paperwork setup prompt

Set up Paperwork from its official GNU/Linux installation guide (https://www.openpaper.work/en/download/linux). Detect architecture, distribution and package manager, existing distro, Flatpak or AppImage installation, document work directory, index and training data, OCR engines and languages, USB or network scanners, synchronization tools and pending conflicts. Prefer the reviewed distribution package recommended by OpenPaperwork. Do not add OpenPaper's master Flatpak remote, install an unreviewed build, replace an AppImage, add FUSE, broaden scanner permissions, or switch packaging methods without approval.

Install without launching Paperwork, choosing a work directory, discovering scanners, importing files, running dependency checks that access devices, or building an index. Preserve every JPEG page, hOCR file, PDF, document directory, label, date, search index, automatic-label model, OCR result, thumbnail, scanner setting, sync marker, conflict and backup. Paperwork keeps documents under one ordinary directory; never create a second library, move it into a sync root, merge two roots, migrate formats, or assume a generated index can safely be deleted.

Scanned papers can contain identity, financial, medical, legal and customer data. Do not open a scanner, acquire a page, alter feeder or resolution settings, enumerate a private network, upload diagnostics, or submit a scanner report. OpenPaperwork scan reports require a scanned page and may publish it with optional identity information; never use a real page or submit a report during setup. Before any later scan, show device, transport, source, duplex mode, DPI, color, page count, destination and retention.

OCR and re-indexing consume CPU and modify hOCR, orientation, index and learned-label state. Do not rotate, crop, enhance, reorder, merge, split, relabel or delete pages and documents without a backup and exact before/after preview. Do not let two synchronized machines index and rewrite the same documents concurrently, and never auto-resolve a sync conflict. Verify package provenance, version, executable, package ownership, declared dependencies, data paths and sandbox permissions from metadata without the GUI. Confirm no device request, document read, index, model, OCR file, sync state, diagnostic or network connection changed. Roll back only the installed packages and setup-owned launcher while preserving all documents and machine-learned state.
