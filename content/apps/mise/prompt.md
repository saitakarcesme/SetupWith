# mise setup prompt

Codex, inspect the operating system, architecture, shell, PATH, existing `mise`, `asdf`, runtime shims, and shell startup files before installation. On macOS prefer Homebrew `mise`; on Linux use a trusted distribution package when current or mise’s official installer after explaining the source; on Windows prefer `winget install jdx.mise`. Ask before administrator access, running a downloaded installer, changing PATH order, replacing existing version-manager hooks, or modifying project files. Preserve all existing `.mise.toml`, `mise.toml`, `.tool-versions`, and shell configuration. Configure only `default_runtimes`, `activate_shell`, and `global_config` when supplied. If activation is requested, add the shell-specific `mise activate` command in a marked, idempotent block. Store global runtime selections in the user config, but do not install large runtimes or migrate from asdf without approval. Never rewrite project-local version files automatically. Verify with `mise --version`, `mise doctor`, `mise config ls`, and `mise ls`. If approved runtimes are installed, confirm their executables resolve through a clean shell and report shim precedence. Avoid modifying the system default runtime. Rollback removes the activation block, restores config backups, and uninstalls only mise; runtime caches remain unless separately approved for deletion. Finish with a structured summary of detected managers, installation, config, runtime actions, verification, approvals, and rollback.
