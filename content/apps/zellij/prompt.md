# Zellij setup prompt

Set up Zellij from its official installation guide (https://zellij.dev/documentation/installation.html). Detect macOS or Linux, architecture, shell and terminal, package managers, existing Zellij binary, running sessions, configuration and layout directories, shell aliases, auto-start integration, plugins, themes, cache, and session metadata. Prefer the operating system package, Homebrew, Cargo Binstall, or an official checksummed release archive. Compile with Cargo only when explicitly requested; pin the released version and do not run an unreviewed install script.

Install the binary without launching Zellij, attaching to a session, creating a session, loading a layout, downloading a plugin, generating configuration, or editing a shell profile. Preserve all live and resurrectable sessions, panes, scrollback, commands, working directories, layouts, KDL configuration, keybindings, themes, plugin aliases and caches, permissions, shell integration, and remote-terminal state. Record the existing executable, version, package owner, config search path and session names through read-only inspection. Never replace a package-managed binary with Cargo or a manual archive, and never let two installation methods compete on PATH.

Treat every layout pane command and WebAssembly plugin as executable code. Before later loading a layout, inspect its KDL, display each command, argument, working directory, environment value, floating pane and plugin URL, and obtain approval. Do not grant plugin permissions, load code from an unpinned URL, forward terminal content, or expose tokens from environment variables and scrollback. Existing session names can contain active work; do not attach, resurrect, rename, detach other clients, kill sessions, close panes, clear scrollback, or use cleanup commands. Do not enable shell auto-start because it changes every interactive terminal and can recurse over SSH, nested multiplexers, CI shells, or IDE terminals.

Verify archive checksum or package provenance, `zellij --version`, resolved executable, installation method and PATH precedence without starting the server. If available, use commands that print help, dump a built-in layout to standard output, or check configuration without attaching; do not use a bare `zellij` command because it may create or attach to a session. Confirm the pre-install session list and configuration hashes remain unchanged and that no server process, socket, session, pane, plugin, cache, profile, alias, layout, terminal title, clipboard, or remote connection was created or modified. Roll back only the installed binary or package and setup-owned PATH entry, preserving all user configuration and session data.
