# Packer setup prompt

Set up Packer from its verified official source (https://github.com/hashicorp/packer). Supported targets: macOS, Linux, Windows. Begin with a read-only preflight covering the operating system, architecture, shell, package managers, disk space, relevant runtimes or hardware, and any existing installation. Use HashiCorp's signed official package or release, confirm architecture and checksum, and keep Packer plug-ins and cache in explicit user-owned directories.

Preserve Packer templates, variable files, plug-in locks, caches, manifests, build artifacts, and cloud credentials. Back up files before editing and explain the selected version, source, location, dependencies, and commands. Apply only supplied, supported preferences: plugin_directory, cache_directory, build_directory, cloud_provider. The only available credential references are secret://cloud/provider-credentials. Treat every reference as opaque: never print, echo, log, resolve, or paste its value.

Ask before elevation, system-wide packages, services or startup items, ports or firewall rules, sign-in, large downloads, overwrites, or migrations.  Do not enable startup items, background services, overlays, notifications, analytics, or device permissions unless they are requested and separately approved. Do not initialize plug-ins, contact cloud APIs, build images, start virtual machines, upload artifacts, or read secret variable files without approval. For a large game or media download, report the exact size, destination drive, free space, and bandwidth impact, then wait for approval. Never delete game libraries, save files, media libraries, mods, profiles, or cloud-sync data. If the platform or configuration is unsupported, stop and offer the closest official alternative.

Run `packer version`; validate only an approved template after initialization requirements are explained, and never execute `packer build` as part of setup verification. Report the version, executable, configuration and data paths, changed files, active processes or listeners, and verification evidence without exposing sensitive values. End with manual steps and exact rollback or uninstall instructions that remove only setup-owned changes, restore backups, stop new services, and preserve user data.
