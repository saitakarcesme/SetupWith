# Uptime Kuma setup prompt

Codex, first inspect the OS, architecture, shell, Docker or Node.js availability, existing Uptime Kuma deployment, data directory, monitors, notification settings, reverse proxy, and occupied port 3001. Prefer the official `louislam/uptime-kuma` Docker image with a persistent `/app/data` volume; use the documented Node.js installation only when containers are unsuitable. Ask before administrator access, installing container tooling, starting a service, exposing ports, changing firewall rules, opening a browser, replacing containers, or overwriting data. Preserve monitors, status pages, notification integrations, certificates, database files, and backups. Configure only `server_port`, `data_directory`, `public_url`, and `timezone` when supplied. Bind to localhost unless a reverse proxy, TLS, and authentication plan are approved. Do not configure third-party notification credentials automatically. Verify image or package identity, persistent mount, startup health, HTTP readiness, timezone display, and creation plus deletion of a disposable localhost monitor. Avoid probing external systems without approval. Rollback stops and removes only created containers or services, restores manifests, and retains the data directory unless deletion is explicitly authorized. Finish with a structured summary of deployment, storage, URL, timezone, monitor test, verification, approvals, and rollback.
