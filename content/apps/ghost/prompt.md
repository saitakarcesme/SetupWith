# Ghost setup prompt

Set up Ghost from its verified official source (https://github.com/TryGhost/Ghost). Supported targets: Linux. Begin with a read-only preflight covering the operating system, architecture, shell, package managers, disk space, relevant runtimes or hardware, and any existing installation. Use Ghost CLI on a supported Ubuntu host for production or the official container or local-development path for evaluation, keeping content storage and database versions explicit.

Preserve Ghost content, themes, images, database, members, mail settings, configuration, certificates, backups, and container volumes. Back up files before editing and explain the selected version, source, location, dependencies, and commands. Apply only supplied, supported preferences: deployment_mode, content_directory, database_name, listen_address, http_port. The only available credential references are secret://ghost/database-password, secret://ghost/mail-password. Treat every reference as opaque: never print, echo, log, resolve, or paste its value.

Ask before elevation, system-wide packages, services or startup items, ports or firewall rules, sign-in, large downloads, overwrites, or migrations.  Do not enable startup items, background services, overlays, notifications, analytics, or device permissions unless they are requested and separately approved. Do not migrate a database, create an owner account, install themes, configure mail, change DNS, request TLS, expose ports, or start production services without approval. For a large game or media download, report the exact size, destination drive, free space, and bandwidth impact, then wait for approval. Never delete game libraries, save files, media libraries, mods, profiles, or cloud-sync data. If the platform or configuration is unsupported, stop and offer the closest official alternative.

For a fresh local scope, confirm the loopback setup page and service logs, then stop without onboarding an owner or sending email. Report the version, executable, configuration and data paths, changed files, active processes or listeners, and verification evidence without exposing sensitive values. End with manual steps and exact rollback or uninstall instructions that remove only setup-owned changes, restore backups, stop new services, and preserve user data.
