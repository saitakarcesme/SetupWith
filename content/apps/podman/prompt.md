# Podman setup prompt

Codex, begin by detecting the OS, architecture, shell, existing Podman installation, rootless configuration, containers, images, volumes, registries, and any Podman machine. On Linux prefer the distribution’s official `podman` package; on macOS and Windows use Podman Desktop or the official CLI with a managed Podman machine. Ask before administrator access, creating or resizing a VM, enabling socket services, changing subuid or subgid mappings, exposing ports, changing firewall rules, or modifying storage configuration. Preserve all containers, images, volumes, machine disks, registry credentials, and `containers.conf`, `registries.conf`, and `storage.conf`. Configure only `storage_root`, `default_registry`, `machine_resources`, and `rootless` when supplied. Provide `secret://provider/REGISTRY_AUTH_FILE` only as a protected file reference; never print, echo, log, or copy its contents. Keep rootless mode when supported and validate storage-path ownership before changes. Verify `podman version`, `podman info`, machine status where applicable, registry search settings, and a disposable `hello-world` or equivalent official container. Rollback restores configuration, removes only the machine or package created here after approval, and never deletes user images or volumes automatically. End with a structured summary of platform mode, machine, rootless state, storage, registry, checks, approvals, and rollback.
