# Dconf Editor setup prompt

Set up Dconf Editor from its official GNOME project and verified Flathub listing (https://apps.gnome.org/DconfEditor/). Inventory Linux architecture, Flatpak scopes, existing package and data paths, dconf profile and database-layer names, schema and key counts, orphaned-key count, locked-path count, active-listener count, sandbox overrides and backup coverage without reading or revealing key names, paths, current values, defaults, account identifiers, histories, network endpoints, tokens or sensitive configuration. Install stable `ca.desrt.dconf-editor` from verified Flathub in the existing ownership scope. Do not compile from source, launch Dconf Editor, connect to a settings backend, enumerate keys, read a value, acquire a write lock, change or reset configuration, notify listeners, export a database, restart an application or alter system policy during setup.

Preserve every user and system database byte, layer, profile, lock, schema, key, value, owner, permission and timestamp, plus remotes, overrides and scope ownership. Direct dconf editing can break applications immediately; it is not equivalent to using an application's validated preferences UI. Treat values as potentially secret and redact them. Installation must not create an absent schema, normalize a GVariant, migrate orphaned keys, remove a lock, reset a subtree or make Dconf Editor the default handler.

Before a later edit, require the exact profile, database layer, canonical path and key, owning application, schema ID, GVariant type, constraints, schema default, current user value and effective value. Confirm the target application version and whether it watches the key live. Preview an exact typed old-to-new diff using placeholders for secrets. Reject type, range, enum, tuple or array mismatches. Batch edits need explicit ordering, concurrency handling and a recoverable snapshot; never assume multiple key writes are atomic. Use a disposable test profile and synthetic schema for behavioral validation.

Resetting a key, resetting a subtree and deleting a user override have different inheritance effects; display the child-key blast radius and resulting effective defaults. Respect locked and mandatory system policy rather than bypassing it. Verify provenance, app ID, origin, commit, runtime, executable, files and static permissions offline. Prove no backend connection, key enumeration, value read, write, reset, lock change, listener notification, export, restart or policy mutation occurred. On failure, rollback only the new Dconf Editor ref in its original scope; preserve shared runtimes, remotes, overrides, profiles, databases, schemas, locks, values, snapshots and backups.
