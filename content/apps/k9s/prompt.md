# K9s setup prompt

Set up K9s from the official derailed/k9s release and installation documentation (https://k9scli.io/topics/install/). Detect the operating system, architecture, shell, terminal capabilities, package managers, existing `k9s` and `kubectl` binaries, K9s configuration paths, and kubeconfig file locations without reading credential values. Prefer a checksummed release or the documented Homebrew, distribution, Winget, Scoop, or Chocolatey package. Avoid development `go install`, devmode Snap, Webi scripts, and third-party Docker Desktop extensions unless explicitly selected with their provenance risk understood.

Preserve every kubeconfig file and current context, cluster and namespace selection, RBAC identity, K9s config, per-cluster settings, aliases, hotkeys, views, skins, plugins, logs, screen dumps, benchmarks, and port-forward state. Back up only files that an approved change will touch. Apply the requested read-only mode, default namespace, refresh rate, or skin without replacing unrelated YAML. Keep the port-forward address on loopback and node-shell feature gate disabled unless separately approved. Treat plugins as arbitrary host commands whose environment can contain cluster, context, namespace, resource, and kubeconfig details.

Do not connect to any cluster until its server endpoint, current context, namespace, and authenticated identity are shown and approved. Never reveal kubeconfig tokens or certificates; view, decode, edit, delete, scale, restart, exec into, attach to, or port-forward a resource; create a shell pod; copy data through OSC52; run Popeye or image scans; execute a plugin; or change context automatically. Read-only mode reduces accidental mutation but does not prevent sensitive resource, log, or Secret visibility, so request permission before loading cluster data. Do not grant or broaden RBAC permissions for K9s.

Verify package provenance, `k9s version`, executable path, and `k9s info` configuration locations while offline. Validate YAML syntax and plugin command definitions without executing them. If cluster access is approved, launch with an explicit context and namespace plus `--readonly`, observe only non-sensitive resource metadata, then exit without changing current kubeconfig context. Confirm audit evidence shows no API mutation, port forward, shell pod, plugin process, screen dump, clipboard transfer, or configuration write. Roll back only setup-owned config and the installed binary, restore backups, and preserve all kubeconfigs, contexts, RBAC bindings, and cluster resources.
