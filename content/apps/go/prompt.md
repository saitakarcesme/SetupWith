# Go setup prompt

Codex, begin by detecting the OS, architecture, shell, PATH, existing `go` binary, package-manager ownership, `GOTOOLCHAIN`, workspaces, and project `go.mod` files. Prefer an existing mise or version manager when present; otherwise use Homebrew `go` on macOS, the trusted distribution package or official Go archive on Linux after explaining freshness and provenance, and `winget install GoLang.Go` on Windows. Ask before administrator access, replacing an existing toolchain, editing PATH, or downloading a different toolchain automatically. Preserve `go env` settings, module caches, workspaces, credentials, and project files. Configure only `go_version`, `go_workspace`, and `go_proxy` when supplied. Use `go env -w` only after backing up current values, and never set `GOPATH` unnecessarily. For private modules, reference `secret://provider/GOPRIVATE` only as a configuration alias; never print, echo, log, or place secret material in source files. Verify with `go version`, `go env`, `go tool dist list`, and a disposable temporary module that runs `go test` using only standard-library code. Do not download dependencies from an existing project. Rollback restores previous `go env` values and profile files, removes only the installed toolchain, and leaves module caches unless approved. Finish with a structured summary of install source, workspace and proxy settings, verification, approvals, and rollback.
