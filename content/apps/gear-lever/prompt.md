# Gear Lever setup prompt

Set up Gear Lever using its official documentation and verified Flathub package (https://gearlever.mijorus.it/docs/overview/). Inventory Linux architecture, desktop, Flatpak user and system scopes, existing Gear Lever package, AppImage files, managed folders, executable bits, hashes, desktop entries, extracted icons, open-with associations, CLI aliases and known update metadata. Install stable `it.mijorus.gearlever` from the verified Flathub origin in the scope matching current ownership. Do not install a development build, build from source, launch Gear Lever, open an AppImage or claim its file association.

Preserve every AppImage at its exact path with its name, bytes, mode, owner and timestamp; preserve existing desktop entries, icons, launch arguments, working directories and update preferences. Setup must not scan broad home folders, move or copy portable apps into a managed directory, rename duplicates, extract embedded assets, toggle executability or clean stale launchers. If a custom managed directory already exists, verify its ownership and free space from metadata only and never replace it with Gear Lever's default.

Treat each AppImage as untrusted native executable content, not as a harmless archive. Before any future integration or update, show the resolved file path, publisher evidence, cryptographic hash, signature or published checksum when available, architecture, required FUSE behavior, requested filesystem reach, embedded update source, redirect chain, target filename, whether the old version is retained and the exact desktop entry that would be written. Never execute an AppImage to discover metadata, trust a filename as identity, follow an unauthenticated FTP update, overwrite the only known-good version or expose the entire home directory to the Flatpak.

Do not create menu entries, extract icons, add shell aliases, register open-with handlers, update in place, keep side-by-side copies, trash applications or remove launchers during setup. Verify Gear Lever provenance, app ID, origin, installed commit, runtime, files, executable and declared permissions through Flatpak metadata without running it. Compare the preflight AppImage and integration inventories and prove no executable bit, portable binary, desktop entry, icon, handler, alias, network request or managed-folder content changed. If verification fails, rollback only the newly installed Gear Lever ref in its original scope; retain all AppImages, shared runtimes, remotes, overrides and integration files.
