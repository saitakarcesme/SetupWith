# Qdrant setup prompt

Codex, begin by detecting the OS, architecture, shell, container runtime, existing Qdrant binaries or containers, storage directories, collections, snapshots, and occupied ports 6333 and 6334. Prefer Qdrant’s official Docker image with a persistent volume on macOS, Linux, or Windows; use the official Linux binary only when containers are unsuitable and the host is supported. Ask before administrator access, installing or starting Docker or Podman, creating services, exposing ports, changing firewall rules, replacing containers, or modifying existing storage. Preserve collections, payload indexes, snapshots, configuration, and volume data. Configure only `storage_path`, `http_port`, `grpc_port`, and `default_collection` when supplied. Provide `secret://provider/QDRANT_API_KEY` only through secure runtime injection; never print, echo, log, or store its value in committed compose files. Bind to localhost unless remote access is explicitly approved. Verify the image or binary identity, storage mount, readiness endpoint, API-key enforcement when enabled, collection listing, and creation plus deletion of a disposable test collection. Do not alter existing collections or snapshots. Rollback stops and removes only resources created here, restores backed-up manifests, and retains storage volumes unless deletion is separately authorized. Finish with a structured summary of deployment, persistence, ports, authentication, collection configuration, checks, approvals, and rollback.
