# HTTP Toolkit setup prompt

Set up HTTP Toolkit from its official installation guide and desktop repository (https://httptoolkit.com/docs/getting-started/installing/). Detect Windows, macOS, or Linux, architecture, package managers, existing installations, firewall state, proxy settings, browser profiles, container engines, Android tooling, and prior HTTP Toolkit data. Select the signed Windows installer or portable archive, macOS DMG or official Homebrew cask, Debian package, or documented Linux archive. Verify publisher or checksum and do not disable antivirus, firewall, or platform security to make installation succeed.

Install and launch HTTP Toolkit without starting interception. Preserve all proxy settings, trusted certificate stores, generated CA material, rules, breakpoints, captured exchanges, exports, browser profiles, device VPNs, ADB state, container configuration, firewall rules, and upstream proxy credentials. Apply only the requested target, listen interface, upstream proxy, or certificate-validation whitelist. Keep listeners bound to loopback unless a specific device connection is approved, and never store proxy passwords directly in configuration or logs.

Traffic capture can expose cookies, authorization headers, tokens, personal data, request bodies, and private endpoints. Require explicit authorization for the exact application, account, hostnames, device, network, and time window before interception. Stop separately before changing a system proxy, trusting HTTP Toolkit's CA, opening firewall access, launching an instrumented browser, redirecting Docker traffic, installing an Android VPN or user CA, using ADB, injecting a system certificate, requesting root, rewriting traffic, exporting sessions, or disabling TLS validation. Never bypass certificate pinning, modify a third-party application, or capture traffic belonging to other users.

Verify application version, signature, executable and data paths, listening sockets, firewall state, proxy state, certificate stores, and generated CA fingerprint without exposing its private key. For a safe smoke test, use only HTTP Toolkit's documented test endpoint or a disposable local server after approval; confirm no unrelated traffic appears and stop interception immediately. Prove system proxy and trust settings match their baseline, no device VPN or ADB modification remains, and no capture was exported. Roll back by stopping listeners, restoring proxy and firewall settings, removing only setup-installed certificates from each approved target, and preserving pre-existing rules and captures.
