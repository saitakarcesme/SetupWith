# Elasticsearch setup prompt

Codex, first inspect the OS, architecture, shell, existing Elasticsearch packages or containers, Java ownership, cluster state, node roles, data and log paths, security configuration, heap settings, and ports 9200 and 9300. Prefer Elastic’s official signed packages on supported Linux distributions, Homebrew for local macOS development when appropriate, and the official Docker image for isolated cross-platform deployments. Ask before administrator access, adding repositories, enabling services, joining a cluster, opening ports, changing firewall rules, generating certificates, or modifying data paths. Preserve indices, snapshots, cluster metadata, keystores, `elasticsearch.yml`, JVM options, and service definitions. Configure only `cluster_name`, `http_port`, `data_directory`, and `heap_size` when supplied. Use `secret://provider/ELASTIC_PASSWORD` through the Elasticsearch keystore or protected environment injection; never print, echo, log, or expose it in commands. Keep a new node single-node and localhost-bound unless cluster participation is explicitly approved. Verify package identity, node startup, cluster health, authenticated API access, heap allocation, and a disposable index with one document and search. Rollback restores configs and prior service state, removes only newly created deployment resources, and never deletes existing indices automatically. Finish with a structured summary of topology, security, storage, ports, heap, verification, approvals, and rollback.
