# Plane setup prompt

Codex, begin by detecting the OS, architecture, shell, Docker and Compose availability, existing Plane deployment, PostgreSQL data, object storage, environment files, domains, and occupied ports. Prefer Plane’s official self-hosting Docker Compose setup and documented installer; do not assemble unofficial service combinations. Ask before administrator access, installing or starting Docker, creating databases or buckets, running migrations, binding ports, changing firewall rules, opening a browser, or overwriting compose and environment files. Preserve projects, issues, users, uploads, database volumes, Redis data, and existing proxy settings. Configure only `domain_name`, `server_port`, `database_name`, and `file_storage` when supplied. Inject `secret://provider/SECRET_KEY`, `secret://provider/POSTGRES_PASSWORD`, and `secret://provider/AWS_SECRET_ACCESS_KEY` only through protected secret files or runtime injection; never print, echo, log, or commit values. Keep the deployment local unless the domain, TLS, and reverse proxy are approved. Verify container health, migration completion, database connectivity, storage write access, API readiness, and the login page without creating cloud accounts. Rollback removes only newly created containers and manifests, restores backups, and retains volumes and uploads unless deletion is explicitly authorized. Finish with a structured summary of topology, domain, database, storage, ports, verification, approvals, and rollback.
