# Errands setup prompt

Set up Errands from its official repository and verified Flathub listing (https://apps.gnome.org/List/). Inventory Linux architecture, Flatpak scopes, existing Errands package and data paths, local list and task counts, configured CalDAV account count, secret-store boundary, offline-edit state, notification policy and backup availability without reading titles, notes, due dates, server paths or credentials. Install stable `io.github.mrvladus.List` from verified Flathub in the existing ownership scope. Do not compile from source, launch Errands, authenticate, discover a CalDAV endpoint, import ICS, create a list or begin synchronization during setup.

Preserve every list, task, subtask, UID, parent relationship, ordering, accent color, completion flag, due date, note, tombstone, sync token, account reference and preference. Task data can expose medical care, employment, family and location information; redact content and collection names from diagnostics and notifications. Do not mark items complete, normalize colors, reorder via drag-and-drop, merge duplicates or reinterpret a task as a calendar event. Back up the local database before any future schema migration or first bidirectional sync.

Before connecting Nextcloud or another CalDAV provider show the exact HTTPS origin, redirects, certificate verification, authenticated account, app-password storage, discovered collection IDs, read/write scope and whether collections are shared. Preview counts of local-only, remote-only, changed, conflicted and deleted records without showing content. Establish one first-sync authority and explicit rules for duplicate UIDs, tombstones, parent-child conflicts, clock skew and partial failure; never assume newest timestamp or server deletion wins. Revoke only credentials created specifically for Errands.

Treat imported ICS as untrusted structured data. Validate MIME type, byte size, encoding, line folding, recurrence expansion limits, alarms, attachments, organizer/attendee fields, URLs, UIDs and duplicate impact before parsing. Import into a new reviewed list first, never overwrite silently, fetch remote attachments or send invitations. Verify Errands provenance, app ID, origin, commit, runtime, executable, database schema, files and permissions offline. Prove no secret access, endpoint discovery, network request, task mutation, sync token, ICS parse, alarm, notification or filesystem state changed. On failure, rollback only the new Errands ref in its original scope; preserve shared runtimes, remotes, overrides, databases, credentials and all task records.
