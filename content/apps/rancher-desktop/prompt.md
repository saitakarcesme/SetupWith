# Rancher Desktop setup prompt

Set up Rancher Desktop from its verified official source (https://github.com/rancher-sandbox/rancher-desktop/releases). Supported targets: macOS, Linux, Windows. Begin with a read-only preflight covering the operating system, architecture, shell, package managers, disk space, relevant runtimes or hardware, and any existing installation. Select the signed Rancher Desktop release for the detected platform and architecture, verify macOS virtualization, Windows WSL, or Linux KVM prerequisites, and show the Kubernetes image download plus bundled kubectl, Helm, nerdctl, Docker, and Compose impact before first launch.

Preserve existing Rancher Desktop virtual machines, snapshots, images, containers, volumes, Kubernetes workloads, kubeconfig contexts, deployment profiles, WSL distributions, KVM permissions, Docker contexts, registry credentials, caches, and resource settings. Back up files before editing and explain the selected version, source, location, dependencies, and commands. Apply only supplied, supported preferences: container_engine, kubernetes_enabled, kubernetes_version, resource_limits. No credential references are needed for this setup.

Ask before elevation, system-wide packages, services or startup items, ports or firewall rules, sign-in, large downloads, overwrites, or migrations.  Treat drivers, kernel components, anti-cheat, background services, overlays, firewall changes, startup items, and restarts as separate approval checkpoints. Explain the exact component, vendor, privileges, persistence, and rollback before continuing. Do not install WSL, the privileged service, repository keys, KVM group changes, system profiles, or CLI links; switch container engines or Kubernetes versions; reset Kubernetes; factory-reset data; expose non-loopback ports; or replace the active Docker and kubeconfig contexts without separate approval. For a large game or media download, report the exact size, destination drive, free space, and bandwidth impact, then wait for approval. Never delete game libraries, save files, media libraries, mods, profiles, or cloud-sync data. If the platform or configuration is unsupported, stop and offer the closest official alternative.

Confirm signature, version, virtualization readiness, rdctl state, selected engine, Kubernetes enablement, CLI paths, Docker and kubeconfig contexts, and localhost-only networking; avoid pulling images or starting workloads, and prove all pre-existing runtimes, clusters, snapshots, volumes, profiles, and contexts remain unchanged. Report the version, executable, configuration and data paths, changed files, active processes or listeners, and verification evidence without exposing sensitive values. End with manual steps and exact rollback or uninstall instructions that remove only setup-owned changes, restore backups, stop new services, and preserve user data.
