# KeePassXC setup prompt

Codex, begin by detecting the OS, architecture, shell, existing KeePassXC installation, database files, key files, browser integration, auto-lock settings, and file associations. Use the official signed application on macOS or Windows; on Linux prefer the distribution package, official AppImage, or Flatpak. Ask before administrator access, replacing the application, changing `.kdbx` associations, enabling browser integration, installing browser extensions, opening a browser, or modifying an existing database. Preserve all databases, key files, backups, custom icons, settings, and browser pairing records. Configure only `database_path`, `browser_integration`, `auto_lock_minutes`, and `key_file_path` when supplied. Never request, display, log, or store a master password. Validate paths and permissions, and require approval before creating a new key file or enabling browser communication. Verify application launch, version information, settings persistence, auto-lock configuration, and opening a disposable temporary database created solely for testing. Do not unlock or alter the user’s real database. Rollback restores preference backups, disables only integrations enabled here, removes any disposable test database, and uninstalls only this run’s package. Finish with a structured summary of installer, database and key-file paths, browser integration state, lock policy, verification, approvals, and rollback.
