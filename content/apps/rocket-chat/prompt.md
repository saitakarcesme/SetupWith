# Rocket.Chat setup prompt

Codex, begin by detecting the OS, architecture, shell, Docker availability, existing Rocket.Chat deployment, MongoDB replica-set state, volumes, environment files, reverse proxy, and occupied ports. Prefer Rocket.Chat’s official Docker Compose deployment and supported MongoDB configuration; do not use an unsupported standalone database layout. Ask before administrator access, installing Docker, initializing or changing a MongoDB replica set, starting services, opening ports, changing firewall rules, opening a browser, or overwriting environment files. Preserve channels, users, uploads, database volumes, settings, and integrations. Configure only `server_port`, `site_name`, and `default_language` when supplied. Inject `secret://provider/MONGO_URL`, `secret://provider/MONGO_OPLOG_URL`, and `secret://provider/ROOT_URL` through protected runtime secrets or permission-restricted environment files; never print, echo, log, or commit values. Bind locally until the public URL, TLS, and proxy are approved. Verify official image sources, MongoDB health and replica-set readiness, Rocket.Chat startup, migration completion, HTTP readiness, and the login page without registering users. Rollback restores compose files, removes only newly created containers, and retains MongoDB and uploads unless deletion is authorized. Finish with a structured summary of services, database topology, site settings, port, verification, approvals, and rollback.
