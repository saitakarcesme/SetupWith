# Apache Superset setup prompt

Set up Apache Superset from its verified official source (https://github.com/apache/superset). Supported targets: macOS, Linux. Begin with a read-only preflight covering the operating system, architecture, shell, package managers, disk space, relevant runtimes or hardware, and any existing installation. Use the official container-compose development path or an isolated Python environment with a supported release, clearly separating a local evaluation from production deployment.

Preserve Superset metadata databases, `superset_config.py`, dashboards, uploaded assets, database connections, encryption keys, and container volumes. Back up files before editing and explain the selected version, source, location, dependencies, and commands. Apply only supplied, supported preferences: deployment_mode, metadata_database, config_path, listen_address, listen_port. The only available credential references are secret://superset/secret-key, secret://superset/database-url. Treat every reference as opaque: never print, echo, log, resolve, or paste its value.

Ask before elevation, system-wide packages, services or startup items, ports or firewall rules, sign-in, large downloads, overwrites, or migrations.  Do not enable startup items, background services, overlays, notifications, analytics, or device permissions unless they are requested and separately approved. Do not initialize or upgrade an existing database, create users, load examples, connect data sources, or expose the webserver without approval. For a large game or media download, report the exact size, destination drive, free space, and bandwidth impact, then wait for approval. Never delete game libraries, save files, media libraries, mods, profiles, or cloud-sync data. If the platform or configuration is unsupported, stop and offer the closest official alternative.

Run the version command and configuration checks; start only a fresh loopback instance if approved, confirm its health page, and stop all test services. Report the version, executable, configuration and data paths, changed files, active processes or listeners, and verification evidence without exposing sensitive values. End with manual steps and exact rollback or uninstall instructions that remove only setup-owned changes, restore backups, stop new services, and preserve user data.
