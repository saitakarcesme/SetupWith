# Workbench setup prompt

Set up Workbench from its official project and verified Flathub listing (https://apps.gnome.org/Workbench/). Inventory Linux architecture, Flatpak scopes, existing package and data paths, saved-session and project counts, aggregate autosave bytes, configured language runtimes, sandbox overrides, network and D-Bus permission presence, terminal-output retention and backup coverage without reading source code, project names, file paths, terminal text, environment values, diagnostics, recent examples or secrets. Install stable `re.sonny.Workbench` from verified Flathub in the existing ownership scope. Do not compile from source, launch Workbench, restore a session, load an example, parse a project, render a preview, run JavaScript, Rust, Python or Vala, invoke a compiler or formatter, start a terminal, access a bus, contact a network, or autosave during setup.

Preserve every project and session byte, ownership, permissions, autosave and recovery state, runtime choices, formatter settings, terminal history, sandbox overrides, remotes and scope ownership. Workbench is an execution environment, not a passive editor: examples, preview markup, CSS, build scripts and language code can create subprocesses, access portals, invoke URI handlers or communicate over D-Bus. Treat all non-bundled code as untrusted. Redact source, paths, environment and terminal output; never place real credentials in a prototype.

Before later execution, require source provenance and checksum, license, reviewed language and entry point, exact runtime or compiler versions, dependency and network-fetch plan, arguments, environment allowlist, working directory, filesystem mounts, D-Bus names, portal access, CPU, memory, process, output and timeout limits. Deny network by default. Run only disposable synthetic projects for validation. Review live GTK/CSS and declarative previews for widget signals, URI activation, clipboard, notifications, audio and accessibility effects. Formatters and diagnostics that mutate source require a diff preview and recoverable autosave snapshot.

Sanitize terminal ANSI controls and cap retained output; terminate child process groups on cancel or preview close. Verify provenance, app ID, origin, commit, runtime, executable, files and static sandbox permissions offline. Prove no project or session read, runtime process, compiler, formatter, preview, terminal, environment inspection, filesystem write, bus call, portal, network request, autosave or notification occurred. On failure, rollback only the new Workbench ref in its original scope; preserve shared runtimes, remotes, overrides, projects, sessions, autosaves, terminal state and backups.
