# BookStack setup prompt

Set up BookStack from its verified official source (https://github.com/BookStackApp/BookStack). Supported targets: Linux. Begin with a read-only preflight covering the operating system, architecture, shell, package managers, disk space, relevant runtimes or hardware, and any existing installation. Prefer the official container-compose pattern for a local deployment or follow BookStack's documented Linux web-stack requirements, pinning versions and persistent directories explicitly.

Preserve the database, uploaded files, `.env`, application key, themes, authentication settings, backups, and container volumes. Back up files before editing and explain the selected version, source, location, dependencies, and commands. Apply only supplied, supported preferences: deployment_mode, data_directory, database_name, listen_address, listen_port. The only available credential references are secret://bookstack/app-key, secret://bookstack/database-password. Treat every reference as opaque: never print, echo, log, resolve, or paste its value.

Ask before elevation, system-wide packages, services or startup items, ports or firewall rules, sign-in, large downloads, overwrites, or migrations. Browser Use and Computer Use may open the official page, download the approved signed installer, complete the visible installer flow, verify the publisher or code signature, and launch the product once. Stop and hand control to the user before account creation, sign-in, password entry, MFA, CAPTCHA, age verification, purchases, subscriptions, license acceptance that creates a paid obligation, or linking external accounts. Never bypass DRM, regional restrictions, or platform protections. Do not enable startup items, background services, overlays, notifications, analytics, or device permissions unless they are requested and separately approved. Do not generate or replace an application key, migrate a database, create users, configure mail or SSO, expose ports, or start persistent services without approval. For a large game or media download, report the exact size, destination drive, free space, and bandwidth impact, then wait for approval. Never delete game libraries, save files, media libraries, mods, profiles, or cloud-sync data. If the platform or configuration is unsupported, stop and offer the closest official alternative.

For a fresh approved deployment, confirm the loopback login page and container health, inspect logs for errors, and stop without completing setup or changing credentials. Report the version, executable, configuration and data paths, changed files, active processes or listeners, and verification evidence without exposing sensitive values. End with manual steps and exact rollback or uninstall instructions that remove only setup-owned changes, restore backups, stop new services, and preserve user data.
