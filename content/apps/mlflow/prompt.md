# MLflow setup prompt

Codex, inspect the OS, architecture, shell, Python environment, existing MLflow installation, tracking configuration, artifact stores, backend database, running servers, and port usage before changes. Prefer installing the official `mlflow` PyPI package inside a dedicated `uv` or virtual environment; use a container only when the user already operates containerized services. Ask before administrator access, database migrations, starting a persistent service, binding port 5000, firewall changes, browser launch, or altering experiment data. Preserve the tracking database, artifact root, model registry, environment files, and existing server configuration. Configure only `tracking_uri`, `artifact_root`, and `server_port` when supplied. Use `secret://provider/AWS_ACCESS_KEY_ID` and `secret://provider/AWS_SECRET_ACCESS_KEY` only through secure credential injection for an approved S3 artifact store; never print, echo, log, or write values into commands or tracked files. Default to a local SQLite backend and filesystem artifacts unless another existing backend is explicitly selected. Verify `mlflow --version`, database connectivity, artifact write/read using a disposable experiment, server health, and read-only UI availability. Rollback stops and removes only created services and environments, restores configuration, and retains tracking data unless deletion is approved. End with a structured summary of backend, artifacts, port, credentials source, verification, approvals, and rollback.
