# Binary setup prompt

Set up Binary from its official project and verified Flathub listing (https://apps.gnome.org/Binary/). Inventory Linux architecture, Flatpak scopes, existing package and data paths, saved source and target base choices, numeric-width and signedness policy presence, recent-value count, clipboard-access declaration, sandbox overrides and backup coverage without reading or revealing any numeric input, converted output, clipboard text, identifier, key material or usage history. Install stable `io.github.fizzyizzy05.binary` from verified Flathub in the existing ownership scope. Do not compile from source, launch Binary, restore an input, parse or convert a value, infer width, read or write the clipboard, update recents, emit a notification or access a network or filesystem portal during setup.

Preserve all preferences, input and output state, history, clipboard contents, window state, permissions, remotes, overrides and scope ownership. Numeric strings can be cryptographic keys, hardware identifiers or account numbers; redact them and never use real secrets as conversion tests. Installation must not reinterpret an existing negative value, strip significant leading zeros, infer two's complement, truncate to a machine word, auto-copy output or register itself as a handler.

Before later conversion, require explicit source and target bases and define accepted prefixes, separators, case, whitespace, sign and leading-zero behavior. State whether arithmetic is arbitrary precision or fixed width. Signed magnitude and two's-complement bit patterns are different interpretations; require an explicit bit width before two's-complement decoding and report overflow rather than truncating. Preserve a canonical zero and negative-value representation. Validate with public boundary vectors covering zero, powers of two, maximum widths, mixed case, invalid digits and round trips across every supported base.

Clipboard paste must be explicit, sanitized for control and invisible characters and shown before parsing. Copy must label the target base, require user action and avoid overwriting unrelated clipboard data during tests. Binary conversion does not validate a cryptographic key, memory address, permission mask or protocol field; those require domain-specific width and semantics. Verify provenance, app ID, origin, commit, runtime, executable, files and static permissions offline. Prove no input restoration, parse, conversion, width inference, clipboard access, recent-state write, notification, portal or network request occurred. On failure, rollback only the new Binary ref in its original scope; preserve shared runtimes, remotes, overrides, preferences, numeric state, history, clipboard and backups.
