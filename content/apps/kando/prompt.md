# Kando setup prompt

Set up Kando from its official platform guide and kando-menu repository (https://kando.menu/). Detect Windows, macOS, or Linux, architecture, desktop environment, X11 versus Wayland, compositor, package managers, existing Kando or portable installation, tray/startup state, global shortcuts, accessibility grants, GNOME extensions, desktop rules, and configuration directories. Select Winget or the matching release on Windows, Homebrew or signed DMG on macOS, and Flathub, distribution package, or matching official release on Linux. If a Windows artifact is unsigned, report that fact and require explicit provenance approval instead of bypassing the warning automatically.

Install without starting at login, registering shortcuts, granting permissions, installing adapters, or editing compositor configuration. Preserve `config.json`, `menus.json`, portable-mode routing, themes, sounds, icons, menu conditions, commands, macros, hotkeys, pasted text, file and URI targets, achievement state, shortcut IDs, desktop portal grants, GNOME extensions, window-manager rules, login items, and background processes. Apply only approved triggers, menus, login behavior, or WebSocket setting, and show a complete diff before configuration hot-reloads it.

Menu items can execute arbitrary commands and macros, simulate input, move the pointer, paste sensitive text, open files or URLs, and target the focused application. Never invoke existing menu items during verification. Review each new action's exact executable, arguments, working directory, environment, target window, hotkey sequence, text sensitivity, URI scheme, and rollback. Stop separately before macOS Accessibility or Screen Recording grants, a GNOME Wayland D-Bus adapter, KDE portal shortcut, Hyprland/Niri rule, AutoHotKey, Input Remapper, Karabiner, startup item, or WebSocket listener. Keep remote control disabled and avoid conflicting system shortcuts.

Verify artifact provenance, version, executable and configuration paths, desktop compatibility, processes, listeners, startup state, permissions and shortcut registrations. Launch once only if approved, confirm the tray process and example menu can appear, then dismiss it without selecting an item, warping the pointer, simulating input, reading the focused-window name, or persisting a shortcut. Confirm no command, macro, paste, file, URI, network listener, extension, portal grant, accessibility permission, window rule, login item, or config migration changed. Roll back setup-owned files and grants only while preserving all pre-existing menus and desktop settings.
