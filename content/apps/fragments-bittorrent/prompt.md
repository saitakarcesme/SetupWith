# Fragments setup prompt

Set up Fragments from its official GNOME project and verified Flathub listing (https://apps.gnome.org/Fragments/). Inventory Linux architecture, Flatpak scopes, existing Fragments package and data paths, local Transmission daemon state, remote-session definitions, secret storage, active torrent count, download/incomplete roots, clipboard-monitoring preference, metered policy, ports and firewall state without reading torrent names, info hashes or credentials. Install stable `de.haeckerfelix.Fragments` from verified Flathub in the existing ownership scope. Do not install a nightly, compile from source, launch Fragments, start Transmission, connect remotely or add a test torrent.

Preserve every torrent, magnet URI, info hash, tracker, peer policy, ratio, queue position, selected file, downloaded byte, incomplete file, destination, label, statistic, remote credential and preference. Torrent metadata may reveal copyrighted interests, research, peer IP addresses and local filenames. Never print names, trackers, hashes, peers or remote URLs in diagnostics. Do not inspect the clipboard: automatic magnet/torrent-link detection could read unrelated credentials, messages or private URLs.

Treat `.torrent` files and magnet metadata as untrusted structured input. Before any future addition show publisher/source, expected content, info hash, tracker/DHT behavior, file tree, total size, selected files, destination, free space, symlink/path-traversal checks and legal authorization. Do not auto-start, trash the source `.torrent`, open a downloaded file or execute a CLI addition without separate approval. BitTorrent encryption does not provide anonymity or establish content authenticity.

Remote Transmission control can mutate another system. Require exact HTTPS endpoint, certificate verification, authenticated identity, server owner, session inventory and deletion boundary. Do not test ports, enable UPnP/NAT-PMP, change firewall rules, expose a listener, bypass metered limits or inhibit sleep. Verify Fragments provenance, app ID, origin, commit, runtime, executable, bundled backend, files and declared permissions offline. Prove no daemon, connection, clipboard read, torrent parse, tracker/DHT/peer traffic, port, download, source trash, notification or filesystem state changed. On failure, rollback only the new Fragments ref in its original scope; preserve shared runtimes, remotes, overrides, daemon packages, torrent state, credentials and all payload data.
