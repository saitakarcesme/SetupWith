# Metronome setup prompt

Set up Metronome from its official GNOME GitLab project and current Flathub listing (https://flathub.org/apps/com.adrienplazas.Metronome). Inventory Linux architecture, Flatpak scopes, any existing `com.adrienplazas.Metronome` ref, application-data ownership, saved-setting count, audio-server type, available-sink count, default-route class, mute state, sandbox overrides and backup coverage without printing device names, practice tempos, meters or session history. Match the Flathub manifest source and app ID to upstream before installing the stable ref in the existing scope. Do not compile from source, launch Metronome, play a click, change BPM or meter, generate tap events, unmute audio, select a sink or alter system routing during setup.

Preserve the last tempo, time signature, window state, app volume, system volume, mute and routing state, Bluetooth profile, permissions, remotes, overrides and scope ownership. Tap tempo uses deliberate pointer or keyboard taps; it must not request microphone access or listen to the room. Never route a click to an unknown shared speaker, recording stream, broadcast mix or hearing device.

Before later playback, confirm BPM, supported range, time-signature numerator and denominator, accent expectations, output device, current volume, surroundings and an explicit play boundary. Start muted or at an agreed low level, then raise volume deliberately. Treat Bluetooth and software-buffer latency as display-to-sound delay, not a reason to rewrite global audio settings. Tap-tempo estimates need several intentional taps and outlier review. The app is a practice aid, not a certified timing, hearing, rehabilitation or live-synchronization instrument.

Verify upstream provenance, app ID, manifest source, selected commit, runtime, executable, files, embedded logo, checksum and declared permissions offline. Confirm no sound played, tap event was synthesized, audio route or volume changed, device opened, background session started, network connection occurred or preference mutated. On failure, rollback only the new Metronome ref in its original scope; preserve shared runtimes, audio configuration, preferences, remotes, overrides and backups.
