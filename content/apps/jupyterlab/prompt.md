# JupyterLab setup prompt

Codex, begin by detecting the OS, architecture, shell, Python ownership, existing JupyterLab installations, kernels, configuration directories, workspace data, and occupied ports. Prefer a dedicated `uv` or Python virtual environment and install the official `jupyterlab` package from PyPI; use conda only when an existing conda-managed data-science environment should be preserved. Ask before administrator access, modifying system Python, replacing kernels, opening port 8888, changing firewall rules, launching a browser, or overwriting configuration. Preserve notebooks, workspaces, extensions, kernelspecs, and `jupyter_server_config` files. Configure only `workspace_dir`, `server_port`, and `default_kernel` when supplied. Reference `secret://provider/JUPYTER_TOKEN` only through secure runtime injection or protected server configuration; never print, echo, log, or store it in shell history. Bind to localhost by default and do not disable authentication. Verify with `jupyter lab --version`, `jupyter kernelspec list`, configuration inspection, a no-browser server startup, HTTP readiness, and execution of a temporary notebook through the selected kernel. Do not install extensions automatically. Rollback stops only the created server, restores config backups, removes the dedicated environment, and preserves notebooks and workspace data. Finish with a structured summary of environment, kernel, bind address, authentication, checks, approvals, and rollback.
