# Paper Clip setup prompt

Set up Paper Clip from its official repository and verified Flathub listing (https://apps.gnome.org/PdfMetadataEditor/). Inventory Linux architecture, Flatpak scopes, existing package and data paths, approved PDF roots, document count, encrypted-file presence, signature-policy presence and output conventions without opening PDFs, extracting metadata, rendering pages or reading passwords. Install stable `io.github.diegoivan.pdf_metadata_editor` from verified Flathub—the project states Flathub is its only official distribution—in the existing ownership scope. Do not compile from source, launch Paper Clip, parse a PDF, unlock a document, change metadata or save output during setup.

Preserve every source PDF byte-for-byte, including encryption, signatures, permissions, Info dictionary, XMP packets, embedded files, annotations and timestamps. Before a future edit require document ownership, exact checksum, authoritative copy, approved output path and a protected backup. Never overwrite the sole original. Treat malformed PDF structure as untrusted parser input; apply file-size/object/decompression limits and do not execute JavaScript, follow links, extract attachments or render content merely to edit metadata.

Define which schema is authoritative for title, author, creator, producer, creation/modification dates and keywords. Paper Clip can synchronize Dublin Core XMP with PDF equivalents, so preview every field-level change, encoding, timezone and conflict before write. Changing any byte can invalidate a digital signature or certification; inspect signed byte ranges and validation state first, and stop unless the signature owner explicitly accepts invalidation. For encrypted documents, request the minimum required password through a protected prompt, never log it, and ensure temporary decrypted content is not persisted.

Metadata editing is not complete document sanitization. Removed values may remain in incremental revisions, backups, thumbnails, attachments, comments, application histories or filesystem metadata. Do not claim anonymity from a clean visible field list. Save atomically to a new file, reopen with two independent readers, compare page count and structural checks, validate intended metadata and re-check signatures/encryption. Verify app provenance, ID, origin, runtime, executable, files and permissions offline. Prove no PDF read, password access, metadata parse, signature check, temporary file, save or filesystem state changed. On failure, rollback only the new Paper Clip ref; preserve runtimes, remotes, overrides and all documents.
