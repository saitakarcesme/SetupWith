# Bottles setup prompt

Set up Bottles using its official documentation and supported Flathub package (https://docs.usebottles.com/getting-started/installation). Inventory the Linux architecture, desktop, Flatpak user and system scopes, Flathub remote, graphics stack, existing Bottles packaging, `~/.local/share/bottles`, Flatpak data directory, bottles, Wine prefixes, runners, components, dependencies, programs, installers, snapshots, configuration backups and full archives. Install only stable `com.usebottles.bottles` from the verified Flathub origin in the scope matching current ownership. Do not use the beta remote, compile from source, migrate directories, launch Bottles or download a runner during setup.

Preserve every prefix, `bottle.yml`, drive_c tree, registry hive, installed program, save file, launcher, environment variable, runner selection, architecture, DXVK/VKD3D setting, DLL override, dependency, snapshot and backup byte-for-byte. Native and Flatpak packages use different data roots; report both and require an explicit reviewed copy plan before any migration. Never merge, move, import, duplicate, repair, rebase or delete a bottle automatically. A configuration backup does not contain the full prefix, while a full archive can contain personal files; label that distinction and never upload or share either artifact.

Treat every Windows executable, MSI, script, community installer manifest, runner and dependency as untrusted executable content. Do not fetch or run an installer, accept a license, enable pre-release components, alter a registry, create a process, add a desktop entry or associate executable file types. Keep the Flatpak sandbox intact. Prefer portals or a single approved directory; never expose the whole home directory, host root, devices or unrelated game libraries. Before any future payload action show source URL, publisher or signature evidence, checksum when published, license, bottle target, architecture, runner, requested network endpoints, filesystem reach and rollback boundary.

Verify package provenance, app ID, installed commit, runtime, declared permissions, executable and data paths from Flatpak metadata without launching it. Compare the preflight bottle inventory and file hashes, confirm no runner/component download, prefix mutation, registry write, process execution, network request, launcher, association, permission override or data migration occurred. If verification fails, remove only the newly installed Flatpak in its original scope; preserve all Bottles data, runtimes shared by other apps, remotes and user overrides.
