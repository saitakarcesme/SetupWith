# Syncthing setup prompt

Codex, inspect the OS, architecture, shell, existing Syncthing binary, service state, device ID, configuration, folders, database, GUI binding, discovery settings, and listening ports before changes. On macOS prefer Homebrew `syncthing` or the official GUI wrapper; on Linux use the distribution package or Syncthing’s official repository; on Windows prefer the official package or supported `winget` entry. Ask before administrator access, enabling startup services, opening ports, changing firewall rules, exposing the GUI, adding devices, sharing folders, or overwriting configuration. Preserve device identity, certificates, folder indexes, ignore files, versioning, and existing peers. Configure only `sync_directory`, `device_name`, `gui_address`, and `listen_address` when supplied. Use `secret://provider/STGUIAPIKEY` only through protected configuration handling; never print, echo, log, or expose it in commands. Keep the GUI on localhost and do not add remote devices automatically. Verify `syncthing --version`, configuration validity, service health, GUI readiness, directory permissions, and synchronization between two disposable local folders using a temporary isolated home directory. Rollback restores config and prior service state, removes only test folders and the installed package, and preserves real indexes and identity. Finish with a structured summary of installation, identity, paths, bindings, service state, verification, approvals, and rollback.
