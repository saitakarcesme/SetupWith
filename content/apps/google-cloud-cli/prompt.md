# Google Cloud CLI setup prompt

Set up Google Cloud CLI from its verified official source (https://cloud.google.com/sdk/docs/install). Supported targets: macOS, Linux, Windows. Begin with a read-only preflight covering the operating system, architecture, shell, package managers, disk space, relevant runtimes or hardware, and any existing installation. Follow Google's Cloud CLI quickstart for the host platform and architecture, validate the official repository or archive, and list optional components before adding any beyond the base CLI.

Preserve Preserve the gcloud configuration directory, named configurations, account tokens, application-default credentials, active project, component state, custom repositories, and shell completion settings.. Back up files before editing and explain the selected version, source, location, dependencies, and commands. Apply only supplied, supported preferences: active_project, default_region, default_zone, component_update_policy. The only available credential references are secret://google/application-credentials. Treat every reference as opaque: never print, echo, log, resolve, or paste its value.

Ask before elevation, system-wide packages, services or startup items, ports or firewall rules, sign-in, large downloads, overwrites, or migrations.  Do not enable startup items, background services, overlays, notifications, analytics, or device permissions unless they are requested and separately approved. Stop before `gcloud init`, browser login, application-default authentication, project selection, component installation, telemetry opt-in, shell profile edits, or any Google Cloud API request. For a large game or media download, report the exact size, destination drive, free space, and bandwidth impact, then wait for approval. Never delete game libraries, save files, media libraries, mods, profiles, or cloud-sync data. If the platform or configuration is unsupported, stop and offer the closest official alternative.

Run `gcloud version` and local configuration listing with account values redacted, report executable and SDK roots, and confirm no authentication, project change, or network operation happened. Report the version, executable, configuration and data paths, changed files, active processes or listeners, and verification evidence without exposing sensitive values. End with manual steps and exact rollback or uninstall instructions that remove only setup-owned changes, restore backups, stop new services, and preserve user data.
