# DVC setup prompt

Codex, first inspect the OS, architecture, shell, Git installation, Python tooling, existing DVC binary, repository `.dvc` configuration, cache, remotes, and tracked data state. Prefer the official `dvc` package in a dedicated `uv` or virtual environment, installing extras only for the selected remote; use Homebrew or a trusted native package when it already manages DVC. Ask before administrator access, initializing DVC, modifying `.gitignore`, changing remotes, moving cache data, downloading files, or overwriting repository configuration. Preserve `.dvc/config`, `.dvc/config.local`, lockfiles, cache links, and all data files. Configure only `cache_dir`, `default_remote`, and `analytics_enabled` when supplied. For cloud access, reference `secret://provider/AWS_ACCESS_KEY_ID`, `secret://provider/AWS_SECRET_ACCESS_KEY`, or `secret://provider/GDRIVE_CREDENTIALS_DATA` only through secure local configuration or environment injection; never print, log, or commit secret values. Verify with `dvc version`, `dvc doctor`, `dvc remote list`, cache configuration, and `dvc status` without pulling or pushing. In a disposable repository, test initialization only if approved. Rollback restores backed-up DVC and Git files, removes only the installed environment, and leaves caches and data untouched unless deletion is authorized. Finish with a structured summary of install source, repository state, cache, remote, verification, approvals, and rollback.
