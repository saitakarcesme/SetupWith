# Memos setup prompt

Codex, first inspect the OS, architecture, shell, existing Memos deployment, Docker or Podman availability, database and data directory, environment files, service definitions, and occupied ports. Prefer the official Memos container image with a persistent data mount; use the official binary only on a supported host when containers are unsuitable. Ask before administrator access, installing or starting a container engine, creating services, exposing ports, changing firewall rules, opening a browser, upgrading the database, or replacing volumes. Preserve the database, attachments, user accounts, configuration, and backups. Configure only `server_port`, `data_directory`, and `public_url` when supplied. Bind to localhost unless an approved reverse proxy or LAN use requires external access. Validate that the public URL matches the selected port and protocol. Verify the image or binary source, persistent mount, application startup, HTTP readiness, database migration status, and creation plus deletion of a disposable memo through the local interface or API. Do not create public users or enable external authentication automatically. Rollback stops and removes only the container, binary, or service created here, restores manifests, and keeps all data files unless deletion is explicitly authorized. Finish with a structured summary of deployment method, storage, URL, port, migration state, verification, approvals, and rollback.
