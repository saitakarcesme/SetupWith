# Bobby setup prompt

Set up Bobby from its official project and verified Flathub listing (https://apps.gnome.org/Bobby/). Inventory Linux architecture, Flatpak scopes, existing package and data paths, recent-database count, aggregate cache bytes, portal grants, declared read/write filesystem reach, clipboard access, sandbox overrides and backup coverage without opening any database or revealing paths, schemas, table or column names, row counts tied to identities, cell values, BLOBs, deleted remnants, tokens, credentials or application data. Install stable `studio.planetpeanut.Bobby` from verified Flathub in the existing ownership scope. Do not compile from source, launch Bobby, enumerate files, open a SQLite connection, read headers or schemas, attach WAL or SHM files, acquire a lock, execute a query, load an extension, render rows, copy a cell, update recents or mutate a database during setup.

Preserve every database, journal, WAL and SHM byte, owner, permission, timestamp, lock and live-writer relationship, plus Bobby preferences, recents, caches, portal grants, remotes, overrides and scope ownership. Databases can contain complete private histories and credentials; redact both values and identifying schema names. Installation must not recover deleted records, checkpoint a WAL, alter journal mode, create side files, normalize a schema, follow an unexpected symlink or associate `.db` files globally without review.

Before later inspection, verify the SQLite header, device and inode, checksum and companion-file set. If a database is live, obtain an application-consistent snapshot through the owning application's approved mechanism; copying only the main file can omit committed WAL data. Open the approved copy immutable and read-only, with no extension loading, application-defined functions, writes, checkpoints or schema side effects. Treat schema SQL, virtual tables, malformed pages and BLOBs as untrusted input. Apply page, row, column, BLOB, recursion, memory, CPU, query and rendering limits. Validate with a synthetic database containing public boundary fixtures.

Pagination and sorting must state whether they operate on the full result or only a visible page. Display NULL, empty text, zero-length BLOB and numeric zero distinctly. Copy requires an explicit cell or row selection, a preview of quoting and delimiters, formula-injection neutralization for spreadsheet targets and a defined clipboard lifetime; tests must not overwrite user clipboard data. Verify provenance, app ID, origin, commit, runtime, executable, files and static permissions offline. Prove no file enumeration, SQLite open, lock, header or schema read, query, row render, extension, clipboard operation, recent write or database mutation occurred. On failure, rollback only the new Bobby ref in its original scope; preserve shared runtimes, remotes, overrides, databases, companions, locks, preferences and backups.
