# HashiCorp Vault setup prompt

Set up HashiCorp Vault from its verified official source (https://github.com/hashicorp/vault). Supported targets: macOS, Linux, Windows. Begin with a read-only preflight covering the operating system, architecture, shell, package managers, disk space, relevant runtimes or hardware, and any existing installation. Install HashiCorp's signed Vault package or binary, treating CLI-only use, a disposable development server, and a production server as separate security scopes.

Preserve Vault storage, seal configuration, recovery and unseal material, policies, audit devices, TLS certificates, tokens, and service configuration. Back up files before editing and explain the selected version, source, location, dependencies, and commands. Apply only supplied, supported preferences: vault_address, storage_backend, listen_address, api_port, deployment_mode. The only available credential references are secret://vault/token. Treat every reference as opaque: never print, echo, log, resolve, or paste its value.

Ask before elevation, system-wide packages, services or startup items, ports or firewall rules, sign-in, large downloads, overwrites, or migrations.  Do not enable startup items, background services, overlays, notifications, analytics, or device permissions unless they are requested and separately approved. Do not initialize, unseal, join, authenticate, enable secret engines, write secrets, start persistent servers, or expose the API without approval. For a large game or media download, report the exact size, destination drive, free space, and bandwidth impact, then wait for approval. Never delete game libraries, save files, media libraries, mods, profiles, or cloud-sync data. If the platform or configuration is unsupported, stop and offer the closest official alternative.

Run `vault version`; do not contact an existing `VAULT_ADDR`, and only with approval start a disposable loopback dev server whose printed root token is not logged or persisted. Report the version, executable, configuration and data paths, changed files, active processes or listeners, and verification evidence without exposing sensitive values. End with manual steps and exact rollback or uninstall instructions that remove only setup-owned changes, restore backups, stop new services, and preserve user data.
