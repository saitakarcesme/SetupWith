# Grafana setup prompt

Codex, begin by inspecting the OS, architecture, shell, existing Grafana installation, package ownership, plugins, data directory, provisioning files, database, service state, and port 3000. Prefer Grafana’s official signed repository on supported Linux distributions, Homebrew `grafana` for local macOS use, the official Windows installer, or the official container image when isolation is preferred. Ask before administrator access, adding repositories, enabling services, exposing ports, changing firewall rules, opening a browser, running database migrations, installing plugins, or overwriting provisioning files. Preserve dashboards, users, alert rules, plugins, SQLite or external database data, and `grafana.ini`. Configure only `admin_user`, `server_port`, `data_path`, and `public_url` when supplied. Use `secret://provider/GF_SECURITY_ADMIN_PASSWORD` and `secret://provider/GF_DATABASE_PASSWORD` only through protected environment or secrets injection; never print, echo, log, or commit values. Bind locally unless external access is approved. Verify package identity, service health, `/api/health`, database connectivity, configured URL, and login-page availability without browser sign-in. Rollback restores config and service state, removes only installed packages or containers, and retains dashboards and data unless deletion is authorized. Finish with a structured summary of installation, database, data path, URL, port, verification, approvals, and rollback.
