# Node.js setup prompt

Codex, first inspect the OS, architecture, shell, PATH, existing `node`, `npm`, Corepack, version managers, and project version files. Do not replace a managed Node installation without explaining ownership. Prefer an existing mise, nvm, fnm, or Volta workflow when present; otherwise use the platform’s trusted package manager, such as Homebrew on macOS, an official NodeSource channel or distribution package on Linux, and `winget install OpenJS.NodeJS.LTS` on Windows. Ask before administrator access, adding repositories, changing PATH, or selecting a different major release channel. Preserve npm configuration, global packages, Corepack settings, and project lockfiles. Configure only `node_version`, `package_manager`, and `npm_registry` when supplied. Pin the runtime through the detected version manager where possible. Enable Corepack only for supported package managers and never regenerate lockfiles. If authentication is required, use only `secret://provider/NPM_TOKEN` through the package manager’s secure configuration path; never print, echo, log, or commit it. Verify `node --version`, `npm --version`, the selected package manager, registry reachability, and a temporary script execution. Do not run project installs unless requested. Rollback restores config backups, removes only the installed runtime version or package, and leaves project files untouched. Finish with a structured summary of runtime source, PATH resolution, config, verification, approvals, and rollback.
