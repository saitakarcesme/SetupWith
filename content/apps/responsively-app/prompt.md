# Responsively App setup prompt

Set up Responsively App from its official repository and download page (https://responsively.app/download). Detect Windows, macOS, or Linux, architecture, package managers, existing stable or legacy installation, application data, custom device profiles, layouts, cached sessions, browser extension, proxy and certificate settings. Install the signed stable desktop release, official Homebrew cask, Winget, Chocolatey, RPM, or AppImage appropriate to the platform. Do not build from an unpinned branch, install the browser extension, or migrate legacy profile data automatically.

Launch to an empty or offline state without loading a user URL. Preserve device profiles, preview layouts, favorites and recent URLs, cookies, local and session storage, cache, authentication state, certificates, proxy settings, screenshots, downloads, developer-tools preferences, extension data, and application configuration. Apply only approved device profiles, layout, interaction mirroring, or developer-tools setting. Show device name, viewport, pixel ratio, user agent and touch behavior before adding or changing a custom profile.

Responsively mirrors interactions across multiple embedded browser views. A single click, form submission, navigation, scroll or keyboard action can therefore affect every preview and may repeat a destructive operation. Disable mirroring until the exact test page and actions are approved. Before loading any URL, show scheme, resolved host, port, path, redirect policy, proxy and whether it is loopback, development, staging or production. Never sign in, use production accounts, submit real forms, accept untrusted certificates, expose local files, grant camera/microphone/location/notification/clipboard permissions, open external protocols, download files, or paste credentials.

Developer tools and screenshots can expose DOM content, tokens, cookies, request headers and private data. Use only a setup-created static page on loopback or a local file containing public sample content for verification; block outbound requests and do not reuse the user's browser profile. Verify publisher, version, executable and data paths, processes, listeners, proxy, certificate and extension baselines. Confirm synchronized viewport rendering without clicking actionable controls, then close and remove only the disposable sample. Prove no URL history, cookie, storage, login, screenshot, download, permission, profile, extension or certificate changed. Roll back the installed app and setup-owned settings while preserving all existing profiles and browser data.
