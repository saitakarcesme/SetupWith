# Bustle setup prompt

Set up Bustle from its official project and verified Flathub listing (https://apps.gnome.org/Bustle/). Inventory Linux architecture, Flatpak scopes, existing package and data paths, declared session and system bus monitoring access, saved-trace count, aggregate trace and cache bytes, redaction-policy presence, default event, byte and duration caps, sandbox overrides and backup coverage without connecting to a bus or revealing trace filenames, bus names, object paths, interfaces, members, process identities, timestamps, message bodies, errors, credentials or application behavior. Install stable `org.freedesktop.Bustle` from verified Flathub in the existing ownership scope. Do not compile from source, launch Bustle, connect to a bus, install a monitor or match rule, capture a message, activate a service, open or parse a trace, render a sequence diagram, compute statistics, write a log, export data or request elevated monitoring during setup.

Preserve every saved trace byte, checksum, timestamp and redaction status, plus capture filters, diagram settings, caches, permissions, remotes, overrides and scope ownership. A D-Bus trace can reconstruct private application workflows and payloads; metadata alone may identify users and activities. Installation must not begin background capture, broaden from session to system bus, activate dormant services, retain an old unredacted trace or request policy changes. Bus monitoring permission is not consent to observe unrelated applications.

Before later capture, require the exact bus, user and namespace, approved destinations, purpose, time window and retention. Use narrow filters and enforce event, byte, duration, memory and disk caps with dropped-message accounting and deterministic stop. Redact bodies, byte arrays, credentials, account identifiers, notification and clipboard content during collection rather than relying only on later export. Validate the capture pipeline against a disposable synthetic bus and known messages, not a production desktop. Remove every monitor rule on stop and prove no service was activated.

Imported traces need provenance, checksum, format and sanitization status and must be parsed with record, nesting, decompression, memory and time limits. Sequence order does not always prove causality; unique bus ownership changes, missing replies and clock precision matter. Label method-duration and signal-frequency statistics with sample window, dropped events, outlier policy and observer overhead. Verify provenance, app ID, origin, commit, runtime, executable, files and static permissions offline. Prove no bus connection, monitor, capture, activation, trace parse, diagram, statistic, log write, export or privilege request occurred. On failure, rollback only the new Bustle ref in its original scope; preserve shared runtimes, remotes, overrides, traces, filters, redaction state, caches and backups.
