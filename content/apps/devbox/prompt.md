# Devbox setup prompt

Set up Devbox from Jetify's verified installation documentation (https://www.jetify.com/docs/devbox/installing-devbox/). Start by detecting the operating system, architecture, interactive shell, available disk space, an existing `devbox` executable, and whether Nix is installed in single-user or multi-user mode. On Windows, continue only inside an already-working WSL2 distribution; do not present Devbox as a native Windows installation. Report the selected Devbox release and installer checksum or pinned Nix reference before making changes.

Preserve every existing Nix profile, channel, flake registry, daemon and trust setting, store path, Devbox global profile, project `devbox.json`, `devbox.lock`, `.devbox` directory, shell startup file, environment variable, init hook, script, and cached package. Before changing a project, show its Git status and make a restorable copy of setup-owned configuration. Apply only the requested project packages, pinned package versions, shell init hook, or global shell integration; explain that project packages are isolated while global integration changes the host shell's PATH. No credential references are needed for this setup.

Download Jetify's installer to a temporary file and inspect it instead of piping network content directly into a shell. Ask separately before installing Nix, enabling or reconfiguring the Nix daemon, using administrator privileges, creating WSL2, editing a shell startup file, adding global packages, downloading a large closure, or overwriting project configuration. Never run an unfamiliar project's init hook or script during installation. Do not update a lock file, change flake trust, enable experimental Nix features, pass `--allow-insecure`, garbage-collect the Nix store, delete profiles, or remove `.devbox` data without explicit approval. If prerequisites are unsupported, stop and link to the closest official installation path.

Verify `devbox version`, `nix --version`, the resolved executable path, platform mode, Nix daemon state, and the list of profiles before and after setup. For an existing project, inspect configuration without evaluating hooks. Otherwise initialize a disposable empty directory, inspect the generated JSON and lock file, enter an empty Devbox shell, and exit without adding packages. Prove that no pre-existing project lock, global profile, shell file, daemon setting, or store path was removed. Finish with changed paths, downloaded store size, verification evidence, manual steps, and rollback commands that remove only setup-created files and restore backups.
