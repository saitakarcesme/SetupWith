# Resources setup prompt

Set up Resources from its official source and verified Flathub listing (https://apps.gnome.org/Resources/). Inventory Linux architecture, Flatpak scopes, existing package and data paths, sandbox overrides, available CPU/GPU/storage/battery telemetry classes, process-control permission presence, refresh policy and saved-state size without launching a monitor or listing process names, command lines, users, PIDs, network addresses, interface names, device serials, mount paths, container names, application activity or usage samples. Install stable `net.nokyan.Resources` from verified Flathub in the existing ownership scope. Do not compile from source, launch Resources, enumerate host processes, poll hardware counters, open device nodes, contact services, stop a process, alter priority, export diagnostics, or change monitoring preferences during setup.

Preserve existing Resources state, view and refresh preferences, sandbox overrides, host permissions, process state, workloads, services, device configuration, drivers, power policy, remotes and scope ownership. System-monitor data can expose document names in command lines, usernames, infrastructure topology, VPNs, mounts and workload timing; redact those identifiers from setup evidence. Treat process control as destructive: a reused PID or stale view can target the wrong workload, and terminating a supervised service may cause an automatic restart or wider outage. Installation never authorizes a stop, terminate, kill or priority change.

Before later monitoring, review each declared filesystem, procfs, sysfs, device, session-bus and system-bus capability against the required CPU, memory, GPU, network, storage and battery views. Document unavailable metrics instead of widening permissions or installing drivers. Set a bounded refresh interval and measure observer overhead on synthetic workload labels. Distinguish memory cache from application use, shared memory from private attribution, link counters from internet traffic, and unsupported sensor values from zero. Before process control require exact PID plus start time, owner, full redacted identity, children, service/container supervision, unsaved-work impact and an explicit per-action confirmation.

Verify provenance, app ID, origin, commit, runtime, executable, files and static sandbox permissions offline. Compare process counts and host state only through preapproved aggregate evidence; do not use Resources itself for installation verification. Prove no process enumeration, telemetry polling, device access, bus call, signal, priority change, network activity, diagnostic export, preference write or notification occurred. On failure, rollback only the new Resources ref in its original scope; preserve shared runtimes, remotes, overrides, running processes, services, devices, drivers, monitoring state and system policy.
