# Mousai setup prompt

Set up Mousai from its official repository and verified Flathub listing (https://apps.gnome.org/Mousai/). Inventory Linux architecture, Flatpak scopes, existing package and data paths, PipeWire or PulseAudio state, microphone and desktop-audio portal grants, recognition-history count, offline-queue count, preview output and AudD credential-reference presence without activating audio, reading history, inspecting clips or accessing the token. Install stable `io.github.seadve.Mousai` from verified Flathub in the existing ownership scope. Do not compile from source, launch Mousai, request capture permission, record audio, contact AudD, replay queued clips, preview a song or open a provider during setup.

Preserve recognition history, offline queue, timestamps, matched metadata, API-token reference, capture choice, output route and preferences. Microphone or desktop capture can include conversations, meetings, calls, notifications and protected media beyond the intended song. Before future listening show the exact source device or application stream, capture duration, visible indicator, bystander consent, applicable policy, stop control and whether any raw clip persists. Prefer a single approved desktop stream over system-wide audio, and never capture authentication, conferencing or communications apps.

Recognition sends audio-derived material to the AudD API. Show endpoint, TLS validation, clip encoding and length, account identity, trial or paid quota, token scope, retention/deletion terms, jurisdiction and retry behavior before upload. Use a dedicated revocable credential only if extra trials are approved. Offline mode can defer rather than avoid disclosure: list queued item counts and expiry without content, require approval before later upload, and securely purge only selected setup-owned queue items.

A title/artist result may be wrong; display confidence or uncertainty and never use a match as copyright, identity or forensic proof. In-app previews and provider links trigger new third-party requests; keep autoplay off, confirm output volume and route, validate final hosts and strip unnecessary tracking parameters. Verify provenance, app ID, origin, commit, runtime, executable, files and permissions offline. Prove no audio capture, portal grant, token access, queue mutation, API request, history entry, preview, browser launch or filesystem state changed. On failure, rollback only the new Mousai ref in its original scope; preserve runtimes, remotes, overrides, history, queue and credentials.
