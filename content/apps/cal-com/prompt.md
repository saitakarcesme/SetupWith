# Cal.com setup prompt

Codex, first inspect the OS, architecture, shell, Node and container tooling, existing Cal.com deployment, database, environment files, calendar integrations, public URL, and occupied ports. Prefer Cal.com’s official Docker self-hosting workflow for an isolated deployment; use the official repository with its documented package manager only when a development installation is explicitly requested. Ask before administrator access, installing Docker or Node tooling, creating databases, running migrations, exposing ports, changing firewall rules, opening a browser, enabling OAuth providers, or overwriting environment files. Preserve bookings, users, teams, database data, integrations, and uploaded assets. Configure only `public_url`, `server_port`, and `default_timezone` when supplied. Inject `secret://provider/NEXTAUTH_SECRET`, `secret://provider/CALENDSO_ENCRYPTION_KEY`, and `secret://provider/DATABASE_URL` through protected runtime secrets; never print, echo, log, or commit them. Do not configure calendar-provider credentials or browser sign-in without separate approval. Verify container or application health, migration completion, URL and timezone settings, database connectivity, and the public scheduling page using a disposable local account only if approved. Rollback stops and removes only created services, restores configuration, and retains databases unless deletion is authorized. Finish with a structured summary of runtime, URL, timezone, database, integrations state, verification, approvals, and rollback.
