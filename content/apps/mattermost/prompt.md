# Mattermost setup prompt

Codex, inspect the OS, architecture, shell, existing Mattermost deployment, Docker or Kubernetes tooling, PostgreSQL database, file storage, configuration, plugins, site URL, and occupied ports. Prefer Mattermost’s official Docker deployment for a new self-hosted instance; use official Linux packages only when an existing managed server layout is already present. Ask before administrator access, installing services, creating databases, running migrations, exposing ports, changing firewall rules, opening a browser, enabling plugins, or overwriting configuration. Preserve messages, users, teams, uploads, database volumes, plugins, and `config.json`. Configure only `server_port`, `site_url`, `default_team`, and `file_storage` when supplied. Inject `secret://provider/MM_SQLSETTINGS_DATASOURCE` and `secret://provider/MM_SERVICESETTINGS_SITEURL` through protected runtime configuration; never print, echo, log, or commit values. Keep the deployment local until URL, TLS, and proxy settings are approved. Verify official image or package identity, database connectivity, migration completion, file-storage permissions, server health, and login-page availability without browser sign-in. Rollback restores configuration, removes only newly created services, and preserves database and uploaded files unless deletion is explicitly authorized. Finish with a structured summary of topology, database, storage, URL, port, verification, approvals, and rollback.
