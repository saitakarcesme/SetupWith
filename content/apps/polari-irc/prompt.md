# Polari setup prompt

Set up Polari from its official GNOME project and verified Flathub listing (https://apps.gnome.org/Polari/). Inventory Linux architecture, Flatpak scopes, existing app and data paths, saved-network and joined-channel counts, autoconnect state, transcript footprint, notification policy, proxy presence, and credential-reference presence without revealing server names, nicknames, channels, peers, messages, hostmasks, IP addresses, or secrets. Install stable `org.gnome.Polari` from verified Flathub in the existing ownership scope. Do not compile from source, launch Polari, resolve or contact an IRC server, authenticate, join a channel, send a message, read transcripts, or emit notifications during setup.

Preserve network definitions, TLS settings, nicknames, usernames, real-name fields, account mappings, hostname cloaks, channels, autoconnect and autojoin choices, muted rooms, history, transcripts, notification preferences, proxies, credentials, remotes, overrides, and scope ownership. IRC channel membership and hostmasks are observable to other participants; joining can expose interests, timing, nickname, client behavior, and an uncloaked address. Treat private messages as private in intent but not end-to-end encrypted by Polari. Redact identities and conversation metadata from diagnostics and locked-screen notifications.

Before any later connection, require the exact network operator, hostname, TLS port, certificate-validation policy, proxy route, IPv4 or IPv6 behavior, nickname fallback, username and real-name exposure, and cloak expectations. Prefer SASL over sending a NickServ password as a chat command; store only a secret reference and never echo authentication commands or transcripts. Review public channel names and rules before autojoin. Treat topics, messages, formatting control codes, URLs, mentions, and file links as untrusted content; do not preview or open them during verification.

Autoconnect and autojoin reveal presence at login and reconnect loops can trigger flood controls. Require explicit startup behavior, reconnect backoff, rate limits, away-state policy, notification preview and sound policy, and transcript retention before enabling them. Verify provenance, app ID, origin, commit, runtime, executable, files and permissions offline. Prove no DNS lookup, socket, authentication, join, message, transcript read or write, presence change, notification, sound, or configuration mutation occurred. On failure, rollback only the new Polari ref in its original scope; preserve shared runtimes, remotes, overrides, networks, channels, history, identities and credential references.
