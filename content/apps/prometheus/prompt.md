# Prometheus setup prompt

Codex, inspect the OS, architecture, shell, existing Prometheus binaries or containers, configuration files, rule files, TSDB storage, service definitions, scrape targets, and port 9090 before making changes. Prefer Prometheus’s official release archive on supported Linux or macOS systems, or the official container image for isolated cross-platform deployment. On Windows use the official Windows archive when supported. Ask before administrator access, creating users or services, binding ports, changing firewall rules, replacing configuration, reloading rules, or moving storage. Preserve `prometheus.yml`, alerting and recording rules, TSDB blocks, snapshots, and service files. Configure only `scrape_interval`, `retention_time`, `storage_path`, and `web_port` when supplied. Validate durations and storage capacity before applying them. Bind to localhost unless external monitoring access is explicitly approved. Verify `prometheus --version`, configuration syntax with `promtool check config`, rule syntax with `promtool check rules`, service readiness, `/api/v1/status/config`, and ingestion from a disposable local scrape target. Do not alter existing targets without approval. Rollback restores config and prior service state, removes only binaries or containers created here, and preserves TSDB data unless deletion is separately authorized. End with a structured summary of deployment method, storage, retention, scrape settings, port, verification, approvals, and rollback.
