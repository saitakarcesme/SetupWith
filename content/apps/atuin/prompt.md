# Atuin setup prompt

Set up Atuin from its official installation documentation (https://docs.atuin.sh/18.17/guide/installation/). Detect Windows, macOS, or Linux, architecture, active and installed shells, package managers, existing Atuin binary, shell hooks, config and data directories, SQLite history database, encrypted record store, import state, sync account, server URL, daemon, session token and encryption key. Prefer a stable package-manager release or checksummed official binary. If considering the Unix setup script, download and inspect it first and force its non-interactive path; never pipe network content directly into a shell.

Install only the executable. Do not evaluate `atuin init`, edit `.zshrc`, `.bashrc`, Fish, Nushell, Xonsh or PowerShell profiles, bind Ctrl-R, Up or `?`, start the daemon, create configuration, import history, register or log in, sync, enable AI or dotfiles, or change the default shell. Preserve every native history file, Atuin database and record, command text, timestamps, working directories, durations, exit codes, host and session identifiers, filters, statistics, config, keys, tokens, accounts, remote history, aliases and environment variables.

Shell integration installs preexec and precmd hooks that record commands and context. History frequently contains pasted passwords, tokens, private URLs, customer names and filesystem paths. Before any later import, perform a local-only dry review of the source and ignore rules, explain metadata retention, back it up, and obtain approval; never display raw history or put secrets in logs. Sync must remain off until the user chooses a server, reviews encryption and recovery, stores the key separately, and approves the exact first upload. Never print `atuin key`, pass passwords or keys as command arguments, delete an account, rekey, purge, force-push or force-pull the store. Dotfile sync can distribute aliases and environment variables to other machines and requires an independent diff.

Verify package provenance or checksum, `atuin --version`, resolved executable, installation method and PATH without launching an interactive shell or any command that initializes storage. Hash the pre-existing shell profiles, history files, Atuin config, database, record store, key and session files before and after using metadata-only comparisons that do not reveal content. Confirm no hook, binding, daemon, database migration, import, sync request, account action, AI call, alias or environment change occurred. Roll back only the installed binary and setup-owned PATH entry, retaining all history, cryptographic material, configuration and remote state.
