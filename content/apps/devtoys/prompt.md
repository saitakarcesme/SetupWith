# DevToys setup prompt

Set up DevToys from the official download page and DevToys-app repository (https://devtoys.app/download/). Detect Windows, macOS, or Linux, CPU architecture, package managers, .NET 8 availability, existing GUI and CLI installations, portable copies, and DevToys data and plugin directories. Distinguish the desktop app from DevToys CLI. Choose the official Microsoft Store, Winget, macOS app or Homebrew cask, Linux DEB, or matching portable archive; do not use download-page options marked coming soon or substitute an unofficial package.

Preserve settings, favorites, recent-tool preferences, window state, portable data, CLI configuration, custom tools, and installed extensions. Report whether the selected artifact bundles .NET or depends on the host runtime, and verify its architecture and release provenance before installation. Apply only the requested GUI or CLI variant, portable mode, recent-tools preference, and explicitly named extensions. Do not silently install both variants or migrate data between stable and preview channels.

Treat all text, JWTs, certificates, keys, hashes, URLs, files, images, and clipboard content supplied to DevToys as potentially sensitive even when processing is local. Never populate a tool with real credentials for testing, read the clipboard automatically, retain sample data in recents, or include user input in logs or screenshots. DevToys 2 supports third-party extensions, so show each extension's publisher, source, version, permissions, files, and checksum before approval. Do not enable unknown feeds, sideload a plugin, overwrite an extension directory, or load an unsigned preview extension.

Verify the installed DevToys and CLI versions, publisher or checksum, executable paths, architecture, runtime dependency, settings path, and plugin path. Launch the GUI without opening sensitive files or using clipboard content, and test only with a disposable public string; for CLI, list help and available tools without transforming user data. Confirm no extension was downloaded, no recent sensitive value was stored, and no unrelated configuration changed. Roll back by removing only the installed variant and setup-added extensions, restoring backed-up settings, and preserving portable folders and all pre-existing plugins.
