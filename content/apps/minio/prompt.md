# MinIO setup prompt

Codex, begin by detecting the OS, architecture, shell, existing MinIO binary or container, storage volumes, service definitions, certificates, and occupied API and console ports. Prefer MinIO’s official binary on supported Linux or macOS hosts, or the official container image for macOS, Linux, and Windows environments. Ask before administrator access, installing container tooling, creating a persistent service, exposing ports, changing firewall rules, modifying storage directories, or replacing certificates and configuration. Preserve all buckets, object versions, policies, encryption metadata, certificates, and existing volumes. Configure only `data_directory`, `api_port`, `console_port`, and `server_url` when supplied. Inject `secret://provider/MINIO_ROOT_USER` and `secret://provider/MINIO_ROOT_PASSWORD` through a protected environment or secret store; never print, echo, log, or commit values. Bind to localhost unless network use is approved, and reject an empty or temporary data directory for production. Verify binary or image identity, storage access, health endpoints, console reachability, authenticated `mc` alias configuration, and creation plus deletion of a disposable bucket and object. Rollback removes only created services, containers, and aliases, restores configuration, and retains object data unless deletion is authorized. End with a structured summary of deployment, storage, endpoints, credentials handling, checks, approvals, and rollback.
