# direnv setup prompt

Set up direnv from its verified official source (https://github.com/direnv/direnv). Supported targets: macOS, Linux. Begin with a read-only preflight covering the operating system, architecture, shell, package managers, disk space, relevant runtimes or hardware, and any existing installation. Use the trusted platform package or official binary, then show the exact shell-hook line appropriate to the detected shell before editing startup files.

Preserve shell startup files, existing direnv configuration, allow records, `.envrc` files, environment variables, and project secrets. Back up files before editing and explain the selected version, source, location, dependencies, and commands. Apply only supplied, supported preferences: preferred_shell, config_directory, environment_variables, project_directory. No credential references are needed for this setup.

Ask before elevation, system-wide packages, services or startup items, ports or firewall rules, sign-in, large downloads, overwrites, or migrations.  Do not enable startup items, background services, overlays, notifications, analytics, or device permissions unless they are requested and separately approved. Do not allow or execute any existing `.envrc`, read secret values, or add a shell hook without explicit approval. For a large game or media download, report the exact size, destination drive, free space, and bandwidth impact, then wait for approval. Never delete game libraries, save files, media libraries, mods, profiles, or cloud-sync data. If the platform or configuration is unsupported, stop and offer the closest official alternative.

Run `direnv version` and test hook behavior in a disposable directory containing a harmless variable; confirm it unloads after leaving the directory. Report the version, executable, configuration and data paths, changed files, active processes or listeners, and verification evidence without exposing sensitive values. End with manual steps and exact rollback or uninstall instructions that remove only setup-owned changes, restore backups, stop new services, and preserve user data.
