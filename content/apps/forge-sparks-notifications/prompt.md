# Forge Sparks setup prompt

Set up Forge Sparks from its official repository and verified Flathub listing (https://apps.gnome.org/ForgeSparks/). Inventory Linux architecture, Flatpak scopes, existing package and data paths, forge types, account count, HTTPS origins, secret-store boundary, notification privacy, polling policy and API-rate-limit expectations without contacting servers, reading tokens or listing repositories. Install stable `com.mardojai.ForgeSparks` from verified Flathub in the existing ownership scope. Do not install nightly artifacts, compile from source, launch the app, authenticate, discover an API, fetch notifications or register notification actions during setup.

Preserve every account origin, username reference, token reference, notification filter, unread state, polling interval and desktop policy. Repository names, review requests, issue titles and actor identities may reveal unreleased products or security incidents; redact them from diagnostics and locked-screen notifications. Never reuse a broad development token merely because it already exists in a shell, Git credential helper or forge CLI. Create a dedicated expiring credential only after review, with the minimum read-only notification scope supported by that server, and record its revocation owner.

Before any future connection show the exact HTTPS origin, certificate validation, redirects, forge implementation and version, authenticated identity, requested API endpoints/scopes, private-resource visibility, pagination, conditional-request behavior, poll interval, rate-limit budget and retry backoff. Self-hosted GitLab, Gitea and Forgejo instances can differ from public services; do not guess paths or disable TLS. Initial synchronization must be read-only and must not mark, dismiss, subscribe, comment, approve or mutate forge state.

Notification actions can open attacker-controlled issue links in a logged-in browser. Validate scheme and final host, show the chosen browser profile and require a click; never auto-open, render untrusted markup or include access tokens in URLs. Keep notification previews hidden until content classification is approved. Verify provenance, app ID, origin, commit, runtime, executable, files and permissions offline. Prove no secret access, API request, account creation, polling timer, unread mutation, notification, browser launch or filesystem state changed. On failure, rollback only the new Forge Sparks ref in its original scope; preserve runtimes, remotes, overrides, accounts, tokens and notification history.
