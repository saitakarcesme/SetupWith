# NewsFlash setup prompt

Set up NewsFlash from its official project and verified Flathub listing (https://gitlab.com/news-flash/news_flash_gtk). Inventory Linux architecture, Flatpak scopes, existing NewsFlash package and data paths, configured backend type, server origin, secret-store boundary, local database, OPML policy, notification settings, content-grabber rules and retention preferences without opening feeds, credentials or article content. Install stable `io.gitlab.news_flash.NewsFlash` from verified Flathub in the existing ownership scope. Do not install Snap or unsupported distro builds, compile from source, launch NewsFlash, authenticate, add a feed, import OPML or start synchronization.

Preserve subscriptions, feed URLs, folders, tags, read/unread and starred states, offline articles, search index, media cache, service credentials, cookies, custom extraction rules and preferences. Subscription lists reveal political, health, religious and professional interests; never print feed titles/URLs or OPML contents in diagnostics. Do not migrate from FeedReader, deduplicate subscriptions, clear caches or choose a default service. Local RSS and each web backend have different identity and conflict semantics.

Before future service connection show exact HTTPS server, certificate verification, redirects, authentication/OAuth flow, requested API scope, secret storage and the direction and conflict rules for initial sync. Never assume the server is authoritative for deletions, read state or tags. Preview the counts of local-only and remote-only changes without content, and require a backup before bidirectional merge. OPML may contain private or credential-bearing URLs; export only to an approved protected destination.

Treat feed XML and article HTML as untrusted web content. Do not render articles, load remote images/tracking pixels, execute navigation, open an external browser or fetch full content during setup. The full-article grabber can contact publisher pages and use domain-specific rules; it does not bypass paywalls and must not be used to evade access controls. Keep notifications off for verification because titles can appear on a locked screen. Verify NewsFlash provenance, app ID, origin, commit, runtime, executable, files and permissions offline. Prove no secret access, server request, feed parse, sync mutation, OPML operation, article render, cache, notification, share, clipboard or browser state changed. On failure, rollback only the new NewsFlash ref in its original scope; preserve runtimes, remotes, overrides, databases, credentials and all subscriptions.
