# Gaphor setup prompt

Set up Gaphor from its official repository and verified Flathub listing (https://apps.gnome.org/Gaphor/). Inventory Linux architecture, Flatpak scopes, existing package and data paths, project-file count, broad model-language mix, application-version provenance, backup availability, home-folder permission breadth and collaboration method without opening models, reading element names or exposing architecture. Install stable `org.gaphor.Gaphor` from verified Flathub in the existing ownership scope. Do not compile from source, launch Gaphor, open or migrate a model, import a profile, change filesystem permissions, generate a diagram or export content during setup.

Preserve model files byte-for-byte, including identifiers, packages, elements, relationships, constraints, stereotypes, profiles, diagrams, presentations, styles, metadata, recovery data and version-control state. A Gaphor project is a semantic UML 2, SysML, RAAML or C4 model, not merely a set of pictures; a visually plausible result can still corrupt relationships or traceability. Never auto-fix references, normalize IDs, relayout diagrams, remove orphan-looking elements or convert a legacy model in place. Copy an approved model and verify backup restoration before any version migration.

Treat model and profile files as untrusted structured input. Before future opening show source, checksum, file size, expected Gaphor/schema version, selected modeling language, external-profile inventory, parser resource limits and whether a conversion will be written. Work on a protected duplicate first and compare element, relationship, diagram and identifier counts plus validation findings without exposing names. Gaphor files do not provide safe multi-writer merging by default; establish one owner or an explicitly tested version-control workflow before concurrent edits.

The Flatpak may have broad home-folder access. Retain existing permissions during installation and later narrow them only against an approved project root after confirming file chooser, autosave and export needs. Exports can disclose hidden architecture through labels, links or metadata; review PNG, SVG, PDF and clipboard destinations separately. Verify provenance, app ID, origin, commit, runtime, executable, files and permissions offline. Prove no model read, schema migration, recent-file entry, recovery file, import, layout, clipboard, export or filesystem state changed. On failure, rollback only the new Gaphor ref in its original scope; preserve runtimes, remotes, overrides, projects and backups.
