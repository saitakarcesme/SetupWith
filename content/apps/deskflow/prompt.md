# Deskflow setup prompt

Set up Deskflow from its official project releases (https://github.com/deskflow/deskflow/releases). Detect Windows, macOS, or Linux, architecture, desktop session, X11 or Wayland, package managers, Visual C++ runtime, existing Deskflow, Barrier, Input Leap or Synergy processes, services, listeners, firewall rules, certificates, peer fingerprints, portal grants, and accessibility permissions. Prefer a stable distribution package or official release. On macOS disclose that direct builds may be unnotarized; do not clear quarantine or bypass Gatekeeper without explicit approval of the exact artifact and checksum.

Install without selecting server/client role, starting a service, opening TCP port 24800, discovering peers, or requesting input permissions. Preserve screen layouts and names, hotkeys, switch rules, TLS keys and certificates, trusted fingerprints, clipboard limits, server addresses, logs, daemon mode, startup state, compatibility protocol, firewall rules, portal restore tokens, and all peer configurations. Apply only the approved role, layout, clipboard setting, and TLS/fingerprint policy. TLS and fingerprint checking must remain enabled; compatibility with older forks is never a reason to weaken them silently.

Deskflow gives one computer the ability to inject keyboard and pointer input into another and can transfer clipboard contents whenever the cursor crosses screens. Treat both as sensitive remote control. Require approval for each named peer, IP, network, direction, role, screen edge, and session. Stop separately before macOS Accessibility, Input Monitoring, Screen Recording or Local Network access; Linux remote-desktop portals; a Windows daemon able to interact with UAC or login screens; firewall changes; background startup; certificate regeneration; fingerprint trust; or clipboard sharing. Never expose the listener beyond the approved trusted LAN, disable TLS, auto-accept a fingerprint, or copy passwords and secrets between peers.

Verify publisher or package provenance, version, executable/configuration paths, permission state, services, startup items, processes, listeners, firewall baseline, certificate fingerprint and peer list without revealing private keys. Do not connect to another machine for a smoke test. If a controlled two-host test is later approved, disable clipboard sharing, confirm fingerprints out of band, use a disposable input target, and retain a local keyboard escape path to avoid lockout. Roll back services, grants, listeners and rules created here, restore configurations, and preserve existing certificates, peer trust and layouts.
