# Gradia setup prompt

Set up Gradia from its official repository and verified Flathub listing (https://apps.gnome.org/Gradia/). Inventory Linux architecture, Flatpak scopes, existing package and data paths, screenshot-portal state, recent-file count, default export directory, clipboard policy, image-cache location and whether Imgur upload is allowed without opening images, reading filenames or contacting a service. Install stable `be.alexandervanhee.gradia` from verified Flathub in the existing ownership scope. Do not compile from source, launch Gradia, capture or import a screenshot, render a code snippet, grant portal access, copy an image, export or upload during setup.

Preserve originals, edits, annotations, backgrounds, dimensions, color profiles, recent-file state and preferences. Screenshots can expose names, messages, credentials, customer data, device identifiers and location clues. Before future editing identify the image owner, intended audience, classification and minimum crop. Work on a protected duplicate. Inspect crop boundaries, off-canvas pixels, embedded thumbnails, EXIF/XMP metadata, filenames, temporary files and undo data; a visually cropped image may still retain sensitive material elsewhere.

A blur, pixelation or annotation layer is not reliable redaction if underlying pixels remain recoverable. For censoring, cover the full sensitive region with an opaque treatment, flatten to a new raster output, strip metadata, close and reopen that output, inspect at high zoom and have a second reviewer confirm it without access to the original. Keep the original separate and access-controlled. Do not claim redaction success from appearance in the editor alone. Verify annotations and arrows for factual accuracy and accessibility before publication.

Treat source snippets as sensitive code: scan for tokens, internal hosts, customer identifiers, comments and license restrictions before rendering. Imgur upload leaves the device and may create a public or hard-to-delete copy; show final pixels, destination, visibility, retention, terms, jurisdiction and deletion mechanism, then require explicit approval. Never upload as a verification step. Verify provenance, app ID, origin, commit, runtime, executable, files and permissions offline. Prove no image read, portal grant, cache, clipboard, export, network request, upload or filesystem state changed. On failure, rollback only the new Gradia ref in its original scope; preserve runtimes, remotes, overrides, originals and edits.
