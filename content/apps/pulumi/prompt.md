# Pulumi setup prompt

Codex, inspect the operating system, architecture, active shell, existing `pulumi` binary, language runtimes, backend configuration, stacks, plugins, credentials files, and current infrastructure repositories before changing anything. Prefer Homebrew `pulumi` on macOS, Pulumi’s official signed installation method on Linux, and `winget install Pulumi.Pulumi` on Windows. Ask before administrator access, executing a remote installer, changing PATH, logging into Pulumi Cloud, selecting a backend, downloading providers, switching stacks, or running `up` or `destroy`. Preserve `Pulumi.yaml`, stack files, state, plugins, policy packs, and credentials. Configure only `backend_url`, `default_organization`, and `default_stack` when supplied. Use `secret://provider/PULUMI_ACCESS_TOKEN` and `secret://provider/PULUMI_CONFIG_PASSPHRASE` only through protected environment or credential mechanisms; never print, echo, log, or commit their values. Prefer a local backend for verification unless an approved backend already exists. Verify `pulumi version`, plugin discovery, backend status, and stack listing. Create a disposable local project that previews a file resource without applying changes. Rollback restores credentials and config backups, removes only plugins or the CLI installed here, and never deletes stack state automatically. Finish with a structured summary of installation source, backend, organization, stack, verification, approvals, and rollback.
