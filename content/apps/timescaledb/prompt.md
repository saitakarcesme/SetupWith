# TimescaleDB setup prompt

Set up TimescaleDB from its verified official source (https://github.com/timescale/timescaledb). Supported targets: Linux. Begin with a read-only preflight covering the operating system, architecture, shell, package managers, disk space, relevant runtimes or hardware, and any existing installation. Match the TimescaleDB package exactly to an approved PostgreSQL major version and distribution, using the official repository or container image and a fresh test cluster by default.

Preserve PostgreSQL clusters, extension versions, `postgresql.conf`, preload libraries, tablespaces, backups, credentials, and container volumes. Back up files before editing and explain the selected version, source, location, dependencies, and commands. Apply only supplied, supported preferences: postgres_version, data_directory, listen_address, listen_port, telemetry_preference. The only available credential references are secret://postgres/password. Treat every reference as opaque: never print, echo, log, resolve, or paste its value.

Ask before elevation, system-wide packages, services or startup items, ports or firewall rules, sign-in, large downloads, overwrites, or migrations.  Do not enable startup items, background services, overlays, notifications, analytics, or device permissions unless they are requested and separately approved. Do not modify an existing cluster, preload the extension, run `CREATE EXTENSION`, migrate data, or expose PostgreSQL without approval and a verified backup. For a large game or media download, report the exact size, destination drive, free space, and bandwidth impact, then wait for approval. Never delete game libraries, save files, media libraries, mods, profiles, or cloud-sync data. If the platform or configuration is unsupported, stop and offer the closest official alternative.

Confirm package and PostgreSQL compatibility; only in a disposable cluster run `CREATE EXTENSION timescaledb` and query its version, then stop and remove the test cluster. Report the version, executable, configuration and data paths, changed files, active processes or listeners, and verification evidence without exposing sensitive values. End with manual steps and exact rollback or uninstall instructions that remove only setup-owned changes, restore backups, stop new services, and preserve user data.
