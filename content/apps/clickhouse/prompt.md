# ClickHouse setup prompt

Codex, first inspect the OS, architecture, shell, existing `clickhouse` binaries, package source, server configuration, data and log directories, active services, ports 8123 and 9000, users, and backups. Prefer ClickHouse’s official packages and signed repository on supported Linux distributions; on macOS use Homebrew for local development; on Windows use an approved Docker or WSL deployment rather than pretending there is a standard native server installation. Ask before administrator access, adding repositories, starting services, exposing ports, changing firewall rules, creating users, or modifying storage paths. Preserve databases, parts, metadata, dictionaries, access-control files, `config.xml`, `users.xml`, and service definitions. Configure only `clickhouse_user`, `clickhouse_database`, `http_port`, and `data_directory` when provided. Inject `secret://provider/CLICKHOUSE_PASSWORD` through secure configuration or protected input and never print, echo, log, or expose it in arguments. Bind locally unless external access is approved. Verify `clickhouse client --version`, server status, HTTP health, authenticated client access, database creation, and a disposable MergeTree table with insert and aggregate queries. Rollback restores configs and service state, removes only newly created resources, and never deletes existing data without approval. End with a structured summary of deployment method, ports, storage, account, database, verification, approvals, and rollback.
