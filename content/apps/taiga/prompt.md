# Taiga setup prompt

Codex, inspect the OS, architecture, shell, Docker and Compose versions, existing Taiga deployment, PostgreSQL and RabbitMQ data, media volumes, configuration, domains, and occupied ports before proceeding. Prefer the official `taiga-docker` repository and its documented Compose workflow. Ask before administrator access, cloning over an existing directory, installing or starting container services, creating databases, running migrations, exposing ports, changing firewall rules, opening a browser, or overwriting environment files. Preserve projects, users, attachments, database volumes, event queues, static files, and reverse-proxy configuration. Configure only `domain_name`, `server_port`, and `default_language` when supplied. Use `secret://provider/SECRET_KEY`, `secret://provider/POSTGRES_PASSWORD`, and `secret://provider/RABBITMQ_PASS` only through protected environment files with restrictive permissions; never print, echo, log, or commit values. Bind locally unless the domain and TLS path are approved. Verify repository origin, container health, database migrations, asynchronous-events service, media permissions, API readiness, and the web login page without creating external accounts. Rollback restores compose and environment backups, removes only containers created here, and preserves volumes and media unless deletion is authorized. Finish with a structured summary of deployment source, domain, language, services, storage, verification, approvals, and rollback.
