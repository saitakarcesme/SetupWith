# Docker Desktop setup prompt

Set up Docker Desktop from its verified official source (https://docs.docker.com/desktop/). Supported targets: macOS, Linux, Windows. Begin with a read-only preflight covering the operating system, architecture, shell, package managers, disk space, relevant runtimes or hardware, and any existing installation. Install Docker Desktop only when a desktop-managed engine is desired and confirm its license terms for the user's organization. On Windows, select WSL 2 or Hyper-V deliberately; on macOS, match Apple or Intel silicon; on Linux, avoid conflicting with an existing Engine context.

Preserve all Docker contexts, credentials, images, containers, Compose projects, volumes, networks, BuildKit cache, Kubernetes state, registry settings, WSL distributions, VM disk image, extensions, resource limits, and file-sharing configuration. Back up files before editing and explain the selected version, source, location, dependencies, and commands. Apply only supplied, supported preferences: backend, resources_cpu, resources_memory, disk_image_location. The only available credential references are secret://docker/auth-config. Treat every reference as opaque: never print, echo, log, resolve, or paste its value.

Ask before elevation, system-wide packages, services or startup items, ports or firewall rules, sign-in, large downloads, overwrites, or migrations.  Treat drivers, kernel components, anti-cheat, background services, overlays, firewall changes, startup items, and restarts as separate approval checkpoints. Explain the exact component, vendor, privileges, persistence, and rollback before continuing. Require approval before privileged helpers, WSL or Hyper-V features, kernel modules, network services, firewall changes, group membership, file-sharing roots, Kubernetes, extensions, account sign-in, resolving secret://docker/auth-config, relocating the disk image, resetting data, or restarting the host. For a large game or media download, report the exact size, destination drive, free space, and bandwidth impact, then wait for approval. Never delete game libraries, save files, media libraries, mods, profiles, or cloud-sync data. If the platform or configuration is unsupported, stop and offer the closest official alternative.

Run `docker version`, `docker context show`, and `docker info` without pulling an image or starting a container; also confirm Compose version, backend, listeners, VM or WSL state, and resource limits. Rollback must never reset, prune, unregister WSL, or delete images, volumes, containers, networks, or disk data. Report the version, executable, configuration and data paths, changed files, active processes or listeners, and verification evidence without exposing sensitive values. End with manual steps and exact rollback or uninstall instructions that remove only setup-owned changes, restore backups, stop new services, and preserve user data.
