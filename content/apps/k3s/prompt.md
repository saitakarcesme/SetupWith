# k3s setup prompt

Codex, first inspect the Linux distribution, architecture, shell, existing k3s binary, service state, container runtime, cluster token files, manifests, data directories, node role, network interfaces, and ports. Install k3s only on supported Linux hosts using the official `get.k3s.io` installer or documented binary method; do not attempt native macOS or Windows installation outside an explicitly approved Linux VM. Ask before administrator access, executing the installer, creating systemd or OpenRC services, opening cluster ports, changing firewall rules, disabling swap, joining a cluster, or deleting existing state. Preserve `/etc/rancher/k3s`, `/var/lib/rancher/k3s`, manifests, certificates, kubeconfig, and service overrides. Configure only `cluster_name`, `node_role`, `server_url`, and `data_directory` when supplied. Inject `secret://provider/K3S_TOKEN` through a protected environment or token file; never print, echo, log, or expose it in process listings. Verify service health, `k3s --version`, node readiness, system pods, selected runtime, and kubeconfig access. Do not deploy workloads beyond a disposable namespace unless approved. Rollback uses the official uninstall script only after confirmation and preserves requested backups of cluster state. Finish with a structured summary of node mode, server relationship, storage, networking, checks, approvals, and rollback.
