# LocalAI setup prompt

Codex, begin by detecting the operating system, architecture, shell, CPU instruction support, GPU hardware, existing LocalAI installation, container engine, occupied ports, and model directories. Prefer LocalAI’s official Docker or Podman image across supported platforms; on macOS, the official application package is also acceptable when a desktop setup is requested. Use documented Linux binaries only when containers are unavailable. Ask before administrator access, installing or starting a container daemon, exposing ports, changing firewall rules, downloading models, or overwriting model configuration. Preserve existing model files, galleries, container volumes, and YAML configuration. Configure only `model_gallery`, `context_size`, `threads`, and `listen_address` when provided. Use `secret://provider/LOCALAI_API_KEY` and `secret://provider/HUGGINGFACE_TOKEN` solely through secure environment injection; never print, echo, log, or commit them. Default the API to localhost and require approval for remote binding. Select a small compatible model only after checking disk, RAM, and acceleration support. Verify the container or binary version, health endpoint, `/v1/models`, and one short OpenAI-compatible completion using an approved local model. Rollback should remove only resources created here and retain model storage unless deletion is authorized. Finish with a structured summary of backend, hardware path, model source, settings, verification, approvals, and rollback.
