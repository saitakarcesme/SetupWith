# Nextcloud setup prompt

Codex, first inspect the OS, architecture, shell, existing Nextcloud deployment, web server, PHP runtime, database, containers, data directory, configuration, apps, and occupied ports. Prefer Nextcloud’s official Docker image with persistent volumes for a new cross-platform deployment; use the official archive only when an existing Linux web stack is already managed. Ask before administrator access, installing container or web-server services, creating databases, binding ports, changing firewall rules, opening a browser, running upgrades, or overwriting `config.php`. Preserve the data directory, database, installed apps, themes, certificates, and existing volumes. Configure only `admin_user`, `trusted_domains`, `data_directory`, and `server_port` when supplied. Inject `secret://provider/NEXTCLOUD_ADMIN_PASSWORD` and `secret://provider/MYSQL_PASSWORD` through protected runtime secrets; never print, echo, log, or commit values. Keep the service localhost-only until trusted domains and reverse proxy settings are approved. Verify container or web-stack health, `occ status`, database connectivity, trusted-domain configuration, writable storage, and the login endpoint without browser sign-in. Rollback stops and removes only newly created services and restores configuration, while retaining database and files unless deletion is explicitly authorized. Finish with a structured summary of deployment mode, database, storage, domains, port, verification, approvals, and rollback.
