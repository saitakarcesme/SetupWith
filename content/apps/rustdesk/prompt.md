# RustDesk setup prompt

Set up RustDesk from its verified official source (https://github.com/rustdesk/rustdesk/releases/latest). Supported targets: macOS, Linux, Windows. Begin with a read-only preflight covering the operating system, architecture, shell, package managers, disk space, relevant runtimes or hardware, and any existing installation. Choose the signed release asset matching the OS, CPU, and Linux package format from the RustDesk GitHub release, and distinguish portable use from `--silent-install`. Do not deploy hbbs or hbbr server components or install the client service as part of a basic desktop setup.

Preserve RustDesk2 configuration, device ID, approved relay and ID server endpoints, imported encrypted configuration, trusted peers, address-book state, permanent-password policy, service installation, and screen-capture or accessibility permissions. Back up files before editing and explain the selected version, source, location, dependencies, and commands. Apply only supplied, supported preferences: id_server, relay_server, api_server, unattended_access. No credential references are needed for this setup.

Ask before elevation, system-wide packages, services or startup items, ports or firewall rules, sign-in, large downloads, overwrites, or migrations.  Do not enable startup items, background services, overlays, notifications, analytics, or device permissions unless they are requested and separately approved. Do not print the RustDesk ID, set or reveal a permanent password, import a deployment configuration, switch to a public or self-hosted relay, install the unattended service, accept a connection, transfer files, tunnel ports, or grant remote-control permissions without explicit approval. For a large game or media download, report the exact size, destination drive, free space, and bandwidth impact, then wait for approval. Never delete game libraries, save files, media libraries, mods, profiles, or cloud-sync data. If the platform or configuration is unsupported, stop and offer the closest official alternative.

Verify the release signature or checksum where published and report the RustDesk version without exposing its device ID. Inspect configuration and service paths, then avoid a networked first launch unless approved; confirm no relay registration, permanent password, remote session, or new service occurred. Report the version, executable, configuration and data paths, changed files, active processes or listeners, and verification evidence without exposing sensitive values. End with manual steps and exact rollback or uninstall instructions that remove only setup-owned changes, restore backups, stop new services, and preserve user data.
