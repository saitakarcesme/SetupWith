# Tangram setup prompt

Set up Tangram from its official project and verified Flathub listing (https://apps.gnome.org/Tangram/). Inventory Linux architecture, Flatpak scopes, existing package and data paths, persistent-tab and distinct-origin counts, aggregate cookie/storage/cache/service-worker bytes, download and partial-file counts, per-origin permission classes, notification policy, background behavior and session-reference presence without revealing URLs, hostnames, tab titles, account identities, cookies, tokens, messages, downloads, browsing content or secrets. Install stable `re.sonny.Tangram` from verified Flathub in the existing ownership scope. Do not compile from source, launch Tangram, restore tabs, navigate, resolve a hostname, load remote content, authenticate, read site data, register a service worker, request a web permission, download a file, open a URI handler, or emit notifications during setup.

Preserve every tab's stable identity, exact origin, title, order, account purpose, cookies, local storage, IndexedDB, caches, service workers, navigation state, permissions, downloads, notifications, remotes, overrides and scope ownership. Multiple tabs for the same service are safe only if their storage containers are actually independent; friendly titles and favicons do not establish identity. Redact origins and session data. Never merge profiles, share cookies, silently restore a sensitive tab, clear site data, log out all accounts or infer that application sandboxing prevents every cross-site or identity-provider interaction.

Before adding or restoring a web app, require the exact HTTPS origin, Unicode and punycode hostname, redirect and login origins, service owner, certificate policy, third-party identity-provider boundary and intended account. Test container isolation only with disposable synthetic accounts. Review per-origin camera, microphone, location, clipboard, notification, autoplay, screen-capture, file chooser, download and popup policy. Treat pages, frames, scripts, previews and URI handlers as untrusted. Block mixed content and unexpected navigation; preview the final external host before browser handoff. Downloads require MIME and filename validation, a destination and collision policy, byte cap and no automatic opening.

Set explicit notification previews, lock-screen visibility, sounds, per-tab muting, background execution and resource limits. Verify provenance, app ID, origin, commit, WebKit runtime, executable, files and static sandbox permissions offline. Prove no DNS request, navigation, tab restore, cookie or storage read, service-worker activity, authentication, permission prompt, download, URI activation, background request, notification or state mutation occurred. On failure, rollback only the new Tangram ref in its original scope; preserve shared runtimes, remotes, overrides, tabs, containers, sessions, site data, permissions, downloads and backups.
