# Flowise setup prompt

Codex, inspect the OS, architecture, shell, Node.js and container tooling, existing Flowise installation, storage directory, database, credentials store, and occupied ports before proceeding. Prefer the official Flowise Docker image with persistent storage; alternatively use the official npm package `flowise` in a dedicated user-managed Node environment. Ask before administrator access, installing Node or Docker, starting a service, binding port 3000, modifying firewall rules, opening a browser, or replacing existing data and configuration. Preserve flows, credentials, SQLite or external database files, uploads, logs, and environment files. Configure only `server_port`, `storage_path`, and `log_level` when supplied. Reference `secret://provider/FLOWISE_USERNAME`, `secret://provider/FLOWISE_PASSWORD`, and `secret://provider/OPENAI_API_KEY` only through secure environment injection or the application’s protected credential store; never print, echo, log, or commit values. Bind to localhost by default and require authentication before external exposure. Verify the installed package or image, persistent mount, database access, HTTP health, authentication behavior, and creation of a disposable flow that uses no external paid API. Rollback stops and removes only created services or environments, restores configuration, and retains flows and credentials data unless deletion is approved. End with a structured summary of runtime, storage, authentication, port, verification, approvals, and rollback.
