# Cloudflare WARP setup prompt

Set up Cloudflare WARP from its verified official source (https://one.one.one.one/). Supported targets: macOS, Linux, Windows. Begin with a read-only preflight covering the operating system, architecture, shell, package managers, disk space, relevant runtimes or hardware, and any existing installation. Use Cloudflare's documented signed client or repository, identify whether the requested mode is DNS-only, consumer WARP, or Zero Trust enrollment, and explain the tunnel service, network extension, routes, and DNS changes before elevation.

Preserve current DNS servers, search domains, proxy configuration, VPN profiles, routing table, split-tunnel rules, Zero Trust registration, device certificate, firewall policy, and the state of competing network clients. Back up files before editing and explain the selected version, source, location, dependencies, and commands. Apply only supplied, supported preferences: warp_mode, tunnel_protocol, split_tunnels, dns_families. No credential references are needed for this setup.

Ask before elevation, system-wide packages, services or startup items, ports or firewall rules, sign-in, large downloads, overwrites, or migrations.  Treat drivers, kernel components, anti-cheat, background services, overlays, firewall changes, startup items, and restarts as separate approval checkpoints. Explain the exact component, vendor, privileges, persistence, and rollback before continuing. Do not accept an organization enrollment, install a device certificate, switch DNS, connect WARP, enable always-on mode, replace routes, or remove another VPN without approval; retain an offline command that restores original networking. For a large game or media download, report the exact size, destination drive, free space, and bandwidth impact, then wait for approval. Never delete game libraries, save files, media libraries, mods, profiles, or cloud-sync data. If the platform or configuration is unsupported, stop and offer the closest official alternative.

For an approved test, record baseline DNS and routes, verify the WARP client and daemon versions, connection mode, resolver, IPv4 and IPv6 behavior, then disconnect and confirm every baseline DNS, route, and proxy value is restored. Report the version, executable, configuration and data paths, changed files, active processes or listeners, and verification evidence without exposing sensitive values. End with manual steps and exact rollback or uninstall instructions that remove only setup-owned changes, restore backups, stop new services, and preserve user data.
