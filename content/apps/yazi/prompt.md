# Yazi setup prompt

Set up Yazi from its official installation guide (https://yazi-rs.github.io/docs/installation/). Detect Windows, macOS, or Linux, architecture, terminal graphics protocol, package managers, existing `yazi` and `ya` binaries, configuration directory, `YAZI_CONFIG_HOME`, keymaps, openers, previewers, plugins, flavors, shell wrapper, `file(1)`, and optional tools such as ffmpeg, 7-Zip, jq, Poppler, fd, ripgrep, fzf, zoxide, resvg, ImageMagick and clipboard helpers. Install the latest stable packaged or checksummed official binaries. Do not select nightly, `--HEAD`, edge channels, classic Snap confinement, unofficial repositories, or optional dependencies without an explicit feature-by-feature choice.

Install only Yazi and its required file-type detector. Do not launch it in the home directory, write `yazi.toml`, `keymap.toml`, `theme.toml` or `init.lua`, install plugins or flavors, generate shell integration, or alter terminal settings. Preserve every file and directory, selections and yank state, trash, metadata, permissions, links, mounts, network shares, configuration, keymaps, openers, preview cache, plugin data, shell profiles, clipboard and current working directory. Never use a real directory to demonstrate navigation or file operations.

Yazi can copy, cut, overwrite, rename, trash and permanently delete selections; create symbolic and hard links; extract archives; run `;` and `:` shell commands; and invoke configured openers, previewers and preloaders. Treat all opener strings, keymap actions, `init.lua`, Lua plugins and downloaded flavors as executable code. Before enabling any of them, show source revision, resolved command, arguments, selected paths, destination, overwrite behavior, environment and subprocess privileges. Do not preview sensitive documents because external thumbnailers may parse untrusted content and caches can retain it. Never traverse private mounts, follow surprising symlinks, execute files, modify trash, send paths to clipboard, or allow a background task to outlive verification.

The suggested `y` shell wrapper writes a temporary cwd file and changes the parent shell directory on exit; do not install it automatically or use it for validation. Verify package provenance or checksum, `yazi --version`, `ya --version`, resolved binaries, method, PATH and required `file` executable without opening the TUI. Confirm no file operation, task, opener, preview, plugin, cache, clipboard write, shell-profile edit, terminal-mode change or working-directory change occurred. Roll back only setup-owned binaries, packages and PATH entries, retaining all pre-existing Yazi configuration and filesystem state.
