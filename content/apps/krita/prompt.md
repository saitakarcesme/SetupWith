# Krita setup prompt

Codex, begin by detecting the OS, architecture, shell, GPU environment, existing Krita installation, resource folders, workspaces, color profiles, brushes, plugins, and file associations. Use Krita’s official signed application or package for supported macOS, Linux, and Windows systems; prefer the distribution package or official Flatpak on Linux and a supported `winget` package on Windows. Ask before administrator access, replacing an application, changing file associations, installing Flatpak, importing resource bundles, or overwriting settings. Preserve brushes, palettes, templates, workspaces, shortcuts, autosaves, and custom color profiles. Configure only `workspace`, `resource_directory`, `color_profile`, and `canvas_only_mode` when supplied. Validate the requested color profile and resource directory before registering them, and do not move existing resources automatically. Verify application launch, `krita --version` where available, workspace selection, resource discovery, color-profile loading, and creation plus export of a disposable blank document through command-line or GUI-safe automation. Never modify user artwork for testing. Rollback restores backed-up settings, removes only resources or paths added here, and uninstalls only the package installed during this run. Finish with a structured summary of installation source, workspace, resources, color management, canvas mode, verification, approvals, and rollback.
