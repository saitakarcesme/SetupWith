# Ollama setup prompt

Codex, first inspect the operating system, CPU architecture, active shell, available RAM, GPU vendor, existing `ollama` binary, model store, and any running Ollama process or service. Use only supported platforms. On macOS or Windows prefer Ollama’s official signed application installer; on Linux use the official install path or architecture-specific package documented by Ollama. Ask before administrator access, replacing binaries, creating or changing a system service, opening port 11434, altering firewall rules, or downloading large models. Preserve existing models, manifests, logs, and configuration. Configure only `model_names`, `model_storage_path`, `listen_address`, and `gpu_backend` when supplied. Validate storage capacity and GPU compatibility before changing paths or acceleration settings. Bind to localhost by default; require explicit approval for network exposure. Pull only approved model names and show expected download sizes when discoverable. Verify with `ollama --version`, `ollama list`, service health, and a local API check against `/api/tags`; run a brief prompt only with an already installed or approved model. Rollback must restore configuration, stop and remove only services created here, and uninstall without deleting models unless separately approved. Finish with a structured summary covering platform, install method, service state, configured values, models, verification, approvals, and rollback commands.
