# Jan setup prompt

Codex, inspect the operating system, architecture, shell, GPU capabilities, existing Jan application, data directory, downloaded models, local API settings, and occupied ports before installation. Use Jan’s official signed desktop release for supported macOS, Windows, or Linux platforms; prefer the platform-native package format and verify publisher or checksum information when available. Ask before administrator access, replacing an application, adding startup behavior, opening the local API port, changing firewall rules, browser sign-in, or downloading large models. Preserve Jan’s settings, conversations, extensions, model directory, and inference configuration. Configure only `model_directory`, `inference_backend`, and `api_port` when supplied. Reference `secret://provider/OPENAI_API_KEY` only through Jan’s secure credential storage after approval; never print, echo, log, or place its value in plaintext configuration. Keep the API bound to localhost unless remote access is explicitly approved. Select an inference backend only after checking hardware support. Verify application launch, model directory access, backend detection, local API health, and a short local chat using an existing or approved model. Rollback should restore settings, remove only the installed application and API startup changes, and retain conversations and models unless deletion is approved. Finish with a structured summary of package source, backend, data paths, API state, verification, approvals, and rollback.
