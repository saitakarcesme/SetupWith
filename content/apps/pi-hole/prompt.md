# Pi-hole setup prompt

Set up Pi-hole from its verified official source (https://github.com/pi-hole/pi-hole). Supported targets: Linux. Begin with a read-only preflight covering the operating system, architecture, shell, package managers, disk space, relevant runtimes or hardware, and any existing installation. Choose a supported Linux host or an official container deployment, inspect Pi-hole's installer before execution, and map persistent DNS and configuration data explicitly.

Preserve Pi-hole configuration, gravity database, custom DNS records, allow and block lists, DHCP leases, web credentials, backups, and container volumes. Back up files before editing and explain the selected version, source, location, dependencies, and commands. Apply only supplied, supported preferences: deployment_mode, dns_upstream, listen_address, web_port, data_directory. The only available credential references are secret://pihole/webpassword. Treat every reference as opaque: never print, echo, log, resolve, or paste its value.

Ask before elevation, system-wide packages, services or startup items, ports or firewall rules, sign-in, large downloads, overwrites, or migrations.  Do not enable startup items, background services, overlays, notifications, analytics, or device permissions unless they are requested and separately approved. Do not replace system or router DNS, enable DHCP, bind ports 53 or 80, modify firewall rules, update gravity, or expose the dashboard without approval. For a large game or media download, report the exact size, destination drive, free space, and bandwidth impact, then wait for approval. Never delete game libraries, save files, media libraries, mods, profiles, or cloud-sync data. If the platform or configuration is unsupported, stop and offer the closest official alternative.

Use configuration and version checks first; only after port approval start loopback-safe services, query a known harmless domain through the local resolver, and stop test containers. Report the version, executable, configuration and data paths, changed files, active processes or listeners, and verification evidence without exposing sensitive values. End with manual steps and exact rollback or uninstall instructions that remove only setup-owned changes, restore backups, stop new services, and preserve user data.
