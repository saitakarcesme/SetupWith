# Cloudflare Wrangler setup prompt

Set up Cloudflare Wrangler from its verified official source (https://developers.cloudflare.com/workers/wrangler/install-and-update/). Supported targets: macOS, Linux, Windows. Begin with a read-only preflight covering the operating system, architecture, shell, package managers, disk space, relevant runtimes or hardware, and any existing installation. Follow Cloudflare's recommendation to add the latest Wrangler as a project-local development dependency, and review the repository package manager and lockfile before changing either.

Preserve Preserve the project's Wrangler version, lockfile, `wrangler` configuration, environment sections, local state, secrets, compatibility date, generated types, and existing deployment metadata.. Back up files before editing and explain the selected version, source, location, dependencies, and commands. Apply only supplied, supported preferences: project_local_version, environment_name, compatibility_date, telemetry. The only available credential references are secret://cloudflare/api-token. Treat every reference as opaque: never print, echo, log, resolve, or paste its value.

Ask before elevation, system-wide packages, services or startup items, ports or firewall rules, sign-in, large downloads, overwrites, or migrations.  Do not enable startup items, background services, overlays, notifications, analytics, or device permissions unless they are requested and separately approved. Do not run login, initialize a Worker, modify package files, create `.dev.vars`, upload secrets, open ports, deploy, delete resources, or change compatibility settings without approval. For a large game or media download, report the exact size, destination drive, free space, and bandwidth impact, then wait for approval. Never delete game libraries, save files, media libraries, mods, profiles, or cloud-sync data. If the platform or configuration is unsupported, stop and offer the closest official alternative.

Run the pinned `wrangler --version` from the intended project or a disposable directory, inspect configuration read-only, and confirm no login, local server, file mutation, or deployment occurred. Report the version, executable, configuration and data paths, changed files, active processes or listeners, and verification evidence without exposing sensitive values. End with manual steps and exact rollback or uninstall instructions that remove only setup-owned changes, restore backups, stop new services, and preserve user data.
