# Terraform setup prompt

Codex, first inspect the OS, architecture, shell, existing Terraform binaries, package source, CLI configuration, plugin cache, credentials files, workspaces, and any current infrastructure directory. Prefer HashiCorp’s official signed repository on supported Linux distributions, Homebrew `hashicorp/tap/terraform` on macOS, and `winget install Hashicorp.Terraform` on Windows. Ask before administrator access, adding repositories, replacing another Terraform binary, running `init`, changing workspaces, downloading providers, authenticating to backends, or executing `apply` or `destroy`. Preserve `.terraformrc`, `terraform.rc`, credentials, lockfiles, state files, backend configuration, and `.terraform` directories. Configure only `plugin_cache_dir`, `default_workspace`, and `parallelism` when supplied. Use `secret://provider/TF_TOKEN_app_terraform_io`, `secret://provider/AWS_ACCESS_KEY_ID`, and `secret://provider/AWS_SECRET_ACCESS_KEY` only through secure environment or credential helpers; never print, log, or commit them. Verify `terraform version`, CLI config parsing, and `terraform fmt -check` plus `terraform validate` on a disposable local configuration without remote providers. Rollback restores CLI config, removes only the installed binary, and never alters state or infrastructure. Finish with a structured summary of binary source, workspace preference, cache, credentials aliases, checks, approvals, and rollback.
