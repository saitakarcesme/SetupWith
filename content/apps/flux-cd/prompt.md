# Flux CD setup prompt

Set up Flux CD from its verified official source (https://github.com/fluxcd/flux2). Supported targets: macOS, Linux, Windows. Begin with a read-only preflight covering the operating system, architecture, shell, package managers, disk space, relevant runtimes or hardware, and any existing installation. Install the signed Flux CLI from the official release channel and keep CLI installation separate from bootstrapping controllers into any Kubernetes cluster.

Preserve kubeconfig files, current contexts, cluster resources, Git repositories and deploy keys, Flux sources, and reconciliation state. Back up files before editing and explain the selected version, source, location, dependencies, and commands. Apply only supplied, supported preferences: kube_context, git_repository, git_branch, cluster_namespace. The only available credential references are secret://github/token, secret://kubeconfig/credential. Treat every reference as opaque: never print, echo, log, resolve, or paste its value.

Ask before elevation, system-wide packages, services or startup items, ports or firewall rules, sign-in, large downloads, overwrites, or migrations.  Do not enable startup items, background services, overlays, notifications, analytics, or device permissions unless they are requested and separately approved. Do not switch contexts, run preflight checks against a cluster, bootstrap Flux, create deploy keys, reconcile resources, or commit changes without approval. For a large game or media download, report the exact size, destination drive, free space, and bandwidth impact, then wait for approval. Never delete game libraries, save files, media libraries, mods, profiles, or cloud-sync data. If the platform or configuration is unsupported, stop and offer the closest official alternative.

Run `flux --version`; perform no cluster call by default, and show the selected kube context only after confirming it is safe to inspect. Report the version, executable, configuration and data paths, changed files, active processes or listeners, and verification evidence without exposing sensitive values. End with manual steps and exact rollback or uninstall instructions that remove only setup-owned changes, restore backups, stop new services, and preserve user data.
