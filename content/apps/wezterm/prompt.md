# WezTerm setup prompt

Set up WezTerm from its verified official source (https://github.com/wezterm/wezterm). Supported targets: macOS, Linux, Windows. Begin with a read-only preflight covering the operating system, architecture, shell, package managers, disk space, relevant runtimes or hardware, and any existing installation. Use the official signed package or release for the current platform and architecture, keeping preview builds and shell-integration changes opt-in.

Preserve `.wezterm.lua`, XDG WezTerm configuration, state directories, SSH domains, mux sessions, and existing terminal defaults. Back up files before editing and explain the selected version, source, location, dependencies, and commands. Apply only supplied, supported preferences: preferred_shell, terminal_font, terminal_theme, config_directory. No credential references are needed for this setup.

Ask before elevation, system-wide packages, services or startup items, ports or firewall rules, sign-in, large downloads, overwrites, or migrations.  Do not enable startup items, background services, overlays, notifications, analytics, or device permissions unless they are requested and separately approved. Do not execute existing Lua configuration, connect to SSH domains, enable a mux server, or make WezTerm the default terminal without approval. For a large game or media download, report the exact size, destination drive, free space, and bandwidth impact, then wait for approval. Never delete game libraries, save files, media libraries, mods, profiles, or cloud-sync data. If the platform or configuration is unsupported, stop and offer the closest official alternative.

Run `wezterm --version` and `wezterm show-keys --lua` only if safe, then launch one local tab with the selected shell and no remote domains. Report the version, executable, configuration and data paths, changed files, active processes or listeners, and verification evidence without exposing sensitive values. End with manual steps and exact rollback or uninstall instructions that remove only setup-owned changes, restore backups, stop new services, and preserve user data.
