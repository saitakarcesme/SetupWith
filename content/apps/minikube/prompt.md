# Minikube setup prompt

Codex, begin by detecting the OS, architecture, shell, existing `minikube` and `kubectl`, virtualization or container drivers, current profiles, allocated resources, and occupied ports. Install through Homebrew on macOS, the official binary or supported package on Linux, and `winget install Kubernetes.minikube` on Windows. Ask before administrator access, installing hypervisors or container engines, creating or deleting profiles, changing firewall rules, enabling privileged drivers, or modifying kubeconfig. Preserve all existing minikube profiles, cached images, addons, certificates, and contexts. Configure only `profile_name`, `driver`, `container_runtime`, and `cluster_resources` when supplied. Select a driver only after verifying it is installed and supported; do not silently enable Hyper-V, Docker Desktop, KVM, or privileged networking. Present resource allocation before starting the cluster. Verify `minikube version`, driver status, profile creation, `minikube status`, node readiness, and system pods through `kubectl`. Enable no addons unless separately approved. Rollback stops and deletes only the profile created here, restores kubeconfig, and removes only the minikube package while leaving shared caches unless deletion is approved. End with a structured summary of driver, runtime, resources, profile, checks, approvals, and rollback.
