# CrowdSec setup prompt

Set up CrowdSec from its verified official source (https://github.com/crowdsecurity/crowdsec). Supported targets: Linux. Begin with a read-only preflight covering the operating system, architecture, shell, package managers, disk space, relevant runtimes or hardware, and any existing installation. Use CrowdSec's official Linux package or container after identifying supported log sources, and keep the detection engine, Local API, console enrollment, and remediation bouncers as separate approvals.

Preserve CrowdSec configuration, decisions, hub collections, parser state, Local API credentials, machine identities, log acquisition rules, and databases. Back up files before editing and explain the selected version, source, location, dependencies, and commands. Apply only supplied, supported preferences: config_directory, data_directory, log_sources, listen_address, api_port. The only available credential references are secret://crowdsec/bouncer-api-key. Treat every reference as opaque: never print, echo, log, resolve, or paste its value.

Ask before elevation, system-wide packages, services or startup items, ports or firewall rules, sign-in, large downloads, overwrites, or migrations.  Do not enable startup items, background services, overlays, notifications, analytics, or device permissions unless they are requested and separately approved. Do not read sensitive logs, enroll the console, install bouncers, block traffic, expose the API, or enable services without approval. For a large game or media download, report the exact size, destination drive, free space, and bandwidth impact, then wait for approval. Never delete game libraries, save files, media libraries, mods, profiles, or cloud-sync data. If the platform or configuration is unsupported, stop and offer the closest official alternative.

Run version and configuration checks, inspect no user logs by default, and use a bundled harmless test scenario only if its temporary inputs and effects are approved. Report the version, executable, configuration and data paths, changed files, active processes or listeners, and verification evidence without exposing sensitive values. End with manual steps and exact rollback or uninstall instructions that remove only setup-owned changes, restore backups, stop new services, and preserve user data.
