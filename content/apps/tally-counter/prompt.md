# Tally setup prompt

Set up Tally from its official project and verified Flathub listing (https://apps.gnome.org/Tally/). Inventory Linux architecture, Flatpak scopes, existing package and data paths, counter and category counts, aggregate local-state bytes, backup age and sandbox permissions without revealing counter names, values, colors, ordering, categories, health details, habit history or inferred routines. Install stable `ca.vlacroix.Tally` from verified Flathub in the existing ownership scope. Do not compile from source, launch Tally, open its data store, increment or decrement a counter, reorder items, create or rename a counter, reset values, delete data, access portals, or emit notifications during setup.

Preserve every counter identity, label, value, color, category and order, plus local settings, permissions, backups, remotes, overrides and scope ownership. Counter labels and values may describe medication, symptoms, sobriety, prayer, spending, incidents or other sensitive behavior; redact them from diagnostics and screen captures. A count without its increment meaning, unit and correction rule can be misleading. Installation must not normalize negative values, merge duplicate labels, repair ordering, reset a counter or assume that zero means missing data.

Before later use, define for each counter the event being counted, increment size, whether decrement is allowed, range and overflow behavior, correction procedure and reset authority. Validate rapid repeated activation and crash persistence only with disposable synthetic counters, never the user's real collection. Preview reorder and category changes by stable identifier rather than label. Treat reset and deletion as destructive: distinguish one counter from the entire collection, show affected item counts, require explicit confirmation and establish a restorable local backup before proceeding.

Verify provenance, app ID, origin, commit, runtime, executable, files and static sandbox permissions offline. Confirm the no-permission posture and flag any unexpected network, filesystem, clipboard or portal capability without exercising it. Prove no data store was opened, label or value read, count changed, item reordered, counter created, reset or deleted, backup rotated, portal contacted or notification shown. On failure, rollback only the new Tally ref in its original scope; preserve shared runtimes, remotes, overrides, counters, categories, ordering, settings and backups.
