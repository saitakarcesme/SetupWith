# Yaak setup prompt

Set up Yaak from its official installation guide and mountain-loop repository (https://yaak.app/docs/getting-started/installation). Detect Windows, macOS, or Linux, architecture, package managers, an existing Yaak installation, application database, OS keychain entries, workspace directories, sync folders, Git repositories, plugins, certificates, and proxy settings without reading sensitive values. Prefer the stable signed DMG, Homebrew cask, user-level Windows installer, Winget package, AppImage, DEB, or RPM for the detected platform. Do not install a beta or all-users machine build without explicit approval.

Launch in offline mode without importing or sending requests. Preserve every workspace, folder, request, environment, cookie jar, response history, OAuth session, client certificate, proxy credential, plugin, database, keychain master key, workspace encryption key, recovery backup, sync directory, Git branch and change, export, and UI preference. Apply only the requested sync mode, active environment, secret encryption, or proxy. Never migrate automatically from Postman, Insomnia, Bruno, OpenAPI, Swagger, cURL, or clipboard content.

Before transmitting anything, show protocol, method, fully resolved host, port, path, active environment color/name, headers with values redacted, body size, proxy route, client certificate, authentication type, redirects, and whether response chaining triggers additional requests. Require separate approval for development, staging, and especially production targets. Do not inspect the clipboard, follow redirects across hosts, run OAuth in a browser, send cookies, enable NTLM, load private files, or connect WebSocket/gRPC/SSE streams automatically. Plugins execute with full Node.js access, so never install or run unreviewed plugin code.

When enabling encryption, explain the OS-keychain master key, encrypted workspace key, and the need to back up the workspace recovery key without printing it. Keep environments out of directory sync by default; never mark one sharable, export decrypted secrets, initialize Git, commit, push, or overwrite a sync directory without approval. Verify signature, version, executable, database and keychain locations, listeners and outbound connections. Create at most an empty disposable workspace offline, then remove only that workspace. Confirm no request, import, OAuth flow, plugin, sync, Git operation, export, key, cookie, history entry, or existing workspace changed. Roll back only setup-owned files while preserving the database and keychain.
