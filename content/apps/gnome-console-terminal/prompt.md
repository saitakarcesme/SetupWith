# Console setup prompt

Set up Console from its official GNOME project and verified Flathub listing (https://apps.gnome.org/Console/). Inventory Linux architecture, Flatpak scopes, existing package and data paths, configured shell path and checksum, tab count, aggregate running-job and remote-session counts, elevated-shell presence, working-directory reachability, terminal-state byte count, clipboard and hyperlink policy, sandbox overrides and backup coverage without reading commands, output, history, directory names, process arguments, hostnames, usernames, environment values, tokens or credentials. Install stable `org.gnome.Console` from verified Flathub in the existing ownership scope. Do not compile from source, launch Console, allocate a PTY, start a shell, source startup files, restore tabs, send a signal, inspect an environment, read history, access the clipboard, follow a hyperlink, open a file or execute any command during setup.

Preserve all existing tab identities, titles, current directories, foreground jobs, process groups, scrollback, window state, font and accessibility choices, remotes, overrides and scope ownership. A terminal is an arbitrary-code execution boundary, not a passive text viewer. Never interrupt or reparent a running job, close a remote or elevated session, replay a command, import the ambient agent environment or expose terminal text in diagnostics. Installation must not make Console the default terminal or URI handler without explicit review.

Before later launch, pin the intended shell executable and ownership, startup-file behavior, interactive flags, initial directory, locale and a minimal environment allowlist. Exclude secrets and automation credentials. Define PTY, signal, child-process-group, hangup and close-confirmation behavior; a tab may close only after the exact process state is shown. Treat OSC title, hyperlink, clipboard and notification sequences as untrusted output. Require confirmation before opening a final URI or file target and before pasting multiline or control-bearing text. Validate command execution only in a disposable, network-denied test account with inert output and no host mounts.

Review filesystem, network, D-Bus and portal access against terminal requirements, acknowledging that sandboxing the emulator does not constrain every command run with granted access. Verify provenance, app ID, origin, commit, runtime, executable, files and static permissions offline. Prove no PTY, shell, startup file, subprocess, signal, history or environment read, clipboard operation, URI activation, filesystem mutation, network request or notification occurred. On failure, rollback only the new Console ref in its original scope; preserve shared runtimes, remotes, overrides, tabs, processes, scrollback, preferences and backups.
