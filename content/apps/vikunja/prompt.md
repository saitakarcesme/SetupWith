# Vikunja setup prompt

Codex, inspect the OS, architecture, shell, existing Vikunja installation, container runtime, database, files storage, configuration, users, mail settings, and occupied ports before making changes. Prefer Vikunja’s official Docker Compose deployment with persistent volumes; use the official Linux binary only when a native service is specifically preferred. Ask before administrator access, installing container tooling, creating or restarting services, running database migrations, exposing ports, changing firewall rules, opening a browser, or replacing configuration. Preserve tasks, projects, attachments, users, database records, and configuration files. Configure only `server_port`, `database_type`, `public_url`, and `files_path` when supplied. Inject `secret://provider/VIKUNJA_SERVICE_JWTSECRET` and `secret://provider/VIKUNJA_DATABASE_PASSWORD` through protected secrets or environment handling; never print, echo, log, or commit values. Keep registration and external access unchanged unless separately approved. Verify image or binary identity, database connectivity, migration completion, file-storage permissions, HTTP health, and creation plus deletion of a disposable local task and project. Rollback restores configuration, stops and removes only newly created services, and retains databases and files unless deletion is authorized. Finish with a structured summary of deployment, database, files path, URL, port, checks, approvals, and rollback.
