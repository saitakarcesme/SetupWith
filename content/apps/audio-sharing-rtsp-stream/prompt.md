# Audio Sharing setup prompt

Set up Audio Sharing from its official GNOME project and verified Flathub listing (https://apps.gnome.org/AudioSharing/). Inventory Linux architecture, Flatpak scopes, existing package and data paths, audio-server type, candidate playback-monitor count, microphone-node exclusion, configured bind-interface class, port-policy presence, firewall zone, RTSP-client count, background-state presence, sandbox overrides and backup coverage without sampling audio or revealing device names, LAN addresses, stream URLs, QR codes, listening activity, application titles, callers, notifications or captured content. Install stable `de.haeckerfelix.AudioSharing` from verified Flathub in the existing ownership scope. Do not compile from source, launch Audio Sharing, connect to PipeWire, select or monitor a node, capture a sample, bind a socket, open a firewall port, advertise a service, generate or display a QR code, accept a receiver, stream packets, play audio or inhibit sleep during setup.

Preserve all existing audio routing, default devices, volumes, monitor-node state, stream preferences, firewall rules, network bindings, remotes, overrides and scope ownership. Current playback can contain private calls, notifications, assistive output or copyrighted material; capture requires explicit owner and bystander consent. Installation must not select a microphone accidentally, reroute an output, expose a listener on every interface, reuse a previously public stream address or start in the background.

Before later streaming, identify the exact playback-monitor node and prove microphone inputs are excluded. Define IPv4 and IPv6 bind addresses, port, firewall zone, LAN, VPN, hotspot and container reachability. RTSP without reviewed encryption or authentication must be treated as readable by anyone who can reach it; path obscurity and a QR code are not access control. Display the exact exposure boundary and require an intended receiver. Keep stream URLs, addresses and QR codes out of logs and screen sharing. Use a synthetic tone on an isolated test network for validation, never user playback.

Pin codec, sample rate, channel layout and bitrate, then bound latency, buffer, client count, CPU and bandwidth. Provide persistent visible streaming state and explicit stop. Verify provenance, app ID, origin, commit, runtime, executable, files and static permissions offline. Prove no audio-server connection, node access, capture, socket bind, firewall change, advertisement, QR display, client session, packet transmission, playback or sleep inhibition occurred. On failure, rollback only the new Audio Sharing ref in its original scope; preserve shared runtimes, remotes, overrides, routing, devices, volumes, firewall state and backups.
