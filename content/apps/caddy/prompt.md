# Caddy setup prompt

Codex, inspect the OS, architecture, shell, existing `caddy` binary, package source, Caddyfile, JSON configuration, certificates, service state, listeners, and ports 80 and 443 before installation. Prefer Caddy’s official signed repository on supported Linux distributions, Homebrew `caddy` on macOS, and the official Windows package or `winget` entry. Ask before administrator access, binding privileged ports, creating or restarting services, changing firewall rules, obtaining public certificates, modifying DNS, replacing reverse-proxy routes, or overwriting configuration. Preserve the Caddyfile, autosave JSON, certificate storage, logs, and service definitions. Configure only `domain_name`, `http_port`, `https_port`, and `config_path` when supplied. Use `secret://provider/CLOUDFLARE_API_TOKEN` solely through a protected environment or service credential mechanism for an approved DNS challenge; never print, echo, log, or commit it. Default to localhost and a non-privileged test port until public exposure is approved. Verify `caddy version`, `caddy validate`, `caddy adapt`, a temporary local file-server response, and service health where enabled. Rollback restores configuration and prior service state, removes only created service files or packages, and preserves certificates. Finish with a structured summary of install source, domains, ports, TLS approach, config path, verification, approvals, and rollback.
