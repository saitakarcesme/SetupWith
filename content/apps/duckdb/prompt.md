# DuckDB setup prompt

Codex, inspect the operating system, architecture, shell, existing DuckDB CLI, package ownership, target database path, extensions, and filesystem permissions before installing or opening anything. On macOS prefer Homebrew `duckdb`; on Linux use the official CLI release artifact or a trusted distribution package when available; on Windows use the official DuckDB CLI archive or supported `winget` package. Ask before administrator access, changing PATH, replacing binaries, loading unsigned extensions, opening an existing database, or overwriting files. Preserve the database file and any related temporary or WAL files. Configure only `database_path`, `extension_directory`, `memory_limit`, and `threads` when supplied. Validate that the target path is writable and create a timestamped copy before applying persistent settings or schema changes. Do not automatically install networked extensions. Verify with `duckdb --version`, `PRAGMA version`, `PRAGMA database_size`, and a disposable database that imports a tiny CSV, runs an aggregate query, and exits cleanly. For an approved existing database, run non-destructive integrity-oriented reads and confirm configured memory and thread settings. Rollback restores the database backup and previous settings, removes added extension files, and uninstalls only the CLI installed during this run. Finish with a structured summary of binary source, database path, configured resources, extensions, verification results, approvals, and rollback commands.
