# Strapi setup prompt

Set up Strapi from its verified official source (https://github.com/strapi/strapi). Supported targets: macOS, Linux, Windows. Begin with a read-only preflight covering the operating system, architecture, shell, package managers, disk space, relevant runtimes or hardware, and any existing installation. Use Strapi's official project creator with a supported Node.js version and approved package manager, choosing a fresh directory and database strategy before installing dependencies.

Preserve existing projects, source code, schemas, uploaded media, environment files, application keys, databases, lockfiles, and generated builds. Back up files before editing and explain the selected version, source, location, dependencies, and commands. Apply only supplied, supported preferences: node_version, package_manager, project_directory, database_name, listen_port. The only available credential references are secret://strapi/app-keys, secret://strapi/database-password. Treat every reference as opaque: never print, echo, log, resolve, or paste its value.

Ask before elevation, system-wide packages, services or startup items, ports or firewall rules, sign-in, large downloads, overwrites, or migrations.  Do not enable startup items, background services, overlays, notifications, analytics, or device permissions unless they are requested and separately approved. Do not scaffold into a nonempty directory, initialize or migrate a database, generate production secrets, create an admin, expose ports, or install marketplace plug-ins without approval. For a large game or media download, report the exact size, destination drive, free space, and bandwidth impact, then wait for approval. Never delete game libraries, save files, media libraries, mods, profiles, or cloud-sync data. If the platform or configuration is unsupported, stop and offer the closest official alternative.

Run project and dependency checks; start only a fresh project on loopback, confirm the admin welcome route, and stop before account creation or content changes. Report the version, executable, configuration and data paths, changed files, active processes or listeners, and verification evidence without exposing sensitive values. End with manual steps and exact rollback or uninstall instructions that remove only setup-owned changes, restore backups, stop new services, and preserve user data.
