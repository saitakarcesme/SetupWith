# SQLite setup prompt

Codex, inspect the OS, architecture, shell, existing `sqlite3` binary, package ownership, linked SQLite library, target database files, and filesystem permissions before installation. On macOS prefer the system client when sufficient or Homebrew `sqlite` when a separate current CLI is requested; on Debian/Ubuntu use `apt install sqlite3`; on Fedora-family systems use `dnf install sqlite`; on Windows prefer the official SQLite tools archive or a trusted `winget` package. Ask before administrator access, changing PATH precedence, replacing binaries, opening or modifying an existing database, or overwriting files. Preserve every database and its `-wal`, `-shm`, and journal companions. Configure only `database_path`, `journal_mode`, and `synchronous_mode` when supplied. Validate requested pragmas and apply them only to the explicitly approved database after creating a consistent backup with `.backup` or the backup API. Never treat file deletion as initialization. Verify with `sqlite3 --version`, `PRAGMA integrity_check`, current journal and synchronous modes, and a disposable database that exercises a transaction, index, and rollback. Rollback restores the database backup and previous pragmas, removes only the installed CLI package, and leaves user data untouched. Finish with a structured summary of binary source, database path, backup, pragmas, integrity results, approvals, and rollback commands.
