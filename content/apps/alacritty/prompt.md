# Alacritty setup prompt

Set up Alacritty from its verified official source (https://github.com/alacritty/alacritty). Supported targets: macOS, Linux, Windows. Begin with a read-only preflight covering the operating system, architecture, shell, package managers, disk space, relevant runtimes or hardware, and any existing installation. Install the official stable binary or a trusted native package that matches the graphics stack and architecture; do not build from source unless requested.

Preserve Alacritty TOML or YAML configuration, themes, shell integration, desktop entries, and any previous executable. Back up files before editing and explain the selected version, source, location, dependencies, and commands. Apply only supplied, supported preferences: preferred_shell, terminal_font, terminal_theme, config_directory. No credential references are needed for this setup.

Ask before elevation, system-wide packages, services or startup items, ports or firewall rules, sign-in, large downloads, overwrites, or migrations.  Do not enable startup items, background services, overlays, notifications, analytics, or device permissions unless they are requested and separately approved. Do not migrate legacy configuration, change the login shell, or make Alacritty the default terminal without approval. For a large game or media download, report the exact size, destination drive, free space, and bandwidth impact, then wait for approval. Never delete game libraries, save files, media libraries, mods, profiles, or cloud-sync data. If the platform or configuration is unsupported, stop and offer the closest official alternative.

Run `alacritty --version`, check configuration parsing for warnings, and launch one local window using the current shell without executing project startup hooks. Report the version, executable, configuration and data paths, changed files, active processes or listeners, and verification evidence without exposing sensitive values. End with manual steps and exact rollback or uninstall instructions that remove only setup-owned changes, restore backups, stop new services, and preserve user data.
