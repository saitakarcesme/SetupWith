# Distrobox setup prompt

Set up Distrobox from its official project and installation guidance (https://distrobox.it/#installation). Confirm the host is Linux, then detect architecture, distribution, desktop and display protocol, package managers, rootless Podman or Docker availability, configured registries, existing distroboxes, images, containers, volumes, exported applications and binaries, desktop entries, custom homes, and `.distroboxrc`. Install only the packaged Distrobox scripts for the detected distribution; do not install or reconfigure a container engine, registry, subordinate UID/GID mapping, socket, or daemon as an implicit dependency.

Do not create or enter a container during installation. Explain that Distrobox is intentionally tightly integrated: by default it shares the user's home, host filesystem under `/run/host`, display, audio, devices, sockets, groups, and environment. A custom container home prevents dotfile clutter but does not by itself stop the host home from being mounted. Preserve every container, image, volume, home, package, hook, exported wrapper, desktop entry, host configuration, registry credential, and active process. Apply only the approved manager, pinned image digest, custom home, and explicit isolation flags.

Use `distrobox create --dry-run` to preview the exact underlying container command. Stop before pulling an image, creating or cloning a box, sharing additional volumes or devices, adding packages, running pre-init or init hooks, enabling an init system or NVIDIA integration, generating desktop entries, or starting the container. Prefer rootless mode; root inside a rootless box still has the host user's file privileges, while root in a rootful box can be real host root. Never disable the root password, use remote assemble files, enable `distrobox-host-exec`, export sudo wrappers, loosen X11 access persistently, or execute unreviewed container commands.

Verify Distrobox version and package provenance, container-manager client and rootless status, configuration paths, and an unchanged inventory using list and dry-run only. Report proposed image registry, immutable digest, namespace sharing, mounts, environment, hooks, generated entries, and resource impact without pulling or starting anything. Confirm no image, container, volume, wrapper, desktop file, socket, service, firewall rule, group mapping, or host file changed. Roll back only the Distrobox package and setup-owned configuration; never run stop, rm, replace, upgrade, assemble, container prune, or image prune as part of automatic cleanup.
