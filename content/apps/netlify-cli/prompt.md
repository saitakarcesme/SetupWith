# Netlify CLI setup prompt

Set up Netlify CLI from its verified official source (https://docs.netlify.com/api-and-cli-guides/cli-guides/get-started-with-cli/#installation). Supported targets: macOS, Linux, Windows. Begin with a read-only preflight covering the operating system, architecture, shell, package managers, disk space, relevant runtimes or hardware, and any existing installation. Install Netlify CLI using the official Node.js requirements, prefer a project-local dependency when reproducibility matters, and preserve the selected package manager and lockfile.

Preserve Preserve Netlify login data, `.netlify` project links, `netlify.toml`, environment values, functions configuration, local plugin state, package lockfiles, and existing development ports.. Back up files before editing and explain the selected version, source, location, dependencies, and commands. Apply only supplied, supported preferences: project_local_version, site_linking, dev_server_port, telemetry. The only available credential references are secret://netlify/auth-token. Treat every reference as opaque: never print, echo, log, resolve, or paste its value.

Ask before elevation, system-wide packages, services or startup items, ports or firewall rules, sign-in, large downloads, overwrites, or migrations.  Do not enable startup items, background services, overlays, notifications, analytics, or device permissions unless they are requested and separately approved. Do not log in, create or link a site, pull environment variables, start a development server, open a tunnel, modify project files, deploy, or configure domains without approval. For a large game or media download, report the exact size, destination drive, free space, and bandwidth impact, then wait for approval. Never delete game libraries, save files, media libraries, mods, profiles, or cloud-sync data. If the platform or configuration is unsupported, stop and offer the closest official alternative.

Run `netlify --version` and local help outside a project, report the resolved package and Node.js version, and verify no account, site, environment, port, or deployment was accessed. Report the version, executable, configuration and data paths, changed files, active processes or listeners, and verification evidence without exposing sensitive values. End with manual steps and exact rollback or uninstall instructions that remove only setup-owned changes, restore backups, stop new services, and preserve user data.
