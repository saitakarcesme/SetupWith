# Proton VPN setup prompt

Set up Proton VPN from its verified official source (https://protonvpn.com/download). Supported targets: macOS, Linux, Windows. Begin with a read-only preflight covering the operating system, architecture, shell, package managers, disk space, relevant runtimes or hardware, and any existing installation. Download Proton VPN's signed platform client or configure its documented Linux repository, then present the exact WireGuard, OpenVPN, TUN, Network Extension, or Windows network-driver component before requesting administrator approval to install it.

Preserve existing VPN profiles, manually configured DNS resolvers, routes, proxy settings, split-tunnel rules, firewall policy, Network Extensions, and connections managed by another VPN product. Back up files before editing and explain the selected version, source, location, dependencies, and commands. Apply only supplied, supported preferences: vpn_protocol, kill_switch, auto_connect, dns_leak_protection. No credential references are needed for this setup.

Ask before elevation, system-wide packages, services or startup items, ports or firewall rules, sign-in, large downloads, overwrites, or migrations.  Treat drivers, kernel components, anti-cheat, background services, overlays, firewall changes, startup items, and restarts as separate approval checkpoints. Explain the exact component, vendor, privileges, persistence, and rollback before continuing. Do not connect, sign in, replace DNS, enable permanent kill switch, alter routes, remove another VPN, or activate always-on behavior without approval; explain how loss of connectivity will be recovered before changing the network stack. For a large game or media download, report the exact size, destination drive, free space, and bandwidth impact, then wait for approval. Never delete game libraries, save files, media libraries, mods, profiles, or cloud-sync data. If the platform or configuration is unsupported, stop and offer the closest official alternative.

Confirm the signed client and network component versions, inspect DNS and default routes before and after a user-approved test connection, check for IPv4 and IPv6 leaks, then disconnect and prove the original network state is restored. Report the version, executable, configuration and data paths, changed files, active processes or listeners, and verification evidence without exposing sensitive values. End with manual steps and exact rollback or uninstall instructions that remove only setup-owned changes, restore backups, stop new services, and preserve user data.
