# WordPress setup prompt

Set up WordPress from its verified official source (https://github.com/WordPress/WordPress). Supported targets: Linux. Begin with a read-only preflight covering the operating system, architecture, shell, package managers, disk space, relevant runtimes or hardware, and any existing installation. Use WordPress's official package or container image with a supported PHP and database stack, pinning versions and separating a disposable local site from production hosting.

Preserve `wp-config.php`, the database, uploads, themes, plug-ins, salts, rewrite rules, backups, and container volumes. Back up files before editing and explain the selected version, source, location, dependencies, and commands. Apply only supplied, supported preferences: deployment_mode, data_directory, database_name, listen_address, http_port. The only available credential references are secret://wordpress/database-password, secret://wordpress/admin-password. Treat every reference as opaque: never print, echo, log, resolve, or paste its value.

Ask before elevation, system-wide packages, services or startup items, ports or firewall rules, sign-in, large downloads, overwrites, or migrations.  Do not enable startup items, background services, overlays, notifications, analytics, or device permissions unless they are requested and separately approved. Do not overwrite an existing site, run database upgrades, create admin users, install plug-ins, change DNS, expose ports, or enable mail without approval. For a large game or media download, report the exact size, destination drive, free space, and bandwidth impact, then wait for approval. Never delete game libraries, save files, media libraries, mods, profiles, or cloud-sync data. If the platform or configuration is unsupported, stop and offer the closest official alternative.

For a fresh approved local deployment, reach the loopback installation page and check service health, then stop before entering database or administrator credentials. Report the version, executable, configuration and data paths, changed files, active processes or listeners, and verification evidence without exposing sensitive values. End with manual steps and exact rollback or uninstall instructions that remove only setup-owned changes, restore backups, stop new services, and preserve user data.
