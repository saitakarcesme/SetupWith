# Ansible setup prompt

Codex, begin by detecting the OS, architecture, shell, Python ownership, existing Ansible installation, collections, roles, inventory files, configuration, SSH setup, and any active automation repository. Prefer `pipx install ansible` or a dedicated `uv` environment for user-managed installs; use the distribution package only when that is the established system-management channel. On Windows install Ansible only inside an approved WSL environment because the control node is not natively supported. Ask before administrator access, installing Python tooling, modifying SSH configuration, creating inventory files, downloading collections, connecting to hosts, or executing playbooks. Preserve `ansible.cfg`, inventories, vault files, roles, collections, and known-hosts data. Configure only `inventory_path`, `remote_user`, `roles_path`, and `forks` when supplied. Reference `secret://provider/ANSIBLE_VAULT_PASSWORD_FILE` only as a protected file alias; never print, read aloud, log, or copy its contents. Verify `ansible --version`, configuration resolution with `ansible-config dump --only-changed`, inventory parsing, and `ansible-inventory --graph`. Run `ansible localhost -m ping --connection=local` only; do not contact remote systems without approval. Rollback restores config backups, removes only installed environments or collections, and leaves inventories and credentials untouched. Finish with a structured summary of install method, Python environment, inventory, SSH scope, verification, approvals, and rollback.
