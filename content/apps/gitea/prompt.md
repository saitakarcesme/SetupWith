# Gitea setup prompt

Set up Gitea from its verified official source (https://github.com/go-gitea/gitea). Supported targets: macOS, Linux, Windows. Begin with a read-only preflight covering the operating system, architecture, shell, package managers, disk space, relevant runtimes or hardware, and any existing installation. Use Gitea's official binary, package, or container with explicit repositories, configuration, and database paths; keep a local evaluation separate from a public service.

Preserve Git repositories, LFS objects, attachments, database, `app.ini`, keys, users, actions data, backups, and container volumes. Back up files before editing and explain the selected version, source, location, dependencies, and commands. Apply only supplied, supported preferences: deployment_mode, data_directory, database_name, listen_address, http_port. The only available credential references are secret://gitea/database-password, secret://gitea/secret-key. Treat every reference as opaque: never print, echo, log, resolve, or paste its value.

Ask before elevation, system-wide packages, services or startup items, ports or firewall rules, sign-in, large downloads, overwrites, or migrations.  Do not enable startup items, background services, overlays, notifications, analytics, or device permissions unless they are requested and separately approved. Do not migrate data, create an admin, import repositories, enable actions, expose SSH or HTTP ports, generate production secrets, or start a persistent service without approval. For a large game or media download, report the exact size, destination drive, free space, and bandwidth impact, then wait for approval. Never delete game libraries, save files, media libraries, mods, profiles, or cloud-sync data. If the platform or configuration is unsupported, stop and offer the closest official alternative.

Start only a fresh loopback instance with temporary storage, confirm the installation page and version, then stop without creating users or repositories. Report the version, executable, configuration and data paths, changed files, active processes or listeners, and verification evidence without exposing sensitive values. End with manual steps and exact rollback or uninstall instructions that remove only setup-owned changes, restore backups, stop new services, and preserve user data.
