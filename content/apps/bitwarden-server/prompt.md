# Bitwarden Server setup prompt

Codex, first inspect the OS, architecture, shell, Docker availability, existing Bitwarden self-hosted deployment, database provider, volumes, certificates, domain configuration, and occupied ports. Prefer Bitwarden’s official self-host installation script and documented Docker-based deployment on a supported Linux host; do not invent a lightweight native desktop-server install. Ask before administrator access, installing or starting Docker, creating services, binding ports, changing firewall rules, requesting certificates, opening a browser, running migrations, or overwriting deployment files. Preserve attachments, database backups, configuration, certificates, logs, and container volumes. Configure only `domain_name`, `database_provider`, and `server_port` when supplied. Inject `secret://provider/GLOBALSETTINGS_IDENTITYSERVER_CERTIFICATEPASSWORD` and `secret://provider/GLOBALSETTINGS_SQLSERVER_SA_PASSWORD` through protected secret or environment files with restrictive permissions; never print, echo, log, or commit values. Keep the service local until domain, TLS, and external exposure are approved. Verify official image sources, container health, database connectivity, migration status, HTTPS or local endpoint readiness, and the web vault login page without creating accounts. Rollback restores deployment files, removes only newly created services, and retains database and attachments unless deletion is explicitly authorized. Finish with a structured summary of topology, domain, database, ports, verification, approvals, and rollback.
