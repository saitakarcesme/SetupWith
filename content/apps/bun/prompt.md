# Bun setup prompt

Codex, begin by detecting the OS, architecture, shell, PATH, existing `bun` binary, package-manager ownership, and project files such as `bun.lock`, `package.json`, or runtime version declarations. Install only on supported platforms. On macOS and Linux prefer Bun’s official installer unless Homebrew already manages the installation; on Windows use the official supported installation method or `winget` when available. Ask before administrator access, running a downloaded installer, editing PATH, replacing Node tooling, or modifying project lockfiles. Preserve Bun configuration, caches, registries, global packages, and all existing lockfiles. Configure only `bun_version`, `npm_registry`, and `install_cache_dir` when supplied. Use the existing version manager if it already controls Bun. For private registry access, reference only `secret://provider/NPM_TOKEN`; never print, echo, log, or store the value in committed files. Do not run `bun install` inside a user project without approval. Verify with `bun --version`, `bun pm cache`, a temporary `bun -e` script, and creation plus execution of a disposable test outside existing repositories. Confirm registry and cache settings without publishing anything. Rollback restores shell and config backups, removes only the installed Bun version or package, and leaves project artifacts untouched. Finish with a structured summary of detected tooling, install source, configured values, verification, approvals, and rollback.
