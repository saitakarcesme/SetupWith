# Deno setup prompt

Codex, inspect the operating system, architecture, shell, PATH, existing `deno` installation, package-manager ownership, and any project `deno.json` files before changing anything. On macOS prefer Homebrew `deno`; on Linux use the official Deno installer or an appropriate trusted package after explaining the choice; on Windows prefer `winget install DenoLand.Deno`. Ask before administrator access, executing a remote installer, editing PATH, changing file associations, or granting runtime permissions. Preserve existing Deno configuration, caches, lockfiles, tasks, and shell completion setup. Configure only `deno_version`, `default_permissions`, and `npm_registry` when provided. Pin versions through the existing manager when possible. Treat `default_permissions` conservatively: do not create blanket `--allow-all` aliases; instead document or create narrowly scoped task flags only after approval. If private registries are needed, reference `secret://provider/DENO_AUTH_TOKENS` without printing, echoing, logging, or committing the secret. Verify with `deno --version`, `deno info`, a temporary `deno eval`, and a permission-denied test demonstrating the security model. Validate registry configuration without downloading project dependencies unless requested. Rollback restores profile and config backups, removes added completions, and uninstalls only the installed Deno channel. End with a structured summary of install method, version management, permissions, registry configuration, verification, approvals, and rollback steps.
