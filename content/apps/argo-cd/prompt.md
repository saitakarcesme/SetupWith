# Argo CD setup prompt

Codex, first inspect the OS, architecture, shell, existing `argocd` CLI, Kubernetes contexts, namespaces, Argo CD installations, Helm releases, manifests, repositories, and occupied service ports. Install the official Argo CD CLI through Homebrew on macOS, the verified release binary on Linux, or a supported `winget` package on Windows. Do not install the in-cluster controller unless an approved Kubernetes context exists. Ask before administrator access, creating namespaces, applying manifests, installing Helm charts, opening ports, changing firewall rules, port-forwarding, browser sign-in, or modifying cluster resources. Preserve existing Argo CD applications, projects, repositories, secrets, RBAC, and certificates. Configure only `server_address`, `default_project`, and `default_namespace` when supplied. Use `secret://provider/ARGOCD_AUTH_TOKEN` through protected environment injection; never print, echo, log, or store it in shell history. Verify `argocd version --client`, kube-context access, namespace existence, and read-only application listing when authenticated. If no server is available, validate official installation manifests with client-side Kubernetes dry-run only. Rollback restores kubeconfig and CLI config backups, removes only the installed CLI or newly created namespace after approval, and never deletes existing applications. Finish with a structured summary of CLI source, cluster context, namespace, server, authentication, checks, approvals, and rollback.
