# Impression setup prompt

Set up Impression from its official GitLab project and verified Flathub listing (https://gitlab.com/adhami3310/Impression). Inventory Linux architecture, Flatpak user and system scopes, existing Impression package, UDisks/polkit availability, image-download preferences and removable-device access policy without opening any block device. Install only stable `io.gitlab.adhami3310.Impression` from the verified Flathub origin in the existing ownership scope; upstream supports Flatpak as its official package. Do not launch Impression, enumerate media through its UI, select an image, download a distribution or request authorization during setup.

Preserve all disks, partition tables, filesystems, encryption headers, volume metadata, boot records, mounts, swap state and image files byte-for-byte. Raw image writing overwrites the target and is not reversible by uninstalling Impression. Never use a write as installation verification. Before any future write require a separately verified backup and show the image's canonical HTTPS source, publisher, release, architecture, file size, format, signature and published checksum; reject truncated downloads, unexplained redirects and checksum mismatch. Treat Windows installer media transformation separately from a byte-for-byte Linux image write.

Never identify a target by `/dev/sdX` alone because device nodes can change. Immediately before approval re-resolve persistent ID, vendor, model, serial, exact byte capacity, USB/SD transport, removable flag, parent/child topology, mounted partitions, encryption, LVM/RAID membership, swap and open handles. Refuse system disks, ambiguous serials, multipath devices, mounted targets and any drive containing the only backup. Present the destructive confirmation with source and target side by side; authorization must name the persistent target identity, not merely say 'continue'.

Do not unmount, write, cancel an active write, repartition, format, sync or eject during setup. Cancellation may leave unusable partial media, and buffered writes are incomplete until synchronization finishes. Verify Impression provenance, app ID, origin, installed commit, runtime, executable, files and declared permissions through Flatpak metadata offline. Compare preflight block topology, mount table and image hashes and prove no authorization prompt, download, device open, unmount, write, cache file or network request occurred. If package verification fails, rollback only the new Impression ref in its original scope; never attempt to 'rollback' media by writing another image, and preserve runtimes, remotes, overrides, images and every device.
