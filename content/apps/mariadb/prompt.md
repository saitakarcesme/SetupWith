# MariaDB setup prompt

Codex, begin by detecting the OS, architecture, shell, existing MariaDB or MySQL binaries, package ownership, data directories, configuration, active services, port 3306 conflicts, and backups. Prefer Homebrew `mariadb` on macOS, the distribution’s MariaDB packages or MariaDB’s official repository on Linux, and MariaDB’s official MSI package on Windows. Do not install beside an active MySQL server without explaining compatibility and port risks. Ask before administrator access, adding repositories, initializing or upgrading data, enabling services, changing ports or firewall rules, resetting credentials, or replacing configuration. Preserve databases, grants, logs, `my.cnf` includes, and service definitions. Configure only `mariadb_user`, `mariadb_database`, `mariadb_port`, and `data_directory` when supplied. Handle `secret://provider/MARIADB_ROOT_PASSWORD` and `secret://provider/MARIADB_PASSWORD` through secure input or protected option files; never print, echo, log, or expose values in arguments. Bind locally by default and create roles and schemas idempotently with minimal privileges. Verify client and server versions, service health, `mariadb-admin ping`, local login, schema access, and a disposable transactional table. Rollback restores configs and service state and never removes existing data; deleting a new empty instance requires approval. Finish with a structured summary of coexistence checks, install source, instance, users, database, verification, approvals, and rollback.
