# Iotas setup prompt

Set up Iotas from its official GNOME project and verified Flathub listing (https://apps.gnome.org/Iotas/). Inventory Linux architecture, Flatpak scopes, existing package and data paths, local SQLite database presence, note/category counts, FTS and GNOME Shell search state, Nextcloud account count, offline-edit status, secret-store boundary and backup freshness without reading note titles, bodies, categories, search terms or credentials. Install stable `org.gnome.World.Iotas` from verified Flathub in the existing ownership scope. Do not compile from source, launch Iotas, open or migrate the database, authenticate, synchronize, index notes, run backup/restore or render/export content during setup.

Preserve every note, ID, body, Markdown source, task state, category, favorite, timestamp, sync token, conflict copy, deletion marker, FTS record, preference and credential reference. Iotas constantly saves and large collections may be partially loaded; never infer that unloaded notes are absent or that closing without an explicit export creates a recovery point. Back up the SQLite database and associated state consistently before migration or synchronization, then verify the backup checksum and rehearse restoration only against an isolated profile.

Nextcloud Notes sync uses its REST API rather than WebDAV and provides basic conflict detection. Before first connection show the exact HTTPS origin, certificate and redirects, account identity, dedicated app-password storage, API version, note counts on each side and a content-redacted preview of local-only, remote-only, changed, conflicted and deleted records. Declare one initial authority and explicit rules for simultaneous edits, IDs, timestamps, duplicates and tombstones. Never let newest timestamp or server deletion win silently; preserve both versions when uncertain.

GNOME Shell search and FTS indexes can expose titles or snippets outside the editor. Keep the Shell provider disabled until session privacy and indexing scope are approved. Treat Markdown links and rendered HTML as untrusted; do not fetch images or navigate during verification. PDF, ODT and HTML export can retain metadata and links. Verify provenance, app ID, origin, commit, runtime, executable, database schema, files and permissions offline. Prove no database read/write, index, secret access, API request, sync token, preview, task toggle, backup, restore, export, Shell result or filesystem state changed. On failure, rollback only the new Iotas ref in its original scope; preserve runtimes, remotes, overrides, databases, notes and credentials.
