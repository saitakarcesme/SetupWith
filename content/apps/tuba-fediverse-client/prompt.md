# Tuba setup prompt

Set up Tuba from its official project and verified Flathub listing (https://apps.gnome.org/Tuba/). Inventory Linux architecture, Flatpak scopes, existing package and data paths, configured account count, instance-software families, draft and scheduled-post counts, aggregate media/cache bytes, notification policy and OAuth token-reference presence without revealing instance hosts, handles, display names, posts, drafts, schedules, timelines, relationships, moderation lists, media, direct-message content or secrets. Install stable `dev.geopjr.Tuba` from verified Flathub in the existing ownership scope. Do not compile from source, launch Tuba, resolve an instance, register an OAuth client, open a browser, authenticate, fetch a timeline, load remote media, compose, schedule, publish, boost, favorite, follow, search, or notify during setup.

Preserve accounts, full handles, instance mappings, OAuth references, timelines and cache, drafts, scheduled posts, visibility defaults, filters, mutes and blocks, media preferences, notifications, remotes, overrides and scope ownership. A display name is not a unique identity; always pair the full handle with the instance. Multiple accounts create a wrong-composer risk. Fediverse visibility labels do not guarantee confidentiality: remote servers and recipients may retain, screenshot or re-share content, and delete or edit propagation can be incomplete. Never print access tokens or conversation data.

Before later authorization, require exact HTTPS instance origin, operator and jurisdiction, supported server software, redirect URI, OAuth scopes, browser boundary, token storage reference, expiry and revocation path. Use least privilege and confirm the returned account identity before any API write. Before composing, show active full handle, visibility, mentions, language, content warning, sensitive-media flag, alt text, attachment metadata and schedule timezone. Scheduling requires a server/local storage declaration and cancellation test. Treat profiles, posts, HTML, emoji, previews and media as untrusted; block automatic remote loads and strip EXIF before separately approved uploads.

Review direct-message limitations, moderation differences across instances, blocked-domain behavior and locked-screen notification exposure. Verify provenance, app ID, origin, commit, runtime, executable, files and sandbox permissions offline. Prove no DNS request, instance discovery, OAuth registration, browser launch, authentication, API read or write, remote-media load, timeline fetch, relationship action, post scheduling or publication, cache mutation or notification occurred. On failure, rollback only the new Tuba ref in its original scope; preserve shared runtimes, remotes, overrides, accounts, tokens, drafts, schedules, filters, moderation state, media and cache.
