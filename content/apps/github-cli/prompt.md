# GitHub CLI setup prompt

Codex, inspect the OS, architecture, shell, PATH, existing `gh` binary, Git installation, credential helpers, and current GitHub CLI authentication status before making changes. On macOS use Homebrew package `gh`; on Debian/Ubuntu use GitHub CLI’s signed apt repository and package `gh`; on Fedora-family systems use the official RPM repository; on Windows prefer `winget install GitHub.cli`. Ask before administrator access, adding repositories, changing Git protocol defaults, opening a browser, or initiating sign-in. Preserve `~/.config/gh/config.yml`, `hosts.yml`, and existing Git settings. Configure only `git_protocol` and `default_editor` when supplied, merging through `gh config set` without exposing credentials. If `secret://provider/GITHUB_TOKEN` is available, use it through a non-printing authentication path; never echo, log, persist in shell history, or display the value. Otherwise, ask before browser/device authentication. Verify with `gh --version`, `gh config list`, `gh auth status` when authenticated, and a read-only API command such as viewing the current user or a public repository. Do not create issues, repositories, or pull requests. Rollback should restore backed-up config and remove only the installed package. Finish with a structured summary covering installation, authentication method, config changes, verification, approvals, and rollback commands.
