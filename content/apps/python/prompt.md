# Python setup prompt

Codex, inspect the OS, architecture, shell, PATH, existing `python`, `python3`, pip, virtual environments, package managers, and project version files before installation. Never replace the operating system’s managed Python. Prefer an existing mise or pyenv workflow; otherwise use Homebrew on macOS, distribution packages such as `python3`, `python3-pip`, and `python3-venv` on Linux, and `winget install Python.Python.3` on Windows. Ask before administrator access, changing PATH or file associations, compiling Python, or modifying system certificates. Preserve pip configuration, virtual environments, user packages, and project lockfiles. Configure only `python_version`, `virtualenv_location`, and `package_index` when supplied. Pin the interpreter through the detected version manager where possible and create no project environment unless requested. For package indexes, write only non-secret URLs to supported config; do not embed credentials. Verify interpreter resolution with `python3 --version` or the intended `python --version`, `python -m pip --version`, `python -m venv` in a temporary directory, and a small standard-library script. Do not globally upgrade pip or install demonstration packages without approval. Rollback restores profile and pip config backups, removes only the installed interpreter or version-manager entry, and preserves user environments. End with a structured summary of interpreter ownership, install method, configured values, verification, approvals, and rollback.
