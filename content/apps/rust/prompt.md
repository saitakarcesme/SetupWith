# Rust setup prompt

Codex, inspect the OS, architecture, shell, PATH, existing `rustc`, `cargo`, rustup, system packages, installed toolchains, targets, and project `rust-toolchain` files before changing anything. Prefer rustup for user-managed Rust on macOS, Linux, and Windows; if a package manager already owns Rust, explain the conflict rather than layering installations. Ask before administrator access, executing the rustup installer, changing PATH, removing distribution packages, or downloading additional targets and components. Preserve `~/.rustup`, `~/.cargo`, Cargo configuration, credentials, installed binaries, and project files. Configure only `rust_toolchain`, `cargo_install_root`, and `default_target` when supplied. Use rustup overrides only where explicitly requested, and do not overwrite project-specific toolchain declarations. Set Cargo’s install root through supported environment or config mechanisms while preserving existing values. Verify with `rustc --version`, `cargo --version`, `rustup show`, and a disposable `cargo new` project built and tested outside existing repositories. If a non-host target is configured, verify installation but do not cross-compile unless the required linker exists. Rollback restores shell and Cargo config backups, removes only newly installed toolchains or the rustup installation, and preserves user crates unless approved. Finish with a structured summary of toolchain ownership, selected target, config changes, test results, approvals, and rollback.
