# Langfuse setup prompt

Codex, begin by inspecting the OS, architecture, shell, Docker or Kubernetes availability, existing Langfuse deployment, PostgreSQL and object-storage dependencies, environment files, volumes, and occupied ports. Prefer Langfuse’s official self-hosting Docker Compose configuration for a single-machine setup; use Helm only when an existing Kubernetes cluster and operations workflow are already present. Ask before administrator access, installing container tooling, starting services, database migrations, changing ports, firewall rules, browser access, or overwriting compose and environment files. Preserve the PostgreSQL database, ClickHouse or object-storage data where applicable, encryption-related settings, and existing deployment manifests. Configure only `server_port`, `telemetry_enabled`, and `public_url` when supplied. Inject `secret://provider/NEXTAUTH_SECRET`, `secret://provider/SALT`, and `secret://provider/DATABASE_URL` through a protected secrets mechanism; never print, echo, log, or commit values. Keep the service local unless an approved public URL and reverse proxy exist. Verify container health, database migration completion, HTTP readiness, login page availability, and creation of a disposable trace through a local test client without exposing credentials. Rollback removes only newly created services and manifests, restores backups, and retains databases unless deletion is approved. Finish with a structured summary of topology, persistence, URL, telemetry, checks, approvals, and rollback.
