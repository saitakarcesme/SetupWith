# Apache Kafka setup prompt

Codex, inspect the OS, architecture, shell, Java runtime, existing Kafka binaries, cluster metadata, broker configuration, storage directories, services, listeners, and port conflicts before installation. Prefer Apache Kafka’s official binary distribution on macOS or Linux, using a dedicated installation directory and a supported Java runtime; on Windows use an approved WSL or container workflow rather than claiming full native parity. Ask before administrator access, installing Java, formatting KRaft storage, starting brokers, changing services, opening ports, altering firewall rules, or joining an existing cluster. Preserve topic data, metadata logs, consumer offsets, `server.properties`, credentials, and service definitions. Configure only `broker_id`, `listeners`, `data_directory`, and `default_partitions` when supplied. Validate listener addresses and bind locally for a single-node development broker unless external access is approved. Do not reuse or reformat an existing cluster ID. Verify Java and Kafka scripts, configuration parsing, broker readiness, API versions, topic listing, and creation, production, consumption, and deletion of a disposable topic. Rollback stops only the created broker, restores configuration, removes new service files, and keeps log directories unless deletion is explicitly approved. Finish with a structured summary of distribution, Java, KRaft state, listeners, storage, verification, approvals, and rollback.
