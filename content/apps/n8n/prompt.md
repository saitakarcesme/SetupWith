# n8n setup prompt

Codex, begin by detecting the OS, architecture, shell, Docker or Node.js availability, existing n8n deployment, database, encryption key state, workflow data, credentials, public URL, and occupied ports. Prefer n8n’s official Docker image with a persistent data volume; use the official npm package only inside an existing managed Node environment. Ask before administrator access, installing Docker or Node, starting services, exposing ports, changing firewall rules, opening a browser, running database migrations, enabling community nodes, or overwriting environment files. Preserve workflows, executions, credentials, encryption settings, database volumes, and binary data. Configure only `server_port`, `public_url`, `timezone`, and `database_type` when supplied. Inject `secret://provider/N8N_ENCRYPTION_KEY`, `secret://provider/N8N_BASIC_AUTH_PASSWORD`, and `secret://provider/DB_POSTGRESDB_PASSWORD` through protected runtime secrets; never print, echo, log, or commit values. Keep the editor localhost-bound unless authentication, TLS, and proxy settings are approved. Verify image or package identity, database connectivity, migration completion, health endpoint, timezone behavior, and creation plus deletion of a disposable manual workflow without external credentials. Rollback restores manifests, removes only services created here, and retains workflows and database data unless deletion is authorized. Finish with a structured summary of runtime, database, URL, timezone, security, verification, approvals, and rollback.
