# Firebase CLI setup prompt

Set up Firebase CLI from its verified official source (https://firebase.google.com/docs/cli#install_the_firebase_cli). Supported targets: macOS, Linux, Windows. Begin with a read-only preflight covering the operating system, architecture, shell, package managers, disk space, relevant runtimes or hardware, and any existing installation. Choose Google's documented Firebase CLI method for the platform, prefer a supported Node.js and user-writable package location, and distinguish the npm package from standalone installers.

Preserve Preserve `firebase.json`, `.firebaserc`, project aliases, emulator data, login state, cached binaries, functions dependencies, hosting configuration, rules, and package lockfiles.. Back up files before editing and explain the selected version, source, location, dependencies, and commands. Apply only supplied, supported preferences: active_project, project_aliases, emulator_ports, telemetry. The only available credential references are secret://google/application-credentials, secret://firebase/token. Treat every reference as opaque: never print, echo, log, resolve, or paste its value.

Ask before elevation, system-wide packages, services or startup items, ports or firewall rules, sign-in, large downloads, overwrites, or migrations.  Do not enable startup items, background services, overlays, notifications, analytics, or device permissions unless they are requested and separately approved. Do not authenticate, run `firebase init`, select a project, overwrite service configuration, download emulators, bind network ports, deploy, or generate a legacy CI token without approval. For a large game or media download, report the exact size, destination drive, free space, and bandwidth impact, then wait for approval. Never delete game libraries, save files, media libraries, mods, profiles, or cloud-sync data. If the platform or configuration is unsupported, stop and offer the closest official alternative.

Run `firebase --version` and offline help outside an application directory, report executable and runtime paths, and ensure no login, project initialization, emulator, or deployment started. Report the version, executable, configuration and data paths, changed files, active processes or listeners, and verification evidence without exposing sensitive values. End with manual steps and exact rollback or uninstall instructions that remove only setup-owned changes, restore backups, stop new services, and preserve user data.
