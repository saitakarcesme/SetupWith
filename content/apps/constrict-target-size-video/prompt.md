# Constrict setup prompt

Set up Constrict from its official project and verified Flathub listing (https://apps.gnome.org/Constrict/). Inventory Linux architecture, Flatpak scopes, existing package and data paths, encoder availability by codec class, hardware-acceleration presence, queue and partial-output counts, aggregate temporary bytes, output-directory policy, sandbox overrides and backup coverage without opening media or revealing filenames, frames, thumbnails, metadata, subtitles, audio, durations, project subjects or private paths. Install stable `io.github.wartybix.Constrict` from verified Flathub in the existing ownership scope. Do not compile from source, launch Constrict, enumerate media, open or decode a video, probe streams, calculate a target bitrate from user content, generate a thumbnail, start an encoder, reserve output names, create temporary files, overwrite output, consume GPU resources or play compressed media during setup.

Preserve every source and prior output byte, stream, timestamp, metadata field, owner and permission, plus queues, partial files, encoder preferences, remotes, overrides and scope ownership. Target-size compression is lossy and may be impossible at an acceptable quality; installation must not infer a byte limit, discard audio or subtitles, reduce frame rate or resolution, flatten HDR, change rotation, replace an original or resume a stale partial encode. Media content and paths are private; redact them.

Before a later job, require an exact target byte limit and tolerance. Subtract verified container, audio, subtitle and metadata overhead before calculating average video bitrate, and reject nonpositive or below-policy budgets rather than looping indefinitely. Pin H.264, HEVC, AV1 or VP9 encoder, version, profile, level, pixel format and container compatibility. Define scaling with preserved aspect ratio and legal dimensions, frame-rate cap, variable-frame-rate handling, HDR and color metadata. Audio decisions must retain language, channel layout, synchronization and accessibility needs; mono input must not become stereo without reason. Validate planning with synthetic media.

For a batch, bind each checksum to a unique output name, preview collisions and free-space needs, cap retries, passes, CPU, GPU, memory and temperature, and write to a temporary destination before atomic publish. Cancellation must terminate the full encoder process group and remove only owned temporaries. Verify output size, streams, duration, timestamps, A/V sync and complete decode, then perform representative visual and audio review; byte compliance alone is not quality. Verify installation provenance and static permissions offline, proving no source read, probe, decode, calculation, encode, temporary write, collision, hardware job or playback occurred. On failure, rollback only the new Constrict ref; preserve shared runtimes, originals, outputs, queues, preferences and backups.
