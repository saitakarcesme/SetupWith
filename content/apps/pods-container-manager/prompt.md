# Pods setup prompt

Set up Pods from its official repository and verified Flathub listing (https://github.com/marhkb/pods). Inventory Linux architecture, Flatpak scopes, existing Pods package and preferences, Podman and Docker installations, rootless and rootful sockets, remote engine definitions, TLS material, registry auth files, containers, pods, images, volumes, networks, build contexts and running workloads. Install stable `com.github.marhkb.Pods` from the verified Flathub origin in the existing ownership scope. Do not install a nightly artifact or source build, install or reconfigure a container engine, enable a socket, or add a connection during setup.

Install without launching Pods or connecting to any engine. Preserve connection definitions, certificates, SSH details, registry credentials, image stores, tags and digests, container filesystems, pods, volumes, networks, port mappings, health configuration, logs and preferences. Never display secret environment variables, registry tokens, labels, commands, mounted file contents or container logs in setup output. A Unix engine socket grants control equivalent to the engine owner; a rootful socket can cross the host privilege boundary. Do not expose either socket to the Flatpak until its exact path, owner, mode and engine scope are reviewed.

Do not search registries, pull or push images, build a Containerfile, create or start workloads, open a terminal, execute commands, stream logs, map ports, mount host paths, attach devices, add capabilities or create privileged containers. Before any future engine mutation show endpoint identity, TLS verification, rootless/rootful status, exact image digest, registry trust, build context exclusions, container user, requested mounts, devices, capabilities, secrets, networks, published interfaces and cleanup boundary. Treat experimental Docker support independently from Podman and never reuse a connection assumption across engines.

Bulk lifecycle actions and pruning can destroy multiple workloads or irrecoverable volume data. Never stop, kill, delete, force-remove, untag or prune anything as a setup test. Verify Pods provenance, app ID, origin, installed commit, runtime, executable, files and declared permissions using Flatpak metadata offline. Compare preflight engine socket, process and object inventories and prove no connection, auth file, image, container, pod, volume, network, process, port, mount or network request changed. If verification fails, rollback only the newly installed Pods ref in its original scope; preserve shared runtimes, remotes, engine packages, sockets and all container state.
