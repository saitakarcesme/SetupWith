# SetupWith setup prompt

Set up SetupWith from its verified official source (https://github.com/saitakarcesme/SetupWith). Supported targets: macOS, Linux, Windows. Begin with a read-only preflight covering the operating system, architecture, shell, package managers, disk space, relevant runtimes or hardware, and any existing installation. Clone the official SetupWith repository into the approved projects directory, inspect its lockfile and package scripts, require Node.js 20.9 or newer, install dependencies with npm from the lockfile, run the repository checks, and start the Next.js development server on 127.0.0.1 using an available local port.

Preserve any existing SetupWith checkout, uncommitted work, environment files, generated content, browser profile and vault data, saved package drafts, and processes already using the requested port. Back up files before editing and explain the selected version, source, location, dependencies, and commands. Apply only supplied, supported preferences: projects_directory, preferred_package_manager, local_port, bind_address. No credential references are needed for this setup.

Ask before elevation, system-wide packages, services or startup items, ports or firewall rules, sign-in, large downloads, overwrites, or migrations.  Do not enable startup items, background services, overlays, notifications, analytics, or device permissions unless they are requested and separately approved. Do not expose the server to the LAN or public internet, add authentication services, overwrite environment files, alter firewall rules, or print private profile and vault data. Explain that anything the user explicitly copies into Codex leaves SetupWith's local browser boundary and is then governed by the destination Codex service's data controls. For a large game or media download, report the exact size, destination drive, free space, and bandwidth impact, then wait for approval. Never delete game libraries, save files, media libraries, mods, profiles, or cloud-sync data. If the platform or configuration is unsupported, stop and offer the closest official alternative.

Run npm run check, report the exact checkout and configuration paths, open the local home, app catalog, package builder, and profile pages on 127.0.0.1, check for browser and terminal errors, and provide a rollback that stops only the new server and preserves all repository and browser data. Report the version, executable, configuration and data paths, changed files, active processes or listeners, and verification evidence without exposing sensitive values. End with manual steps and exact rollback or uninstall instructions that remove only setup-owned changes, restore backups, stop new services, and preserve user data.
