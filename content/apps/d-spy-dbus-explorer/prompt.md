# D-Spy setup prompt

Set up D-Spy from its official GNOME project and verified Flathub listing (https://apps.gnome.org/Dspy/). Inventory Linux architecture, Flatpak scopes, existing package and data paths, declared session and system bus access, saved-filter count, aggregate introspection-cache bytes, sandbox overrides and backup coverage without connecting to a bus or revealing bus addresses, names, object paths, interfaces, members, process identities, property values, signal payloads, file descriptors, tokens or message contents. Install stable `org.gnome.dspy` from verified Flathub in the existing ownership scope. Do not compile from source, launch D-Spy, connect to any bus, list names, activate a service, introspect an object, read or write a property, call a method, subscribe to a signal, monitor traffic, receive a file descriptor, invoke polkit or export data during setup.

Preserve all saved bus choices, filters, bookmarks, cached introspection, window state, permissions, remotes, overrides and scope ownership. D-Bus inspection can expose account identities, notification text, clipboard-related data and privileged service structure. Redact names and payloads. Installation must not activate a dormant service, claim a name, add a match rule, leave a subscription active or broaden session, system, accessibility or peer-bus access. A sandbox permission to connect is not authorization to inspect or invoke every reachable service.

Before later exploration, require the exact bus type or reviewed custom address, user and container context, purpose, permitted destinations and retention window. Introspect only approved services with object-depth, object-count, byte and timeout limits; treat XML, signatures and annotations as untrusted. Distinguish well-known names from transient unique owners and record ownership changes without identifying unrelated processes. Use a disposable synthetic bus service for validation so production services are neither activated nor queried.

Method calls and writable properties are mutations: require destination, path, interface, member, exact typed arguments, expected reply, side-effect statement and authorization. Never send real secrets or file descriptors in a test. Signal monitoring needs a narrow match, payload redaction, rate and byte caps, expiry and deterministic unsubscribe. Respect D-Bus and polkit denials rather than attempting bypass. Verify provenance, app ID, origin, commit, runtime, executable, files and static permissions offline. Prove no bus connection, name listing, activation, introspection, property access, method call, signal rule, message receipt, descriptor transfer, privilege prompt or export occurred. On failure, rollback only the new D-Spy ref in its original scope; preserve shared runtimes, remotes, overrides, filters, bookmarks, caches and backups.
