# Helix setup prompt

Codex, inspect the operating system, architecture, shell, terminal, existing `hx` binary, package ownership, and Helix runtime/config paths before installing anything. On macOS prefer Homebrew package `helix`; on Debian/Ubuntu use the available `helix` package when suitable or the project’s official release artifact after explaining the choice; on Fedora-family systems prefer the native package; on Windows use `winget install Helix.Helix` when available. Ask before administrator access, downloading a release archive, replacing an existing binary, or modifying PATH. Preserve `~/.config/helix/config.toml`, `languages.toml`, runtime files, and user themes. Configure only `editor_theme`, `preferred_shell`, and `clipboard_provider` when supplied. Merge valid TOML without removing unrelated keys. Set shell commands in the Helix configuration only when supported, and verify the selected clipboard provider exists rather than silently installing additional utilities. Run `hx --version`, `hx --health`, and a non-destructive open test against a temporary file. Check that runtime queries load, the configured theme resolves, and clipboard integration reports usable status. Do not install language servers automatically unless separately approved. Rollback must restore the original TOML files, remove any PATH entry added during this run, and uninstall only the chosen package. Finish with a structured summary of detection, install source, configuration, health checks, skipped dependencies, and rollback.
