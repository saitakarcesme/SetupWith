# Salesforce setup prompt

Set up Salesforce from its verified official source (https://login.salesforce.com/). Supported targets: Web. Begin with a read-only preflight covering the operating system, architecture, shell, package managers, disk space, relevant runtimes or hardware, and any existing installation. Open only the organization's confirmed Salesforce login or sandbox domain in an isolated browser profile, validate the Salesforce certificate and My Domain destination, and offer browser app installation without extensions or data connectors.

Preserve existing Salesforce browser sessions, trusted devices, org and sandbox URLs, local storage, downloaded reports, cached records, notification settings, SSO state, certificates, connected apps, and production data access controls. Back up files before editing and explain the selected version, source, location, dependencies, and commands. Apply only supplied, supported preferences: org_url, sandbox_mode, browser_profile, notification_policy. No credential references are needed for this setup.

Ask before elevation, system-wide packages, services or startup items, ports or firewall rules, sign-in, large downloads, overwrites, or migrations. Browser Use and Computer Use may open the official page, download the approved signed installer, complete the visible installer flow, verify the publisher or code signature, and launch the product once. Stop and hand control to the user before account creation, sign-in, password entry, MFA, CAPTCHA, age verification, purchases, subscriptions, license acceptance that creates a paid obligation, or linking external accounts. Never bypass DRM, regional restrictions, or platform protections. Do not enable startup items, background services, overlays, notifications, analytics, or device permissions unless they are requested and separately approved. Stop before SSO, username, password, MFA, device trust, OAuth consent, production-org access, record creation or mutation, report export, file upload, package installation, Flow execution, email, or administrative Setup changes. For a large game or media download, report the exact size, destination drive, free space, and bandwidth impact, then wait for approval. Never delete game libraries, save files, media libraries, mods, profiles, or cloud-sync data. If the platform or configuration is unsupported, stop and offer the closest official alternative.

Confirm the exact My Domain and sandbox or production classification before login, stop at the authentication page, inspect app scope and permissions, and verify no session, connected app, record, report, file, automation, or production data changed. Report the version, executable, configuration and data paths, changed files, active processes or listeners, and verification evidence without exposing sensitive values. End with manual steps and exact rollback or uninstall instructions that remove only setup-owned changes, restore backups, stop new services, and preserve user data.
