# Bitwarden Desktop setup prompt

Set up Bitwarden Desktop from its verified official source (https://bitwarden.com/download/). Supported targets: macOS, Linux, Windows. Begin with a read-only preflight covering the operating system, architecture, shell, package managers, disk space, relevant runtimes or hardware, and any existing installation. Choose Bitwarden's standard signed desktop build for the detected platform, prefer the vendor package or official store listing over third-party repackaging, and record whether cloud-hosted or self-hosted service discovery is requested before launch.

Preserve the existing encrypted vault cache, configured self-hosted server URL, device approvals, biometric integration, vault timeout policy, application preferences, and separately installed browser extensions. Back up files before editing and explain the selected version, source, location, dependencies, and commands. Apply only supplied, supported preferences: server_url, vault_timeout, browser_integration, biometric_unlock. No credential references are needed for this setup.

Ask before elevation, system-wide packages, services or startup items, ports or firewall rules, sign-in, large downloads, overwrites, or migrations.  Do not enable startup items, background services, overlays, notifications, analytics, or device permissions unless they are requested and separately approved. Never enter, reveal, export, or migrate a master password, recovery code, organization key, or vault contents; changing the server URL, enabling biometrics, or linking browser extensions must remain a visible user-controlled action. For a large game or media download, report the exact size, destination drive, free space, and bandwidth impact, then wait for approval. Never delete game libraries, save files, media libraries, mods, profiles, or cloud-sync data. If the platform or configuration is unsupported, stop and offer the closest official alternative.

Verify the package signature and desktop version, confirm the expected server URL on the signed-out screen, test that the app locks normally, and ensure no vault export, account creation, browser integration, or credential prompt was completed. Report the version, executable, configuration and data paths, changed files, active processes or listeners, and verification evidence without exposing sensitive values. End with manual steps and exact rollback or uninstall instructions that remove only setup-owned changes, restore backups, stop new services, and preserve user data.
