# GitLab Runner setup prompt

Set up GitLab Runner from its verified official source (https://github.com/gitlabhq/gitlab-runner). Supported targets: macOS, Linux, Windows. Begin with a read-only preflight covering the operating system, architecture, shell, package managers, disk space, relevant runtimes or hardware, and any existing installation. Install GitLab Runner from GitLab's official package repository or signed binary and separate CLI installation from registration and service activation.

Preserve `config.toml`, runner authentication tokens, build and cache directories, service accounts, executor volumes, and existing registrations. Back up files before editing and explain the selected version, source, location, dependencies, and commands. Apply only supplied, supported preferences: executor, build_directory, cache_directory, service_user, concurrency. The only available credential references are secret://gitlab/runner-token. Treat every reference as opaque: never print, echo, log, resolve, or paste its value.

Ask before elevation, system-wide packages, services or startup items, ports or firewall rules, sign-in, large downloads, overwrites, or migrations.  Do not enable startup items, background services, overlays, notifications, analytics, or device permissions unless they are requested and separately approved. Do not register or unregister a runner, start jobs, install a service, grant Docker access, change executors, or reveal authentication tokens without approval. For a large game or media download, report the exact size, destination drive, free space, and bandwidth impact, then wait for approval. Never delete game libraries, save files, media libraries, mods, profiles, or cloud-sync data. If the platform or configuration is unsupported, stop and offer the closest official alternative.

Run `gitlab-runner --version`; use `verify` only for an explicitly approved registration and do not contact GitLab or start the runner service by default. Report the version, executable, configuration and data paths, changed files, active processes or listeners, and verification evidence without exposing sensitive values. End with manual steps and exact rollback or uninstall instructions that remove only setup-owned changes, restore backups, stop new services, and preserve user data.
