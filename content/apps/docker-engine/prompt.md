# Docker Engine setup prompt

Codex, inspect the OS, architecture, shell, virtualization support, existing Docker, Moby, Docker Desktop, containerd, contexts, images, containers, volumes, networks, and daemon configuration before changes. On Linux prefer Docker Engine from Docker’s official signed repository or the distribution’s supported Moby packages; on macOS and Windows use Docker Desktop only when explicitly desired, because Docker Engine does not run natively without a VM layer. Ask before administrator access, adding repositories, enabling or restarting daemons, granting group access, installing Desktop, changing firewall rules, or modifying `/etc/docker/daemon.json`. Preserve all containers, images, volumes, contexts, credentials, and daemon settings. Configure only `data_root`, `default_registry`, `log_driver`, and `storage_driver` when supplied. Inject `secret://provider/DOCKER_AUTH_CONFIG` only through a protected credential mechanism; never print, echo, log, or commit it. Validate storage-driver compatibility before changing it and require explicit approval because migration may be disruptive. Verify `docker version`, `docker info`, context selection, daemon health, and a disposable official `hello-world` container. Rollback restores daemon config and prior service state, removes only newly installed packages, and never deletes images, containers, volumes, or data-root contents automatically. Finish with a structured summary of installation mode, daemon, storage, registry, verification, approvals, and rollback.
