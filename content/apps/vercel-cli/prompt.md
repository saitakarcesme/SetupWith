# Vercel CLI setup prompt

Set up Vercel CLI from its verified official source (https://vercel.com/docs/cli). Supported targets: macOS, Linux, Windows. Begin with a read-only preflight covering the operating system, architecture, shell, package managers, disk space, relevant runtimes or hardware, and any existing installation. Install Vercel CLI with the package method documented by Vercel, use a user-writable or project-local package location, and preserve the lockfile and any pinned CLI dependency.

Preserve Preserve Vercel authentication data, project links, `.vercel` metadata, `vercel.json`, environment files, team scope, deployment settings, telemetry choice, and package lock state.. Back up files before editing and explain the selected version, source, location, dependencies, and commands. Apply only supplied, supported preferences: scope, project_linking, package_manager, telemetry. The only available credential references are secret://vercel/token. Treat every reference as opaque: never print, echo, log, resolve, or paste its value.

Ask before elevation, system-wide packages, services or startup items, ports or firewall rules, sign-in, large downloads, overwrites, or migrations.  Do not enable startup items, background services, overlays, notifications, analytics, or device permissions unless they are requested and separately approved. Do not log in, link or create a project, pull environment variables, deploy, promote, roll back, change domains, write `.vercel`, or expose a Vercel token without approval. For a large game or media download, report the exact size, destination drive, free space, and bandwidth impact, then wait for approval. Never delete game libraries, save files, media libraries, mods, profiles, or cloud-sync data. If the platform or configuration is unsupported, stop and offer the closest official alternative.

Run `vercel --version` and local help outside a project, report the resolved binary and package version, and verify that no account, project, environment, or deployment was accessed. Report the version, executable, configuration and data paths, changed files, active processes or listeners, and verification evidence without exposing sensitive values. End with manual steps and exact rollback or uninstall instructions that remove only setup-owned changes, restore backups, stop new services, and preserve user data.
