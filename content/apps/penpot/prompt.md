# Penpot setup prompt

Codex, begin by detecting the OS, architecture, shell, Docker and Compose availability, existing Penpot deployment, PostgreSQL data, assets storage, configuration, public URI, and occupied ports. Prefer Penpot’s official Docker Compose self-hosting configuration. Ask before administrator access, installing or starting container services, creating databases, running migrations, binding ports, changing firewall rules, opening a browser, enabling email registration, or overwriting environment files. Preserve design files, teams, user accounts, assets, database volumes, and existing reverse-proxy configuration. Configure only `public_uri`, `server_port`, and `database_name` when supplied. Inject `secret://provider/PENPOT_SECRET_KEY` and `secret://provider/POSTGRES_PASSWORD` through protected runtime secrets or permission-restricted environment files; never print, echo, log, or commit values. Keep the deployment localhost-only until the public URI, TLS, and proxy settings are approved. Verify official image sources, container health, database migration completion, asset-storage permissions, frontend and backend readiness, and the login page without creating external accounts. Rollback restores compose and environment backups, removes only services created here, and preserves all database and asset volumes unless deletion is explicitly authorized. Finish with a structured summary of deployment source, URI, database, storage, port, verification, approvals, and rollback.
