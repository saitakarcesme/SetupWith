# Kubernetes setup prompt

Codex, inspect the OS, architecture, shell, existing `kubectl`, kubeconfig files, current contexts, cluster access, container runtime, and any local or remote Kubernetes components before changing anything. Install only the official `kubectl` client unless the user explicitly approves provisioning a cluster. On macOS use Homebrew `kubectl`; on Linux use Kubernetes’ official signed package repository or release binary; on Windows prefer `winget install Kubernetes.kubectl`. Ask before administrator access, modifying kubeconfig, switching contexts, creating clusters, installing control-plane services, opening ports, changing firewall rules, or applying resources. Preserve all kubeconfig files, certificates, contexts, namespaces, and cluster state. Configure only `cluster_name`, `context_name`, `namespace`, and `container_runtime` when supplied. Use `secret://provider/KUBECONFIG` only as a protected file or environment alias; never print, log, or copy credential content. Do not create a cluster merely to verify the client. Validate with `kubectl version --client`, `kubectl config get-contexts`, and `kubectl cluster-info` only against an approved context. If no cluster exists, run client-side manifest validation on a disposable resource. Rollback restores kubeconfig backups and removes only the installed client package. Finish with a structured summary of client source, contexts, namespace, cluster reachability, verification, approvals, and rollback.
