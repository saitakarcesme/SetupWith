# Mission Center setup prompt

Set up Mission Center from its official project and verified Flathub listing (https://missioncenter.io/). Detect Linux architecture, desktop, Flatpak user and system scopes, existing Mission Center packages, Flathub origin, GPU vendors, sensor interfaces, current monitoring tools, startup entries and any prior per-process network helper. Install one stable `io.missioncenter.MissionCenter` Flatpak in the scope matching current ownership. Do not select AppImage, Snap, a distro package or a source build when a managed installation already exists, and do not replace an existing package channel without approval.

Install without launching the monitor, sampling hardware, enumerating processes or opening its first-run advanced-feature dialog. Preserve preferences, disabled device categories, graph choices, refresh rate, window state, application grouping and any existing helper configuration. Live telemetry may expose usernames, process commands, application activity, storage labels, mount paths, network interfaces, MAC and IP addresses, wireless details, GPU workload, battery state and service names. Never print those values into setup logs, export them, copy them to a clipboard or send them to a remote endpoint.

Mission Center can monitor per-process networking only after manual setup, and current releases can request `pkexec` elevation to signal processes. Do not install a helper, grant Linux capabilities, add a service, change polkit rules, enable remote monitoring, terminate or suspend a process, or start, stop, enable or disable a service. Before any future privileged action, identify the exact PID or unit, owner, executable, signal/action, dependent workloads, unsaved-data risk, elevation boundary and recovery route. Treat a changing PID as invalid and re-resolve it immediately before approval.

Use metadata-only verification: confirm project provenance, Flathub app ID, origin, installed commit, runtime, architecture, executable, files and declared permissions without running the application. Do not claim that a sensor or GPU feature works merely because the package installed; Intel GPU and desktop-specific limitations must remain visible. Compare process, service, helper, capability, polkit, startup, network and filesystem state to the preflight snapshot. If verification fails, rollback by removing only the newly installed package from its original scope; leave shared runtimes, remotes, monitoring helpers, preferences and system services untouched.
