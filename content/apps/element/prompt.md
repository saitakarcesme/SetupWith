# Element setup prompt

Codex, inspect the OS, architecture, shell, existing Element desktop or web installation, configuration files, homeserver settings, caches, encryption stores, and account state before changes. For desktop use Element’s official signed packages on macOS, Linux, or Windows; for self-hosted web use the official `element-hq/element-web` container or release archive. Ask before administrator access, replacing the application, exposing web ports, changing firewall rules, opening a browser, signing in, clearing caches, or overwriting `config.json`. Preserve local encryption keys, session data, trusted-device state, custom branding, and existing homeserver configuration. Configure only `homeserver_url`, `default_server_name`, `theme`, and `brand_name` when supplied. Do not request or handle account passwords or recovery keys. Validate homeserver URLs and well-known discovery without authenticating. Verify package or image identity, application launch or web readiness, configuration parsing, homeserver reachability, theme and branding, and access to the unauthenticated login screen. Never create a Matrix account automatically. Rollback restores config and cached settings, removes only the desktop package or web container created here, and never deletes encryption stores without explicit approval. Finish with a structured summary of deployment mode, homeserver, branding, theme, connectivity, verification, approvals, and rollback.
