# Commit setup prompt

Set up Commit from its official project and verified Flathub listing (https://flathub.org/apps/re.sonny.Commit). Inventory Linux architecture, Flatpak scopes, existing package and data paths, Git and Mercurial editor-setting presence by scope, saved formatting and spellcheck preferences, pending-editor process count, sandbox overrides and backup coverage without entering repositories or revealing paths, branches, commit text, diffs, comments, issue references, authors, trailers, environment values, tokens or project identities. Install stable `re.sonny.Commit` from verified Flathub in the existing ownership scope. Do not compile from source, launch Commit, change `core.editor`, `sequence.editor` or Mercurial configuration, open a repository, read a message or diff file, start or continue a commit, merge, tag, patch or rebase operation, save text, exit an editor process or invoke Git or Mercurial during setup.

Preserve every existing editor command byte and scope, repository state, index, worktree, pending operation, temporary message file, comments, formatting preferences, remotes, overrides and scope ownership. Commit messages and diffs may expose unreleased work, incident details and credentials; redact them. Installation is separate from editor integration: never replace an existing editor, alter shell quoting, launch on repository events, stage files, write a message, continue an operation or imply a commit was created.

Before later integration, resolve the exact executable and arguments without shell interpolation and preview the precise Git or Mercurial config diff at the chosen local, global or system scope. Keep `core.editor` distinct from `sequence.editor`. Test only in a disposable synthetic repository with no remotes or hooks. Detect commit, merge, annotated-tag, add-patch, interactive-rebase and Mercurial file contracts independently; their comments, allowed edits and exit semantics differ. Respect the repository's comment character, cleanup mode, encoding and final-newline expectations. Read-only comments and status or diff material must never enter the saved message.

Formatting aids are suggestions bounded by team policy: preview capitalization, blank-line insertion and body reflow before applying them, and preserve trailers and deliberately wrapped text. Save must atomically update only the provided temporary file and return the documented success status; Abort must leave it unchanged and return the cancellation status expected by the parent VCS. Verify provenance, app ID, origin, commit, runtime, executable, files and static permissions offline. Prove no config, repository, worktree, index, message, diff, operation, temporary file, Git or Mercurial process changed. On failure, rollback only the new Commit ref in its original scope; preserve shared runtimes, remotes, overrides, VCS editor settings, repositories, pending operations, preferences and backups.
