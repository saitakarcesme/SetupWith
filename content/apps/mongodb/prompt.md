# MongoDB setup prompt

Codex, inspect the operating system, architecture, active shell, existing `mongod` and `mongosh` binaries, package ownership, configuration files, data directory, running services, port 27017, and available backups before making changes. On macOS prefer MongoDB Community through the official Homebrew tap; on Debian/Ubuntu or Fedora-family systems use MongoDB’s official signed repository and Community packages; on Windows use MongoDB’s official MSI or supported `winget` package. Ask before administrator access, adding repositories, enabling services, opening ports, modifying firewall rules, initializing storage, changing authentication, or overwriting configuration. Preserve databases, journals, replica-set metadata, users, `mongod.conf`, logs, and service definitions. Configure only `mongo_user`, `mongo_database`, `mongo_port`, and `data_directory` when supplied. Use `secret://provider/MONGO_INITDB_ROOT_PASSWORD` through protected initialization input; never print, echo, log, or place it in command history. Bind to localhost by default and create requested users idempotently with least privileges. Verify package identity, `mongod --version`, `mongosh --version`, service health, local authenticated connectivity, database ownership, and a disposable insert-query-delete cycle. Rollback restores config and prior service state, removes only a newly created empty instance after approval, and never deletes existing data automatically. Finish with a structured summary of package source, instance, user, database, port, checks, approvals, and rollback.
