# Helm setup prompt

Codex, inspect the OS, architecture, shell, existing `helm` binary, plugins, repositories, cache directories, kubeconfig, current Kubernetes context, and namespace before installation. On macOS prefer Homebrew `helm`; on Linux use Helm’s official signed package repository or verified release binary; on Windows prefer `winget install Helm.Helm`. Ask before administrator access, adding repositories, installing plugins, changing kubeconfig context, logging into registries, creating namespaces, or installing, upgrading, or uninstalling releases. Preserve Helm repositories, cache, plugins, registry config, and all cluster resources. Configure only `default_namespace`, `repository_cache`, and `plugins_directory` when supplied. Reference `secret://provider/HELM_REGISTRY_CONFIG` only as a protected credential-file alias; never print, log, or copy its contents. Validate custom paths and permissions before use. Verify `helm version`, `helm env`, repository listing, plugin listing, and template rendering of a small local disposable chart without contacting a cluster. If an approved cluster is available, run `helm list` read-only in the chosen namespace. Rollback restores Helm environment and repository backups, removes only plugins or repositories added here, and uninstalls only the CLI package. Finish with a structured summary of install source, namespace, paths, repositories, cluster access, verification, approvals, and rollback.
