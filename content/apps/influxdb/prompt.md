# InfluxDB setup prompt

Set up InfluxDB from its verified official source (https://github.com/influxdata/influxdb). Supported targets: macOS, Linux, Windows. Begin with a read-only preflight covering the operating system, architecture, shell, package managers, disk space, relevant runtimes or hardware, and any existing installation. Choose the intended InfluxDB major release first, then use its official package, binary, or container with explicit data and configuration paths; never perform an implicit major-version migration.

Preserve engine data, write-ahead logs, metadata, configuration, tokens, organizations, buckets, backups, and container volumes. Back up files before editing and explain the selected version, source, location, dependencies, and commands. Apply only supplied, supported preferences: data_directory, retention_policy, listen_address, listen_port, deployment_mode. The only available credential references are secret://influxdb/token. Treat every reference as opaque: never print, echo, log, resolve, or paste its value.

Ask before elevation, system-wide packages, services or startup items, ports or firewall rules, sign-in, large downloads, overwrites, or migrations.  Do not enable startup items, background services, overlays, notifications, analytics, or device permissions unless they are requested and separately approved. Do not initialize, upgrade, delete, compact, expose a port, create tokens, or start a persistent service without approval. For a large game or media download, report the exact size, destination drive, free space, and bandwidth impact, then wait for approval. Never delete game libraries, save files, media libraries, mods, profiles, or cloud-sync data. If the platform or configuration is unsupported, stop and offer the closest official alternative.

Check the binary version and configuration, then use only a fresh temporary data directory for an approved loopback health check before stopping the process. Report the version, executable, configuration and data paths, changed files, active processes or listeners, and verification evidence without exposing sensitive values. End with manual steps and exact rollback or uninstall instructions that remove only setup-owned changes, restore backups, stop new services, and preserve user data.
