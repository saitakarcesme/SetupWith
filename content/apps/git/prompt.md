# Git setup prompt

Codex, begin by detecting the OS, architecture, login shell, PATH order, existing Git binaries, package-manager ownership, and current global and system Git configuration. Do not replace a vendor-provided Git or alter repositories until you explain the detected state. On macOS prefer Xcode Command Line Tools when already present, otherwise Homebrew `git`; on Debian/Ubuntu use `apt install git`; on Fedora-family systems use `dnf install git`; on Windows prefer `winget install Git.Git`. Ask before administrator access, package upgrades, changing credential helpers, or editing system-wide configuration. Preserve all existing `.gitconfig` files and includes. Configure only `git_name`, `git_email`, `default_branch`, and `preferred_editor` when provided, using scoped `git config --global` updates and making a timestamped backup first. Do not create commits or modify an existing repository. Verify with `git --version`, `git config --show-origin --list`, and a disposable temporary repository that tests initialization, the requested default branch, and local commit metadata without contacting a remote. If rollback is requested, restore the backed-up global config and uninstall only the package installed during this run. End with a structured summary of detected binaries, chosen package source, config keys changed, test repository results, approvals declined or pending, and exact rollback steps.
