# Cilium setup prompt

Set up Cilium from its verified official source (https://github.com/cilium/cilium). Supported targets: Linux. Begin with a read-only preflight covering the operating system, architecture, shell, package managers, disk space, relevant runtimes or hardware, and any existing installation. Install the official Cilium CLI separately from deploying Cilium agents, and first confirm Linux kernel, eBPF, container runtime, Kubernetes, and existing CNI compatibility.

Preserve kubeconfig files, current contexts, cluster networking, CNI configuration, NetworkPolicies, Cilium values, certificates, and observability state. Back up files before editing and explain the selected version, source, location, dependencies, and commands. Apply only supplied, supported preferences: kube_context, cluster_name, cni_mode, hubble_enabled. The only available credential references are secret://kubeconfig/credential. Treat every reference as opaque: never print, echo, log, resolve, or paste its value.

Ask before elevation, system-wide packages, services or startup items, ports or firewall rules, sign-in, large downloads, overwrites, or migrations.  Do not enable startup items, background services, overlays, notifications, analytics, or device permissions unless they are requested and separately approved. Do not switch contexts, install or upgrade the CNI, restart nodes, modify routes or firewall state, enable Hubble, or contact a cluster without approval. For a large game or media download, report the exact size, destination drive, free space, and bandwidth impact, then wait for approval. Never delete game libraries, save files, media libraries, mods, profiles, or cloud-sync data. If the platform or configuration is unsupported, stop and offer the closest official alternative.

Run `cilium version --client`; perform no cluster status check by default, and explain the selected kube context before any read-only API request. Report the version, executable, configuration and data paths, changed files, active processes or listeners, and verification evidence without exposing sensitive values. End with manual steps and exact rollback or uninstall instructions that remove only setup-owned changes, restore backups, stop new services, and preserve user data.
