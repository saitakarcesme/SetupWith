# Authenticator setup prompt

Set up Authenticator from its official GNOME project and verified Flathub listing (https://gitlab.gnome.org/World/Authenticator). Inventory Linux architecture, Flatpak scopes, existing Authenticator package and data paths, secret-service availability, keyring portal and fallback behavior, application-lock state, backup policy, favicon-download preference, search-provider state and system clock source without reading any account or seed. Install stable `com.belmoussaoui.Authenticator` from verified Flathub in the existing ownership scope. Do not build from source, launch the app, unlock a keyring, import a token or generate a code during setup.

Preserve every TOTP, HOTP and Steam record, issuer, account label, secret seed, HMAC algorithm, digit count, period, HOTP counter, favorite, icon, lock preference and keyring item byte-for-byte. OTP seeds are account takeover credentials; never print, hash for diagnostics, copy, validate against a live service or expose them through process arguments. Do not change system time, NTP, timezone or HOTP counters. Clock accuracy can affect TOTP validity, but time configuration is outside this package-only setup.

QR images and `otpauth` URIs contain the seed. Do not request camera access, capture a screenshot, open an image, parse a URI or inspect the clipboard. Backup and restore formats differ: some exports may be plaintext, some encrypted, and importing can duplicate or overwrite records. Before any future export or restore show format, encryption, password handling, destination permissions, synchronized-folder status, included issuers, duplicate strategy and tested recovery plan without exposing secrets. Never create a backup as an installation test.

Favicon downloads can reveal provider names and Shell search can expose account labels or short-lived codes in the desktop overview and notifications. Keep both in their current state; do not fetch icons, query search, copy a code or alter clipboard lifetime. Verify package provenance, app ID, origin, commit, runtime, executable, files and permissions offline without opening the app database or keyring. Prove no keyring unlock, seed access, counter, backup, camera portal, screenshot, icon request, search result, notification, clipboard or network state changed. On failure, rollback only the new Authenticator ref in its original scope; preserve shared runtimes, remotes, overrides, databases, keyrings and all recovery material.
