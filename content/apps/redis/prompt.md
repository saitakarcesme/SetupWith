# Redis setup prompt

Codex, first inspect the OS, architecture, shell, existing Redis binaries, package ownership, configuration files, data directory, active services, persistence files, port 6379, and backups. Prefer Homebrew `redis` on macOS, the distribution’s Redis package on Linux, and on Windows use an approved WSL or container deployment because upstream Redis does not provide a standard native Windows server. Ask before administrator access, installing a container engine, enabling or restarting a service, opening ports, changing firewall rules, replacing configuration, or deleting persistence data. Preserve `redis.conf`, ACL files, RDB snapshots, AOF files, and service definitions. Configure only `redis_port`, `maxmemory`, `persistence_mode`, and `data_directory` when supplied. Use `secret://provider/REDIS_PASSWORD` through a protected ACL or configuration mechanism; never print, echo, log, or expose it in command arguments. Bind to loopback and enable protected mode unless remote access is explicitly approved. Verify `redis-server --version`, `redis-cli --version`, config parsing, service health, authenticated `PING`, memory limits, persistence status, and a disposable key with expiry. Rollback restores configuration and prior service state, removes only newly created deployment resources, and never deletes RDB or AOF data without approval. End with a structured summary of deployment, bind address, persistence, memory, authentication, verification, approvals, and rollback.
