# Junction setup prompt

Set up Junction from its official repository and verified Flathub listing (https://apps.gnome.org/Junction/). Inventory Linux architecture, Flatpak scopes, existing Junction package and data paths, desktop environment, portal implementation, and the names—not invocation commands—of current user and system defaults for HTTP, HTTPS, file, mailto and registered MIME types. Capture a protected restoration snapshot of handler associations without opening any target. Install stable `re.sonny.Junction` from verified Flathub in the existing ownership scope. Do not compile from source, launch Junction, register it as a handler, change a default, follow a link or open a file during setup.

Preserve every MIME and URI-scheme association, desktop-file override, portal choice, remembered application, browser profile and sandbox permission. URLs may contain reset tokens, search terms, document IDs or credentials, while local paths reveal people and projects; never print either in diagnostics. Junction can display and edit a destination before opening, but that preview does not establish sender trust, content safety or final redirect identity. Treat internationalized domains, punycode, mixed scripts and HTTP downgrade as explicit review signals.

Before any future handler registration show the exact schemes or MIME types affected, current effective handler at each scope, Junction desktop-file identity, portal interaction, command arguments and a reversible restoration command. Avoid broad wildcard claims. A candidate application must be installed from a known source and appropriate for the target type; do not expose a private file to a cloud editor or pass a sensitive URL to an unintended browser profile. Editing a URL changes the destination and must require confirmation.

Middle-click or Ctrl+Click can open one target in multiple applications, multiplying network requests, downloads, login effects and telemetry. Keep multi-open deliberate and never use it for verification. Test only association metadata offline; do not synthesize a URL, touch browser history, activate desktop actions or persist a remembered choice. Verify Junction provenance, app ID, origin, commit, runtime, executable, desktop file, declared MIME/scheme claims, files and permissions. Prove no handler, portal, browser, network, file-open, clipboard, history or preference state changed. On failure, rollback only the new Junction ref in its original scope and restore associations only if this setup changed them; preserve runtimes, remotes, overrides and every pre-existing default.
