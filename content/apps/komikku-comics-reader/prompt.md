# Komikku setup prompt

Set up Komikku from its official project and verified Flathub listing (https://apps.gnome.org/Komikku/). Inventory Linux architecture, Flatpak scopes, existing package and data paths, library/category counts, local content roots, enabled-server count, cached/downloaded byte totals, tracking-service count, auto-update policy and secret-store boundary without listing titles, reading history, server names, paths or credentials. Install stable `info.febvre.Komikku` from verified Flathub in the existing ownership scope. Do not compile from source, launch Komikku, scan a library, contact a server, authenticate, render a page, update series or download content during setup.

Preserve every series, category, favorite, reading direction, chapter progress, history entry, cache, offline download, server configuration, tracker token and preference. Reading history can reveal identity, beliefs, sexuality or health interests; redact it from diagnostics and notifications. Never enable every server by default, bypass regional restrictions, assume hosted material is authorized or delete cached/offline chapters merely because a source disappears. Confirm the user's rights and each source's terms before access.

Treat local CBZ/CBR/CBT, EPUB and PDF files plus remote images and metadata as untrusted input. Before parsing show provenance, checksum, format, size, file count, compressed and expanded limits, symlink/path-traversal checks, decoder boundary and isolated destination. Do not execute embedded scripts, follow external links or extract outside a temporary sandbox. Automatic updates and downloads can create sustained traffic and disk use; require approved servers, interval, metered/battery policy, quota, duplicate handling and partial-download cleanup.

AniList, MangaUpdates and MyAnimeList tracking writes personal progress to third parties. Before connection show exact OAuth origin, requested scopes, account visibility, activity-feed effects, initial direction and conflict rules. Never overwrite local progress or publish activity silently; use a dedicated revocable token where supported. Verify provenance, app ID, origin, commit, runtime, executable, files and permissions offline. Prove no library scan, archive parse, network request, tracker access, progress mutation, cache, download, notification or filesystem state changed. On failure, rollback only the new Komikku ref in its original scope; preserve runtimes, remotes, overrides, libraries, downloads, history and credentials.
