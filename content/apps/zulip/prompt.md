# Zulip setup prompt

Codex, first inspect the OS, architecture, shell, existing Zulip server deployment, Docker support, PostgreSQL, Redis, RabbitMQ, uploads, configuration, hostname, and occupied ports. Prefer Zulip’s official production installer on a supported Ubuntu server; use the official Docker image only for development or evaluation according to Zulip documentation. Do not pretend macOS or Windows are supported production hosts. Ask before administrator access, installing system services, creating databases, running migrations, exposing ports, changing firewall rules, opening a browser, configuring email, or overwriting deployment files. Preserve realms, messages, users, uploads, database backups, secrets, and configuration. Configure only `external_host`, `server_port`, and `default_language` when supplied. Inject `secret://provider/ZULIP_ADMINISTRATOR`, `secret://provider/POSTGRES_PASSWORD`, and `secret://provider/SECRET_KEY` through protected installer inputs or secret files; never print, echo, log, or commit values. Keep the instance private until DNS, TLS, and outbound email are approved. Verify services, database migrations, queue workers, web health, static assets, and login-page access without creating users. Rollback uses supported uninstall or service removal steps, restores backups, and retains database and uploads unless deletion is authorized. Finish with a structured summary of support status, deployment, hostname, services, language, verification, approvals, and rollback.
