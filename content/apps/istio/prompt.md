# Istio setup prompt

Set up Istio from its verified official source (https://github.com/istio/istio). Supported targets: macOS, Linux, Windows. Begin with a read-only preflight covering the operating system, architecture, shell, package managers, disk space, relevant runtimes or hardware, and any existing installation. Install the official `istioctl` release matching the intended control-plane version, keeping the client binary separate from any service-mesh installation or upgrade.

Preserve kubeconfig files, current contexts, IstioOperator resources, Helm values, namespaces, gateways, policies, certificates, and workload labels. Back up files before editing and explain the selected version, source, location, dependencies, and commands. Apply only supplied, supported preferences: kube_context, cluster_name, istio_profile, mesh_namespace. The only available credential references are secret://kubeconfig/credential. Treat every reference as opaque: never print, echo, log, resolve, or paste its value.

Ask before elevation, system-wide packages, services or startup items, ports or firewall rules, sign-in, large downloads, overwrites, or migrations.  Do not enable startup items, background services, overlays, notifications, analytics, or device permissions unless they are requested and separately approved. Do not connect to a cluster, install or upgrade Istio, inject sidecars, label namespaces, restart workloads, or expose gateways without approval. For a large game or media download, report the exact size, destination drive, free space, and bandwidth impact, then wait for approval. Never delete game libraries, save files, media libraries, mods, profiles, or cloud-sync data. If the platform or configuration is unsupported, stop and offer the closest official alternative.

Run `istioctl version --remote=false`; only after context approval perform read-only precheck or analyze commands and report every namespace they inspect. Report the version, executable, configuration and data paths, changed files, active processes or listeners, and verification evidence without exposing sensitive values. End with manual steps and exact rollback or uninstall instructions that remove only setup-owned changes, restore backups, stop new services, and preserve user data.
