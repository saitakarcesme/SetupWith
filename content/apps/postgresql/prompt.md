# PostgreSQL setup prompt

Codex, first inspect the OS, architecture, shell, existing PostgreSQL clients and servers, package ownership, cluster versions, data directories, running services, occupied port 5432, and backups. Prefer Homebrew `postgresql` on macOS, the distribution’s supported PostgreSQL packages on Linux, and the official PostgreSQL installer or `winget` package on Windows. Ask before administrator access, installing or enabling a service, initializing a cluster, changing ports or firewall rules, upgrading a cluster, resetting passwords, or overwriting data directories. Preserve all databases, roles, `postgresql.conf`, `pg_hba.conf`, WAL, and service definitions. Configure only `postgres_user`, `postgres_db`, `postgres_port`, and `data_directory` when supplied. Use `secret://provider/POSTGRES_PASSWORD` through a non-printing password mechanism; never echo, log, or place it in command history. Default to local connections and conservative authentication. Create the requested role or database only after confirming they do not exist. Verify with `postgres --version`, `psql --version`, `pg_isready`, service status, a local connection, and a disposable table transaction. Rollback restores configuration and service state, removes only a newly initialized empty cluster after approval, and never deletes existing data automatically. Finish with a structured summary of package, cluster, role, database, port, checks, approvals, backups, and rollback.
