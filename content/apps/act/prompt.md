# act setup prompt

Set up act from its official nektos/act release and installation guide (https://nektosact.com/installation/index.html). Detect the operating system, architecture, shell, package managers, existing `act` binary, Git repository root, active Docker context, and whether a compatible Docker API endpoint is reachable. Prefer a signed or checksummed release through the documented Homebrew, Winget, Scoop, Chocolatey, Arch, Nix, or GitHub CLI method. Do not build an unpinned development revision.

Before executing anything, enumerate workflow files and use `act --list` for the requested event or workflow. Explain that act mounts repository content, downloads runner images and actions, and runs workflow commands with access to a container engine; it is not a perfect replica of GitHub-hosted runners. Preserve `.github/workflows`, local actions, `.actrc` files at XDG, home, and repository scope, event payloads, variable files, secret files, Docker contexts, images, containers, volumes, caches, and artifact directories. Apply only the requested runner image, container architecture, artifact path, or container reuse behavior.

Treat every workflow and referenced action as executable, potentially untrusted code. Stop before running jobs, pulling large runner images, mounting the Docker socket, using host networking, running privileged containers, writing artifacts, contacting external services, or reusing a container. Never put token values on the command line or in shell history. If a GitHub token is required, use only the opaque `secret://github/token` reference through act's secure prompt or a permission-restricted temporary secret file, and remove only that setup-created file afterward. Do not infer production secrets from GitHub CLI, environment variables, or repository files.

Verify the installed version and executable provenance, parse help output, list workflows and jobs without execution, and show the exact event, workflow, job, runner image, mounts, network mode, and secret names that a later approved run would use. Confirm that no job ran, no image was pulled, no container or volume was created, and no workflow, `.actrc`, credential, Docker context, or artifact changed. End with a rollback that removes only the installed act binary or setup-owned configuration while preserving repositories and container data.
