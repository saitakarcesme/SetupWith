# Logseq setup prompt

Codex, begin by detecting the OS, architecture, shell, existing Logseq application, graph directories, configuration, plugins, themes, journals, and synchronization settings. Install the official signed Logseq desktop release using the native package for supported macOS, Linux, or Windows systems. Ask before administrator access, replacing an existing app, registering file associations, opening a browser, enabling account synchronization, installing plugins, or modifying graph files. Preserve every graph, `config.edn`, custom CSS, plugin data, assets, and Git history. Configure only `graph_directory`, `preferred_format`, and `default_theme` when supplied. Validate that the selected graph directory is not nested inside another graph and that `preferred_format` is supported. Never convert Markdown and Org files in bulk without explicit approval and a full backup. Apply theme changes through existing settings without overwriting custom CSS. Verify application launch, graph indexing, journal creation in a disposable test graph, linked-page behavior, and persistence of format and theme settings. Do not touch the user’s primary graph for functional testing. Rollback restores settings and removes only the temporary graph and installed application, while leaving existing notes and plugins intact. Finish with a structured summary of installation source, graph paths, format, theme, verification, approvals, backups, and rollback.
