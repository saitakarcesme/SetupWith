# Neovim setup prompt

Codex, first inspect the operating system, CPU architecture, shell, terminal capabilities, existing `nvim` binary, package-manager ownership, and current Neovim configuration directories. On macOS prefer Homebrew `neovim`; on Debian/Ubuntu use the distribution package unless it is clearly too old for the user’s existing configuration, then explain safer alternatives; on Fedora-family systems use `dnf install neovim`; on Windows prefer `winget install Neovim.Neovim`. Ask before administrator access, replacing another editor command, installing fonts, or modifying shell aliases. Preserve `~/.config/nvim`, `init.lua`, `init.vim`, plugin lockfiles, and data directories. Configure only `preferred_shell`, `editor_theme`, and `leader_key` when provided. Merge settings into a clearly marked SetupWith block or separate Lua module, and never overwrite an existing configuration. Do not install a plugin manager unless requested; if a theme requires a plugin, ask first and document it. Verify using `nvim --version`, `nvim --headless '+checkhealth' +qa`, and a temporary file opened in headless mode. Confirm the requested shell option and leader mapping without launching destructive plugin updates. Rollback must remove the marked block or added module and uninstall only this run’s package. End with a structured summary of paths, changes, health results, skipped items, and rollback steps.
