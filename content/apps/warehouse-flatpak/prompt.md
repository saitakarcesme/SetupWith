# Warehouse setup prompt

Set up Warehouse from its official repository and verified Flathub listing (https://github.com/flattool/warehouse). Inventory Flatpak user and system installations, remotes, installed refs, runtimes, branches, origins, masks, pins, EOL markers, `~/.var/app` user-data directories, custom installation locations, Warehouse snapshots, file handlers and any existing Warehouse package. Install stable `io.github.flattool.Warehouse` from its verified Flathub origin in the scope matching current ownership. Do not install a release bundle, source build or alternate branch, and do not add a remote merely to satisfy setup without approval.

Install without launching Warehouse or letting it scan, classify or modify Flatpak state. Preserve every installed ref, commit, origin, branch, runtime, mask, pin, update policy, remote definition, trust setting, application data directory, leftover directory, snapshot, custom location and handler. Warehouse assumes the default user-data root is `~/.var/app`; never label data elsewhere as absent or leftover from that assumption. Application data can contain accounts, tokens, documents, browser state and encryption material, so do not list its contents in logs or include it in a new snapshot without consent.

Treat install, reinstall, uninstall, version change, mask, pin, data deletion, remote mutation and snapshot restore as separate state-changing operations. Never batch them under one approval. Before any future action show exact app ID or runtime ref, user/system scope, current and requested commit, origin, dependent runtimes or applications, data path, byte estimate, elevation need and reversal method. A snapshot is not proven until its scope and restore test are reviewed; never delete source data because a snapshot file merely exists. Removing a remote can strand installed refs, and downgrading can introduce incompatible data formats, so both require dependency and application-data review.

Do not claim `.flatpakref`, `.flatpakrepo` or bundle handlers, launch an installed app, copy identifiers to the clipboard, fetch remote metadata or change system policy during setup. Verify Warehouse provenance, app ID, origin, installed commit, runtime, executable, files and declared permissions using Flatpak metadata only. Compare full preflight inventories and prove no ref, runtime, remote, mask, pin, update policy, user data, snapshot, handler, process or network state changed. On failure, rollback only the newly installed Warehouse ref from its original scope; retain shared runtimes, remotes, snapshots and all application data.
