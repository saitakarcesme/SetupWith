# moon setup prompt

Set up moon from the official moonrepo installation guide (https://moonrepo.dev/docs/install). Detect the operating system, architecture, shell, package managers, existing `moon` and `proto` binaries, repository root, package manager, lockfiles, workspace boundaries, `.moon` configuration, `.prototools`, CI files, and current Git status. Prefer a project-pinned proto installation or the documented project-local npm development dependency; explain the version resolution and PATH impact before choosing a global single-version install or download script.

Install the binary without initializing or migrating the repository. Preserve project sources, task inheritance, toolchain definitions, dependency graphs, lockfiles, package-manager settings, environment files, cache directories, generated outputs, CI pipelines, remote-cache configuration, and every uncommitted change. Apply only explicitly requested project sources, task definitions, toolchains, or cache policy. Before writing `.moon/workspace.yml`, `.moon/tasks.*`, `.moon/toolchains.*`, or `.prototools`, show the full proposed diff and how project discovery, task inputs/outputs, and dependency edges will change.

Treat every moon task as arbitrary repository code. Never run `moon run`, `moon check`, `moon ci`, lifecycle hooks, dependency installation, sync, code generation, formatting, or teardown during setup. A configured toolchain version may automatically download runtimes, change PATH resolution, and install dependencies on first task execution; require approval for each tool and version. Do not hydrate untrusted cache artifacts, upload outputs that may contain secrets, connect remote cache or moonbase, clean `.moon/cache`, modify lockfiles, or infer task outputs. Keep environment and credential files excluded from task inputs, outputs, logs, and cache keys.

Verify package provenance, `moon --version`, resolved binary and version pin, then use read-only project and task listing or graph inspection without executing tasks or serving a browser graph. Report detected projects, task names, toolchain requirements, dependency edges, cache locations, and configuration diagnostics. Confirm no runtime, dependency, cache artifact, generated file, lockfile, CI file, or repository source changed and Git status matches its baseline. Roll back only the setup-installed binary, version pin, and approved configuration additions; preserve all workspace files and caches unless their setup-created paths are individually reviewed.
