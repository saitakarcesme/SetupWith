# AppFlowy setup prompt

Codex, inspect the operating system, architecture, shell, existing AppFlowy desktop installation, workspace data, local database, plugins, synchronization configuration, and application settings before changes. Use AppFlowy’s official signed desktop release for supported macOS, Windows, or Linux platforms; prefer the native package format and verify publisher or checksum information when available. Ask before administrator access, replacing the application, changing file associations, enabling startup behavior, opening a browser, signing into cloud synchronization, or moving workspace data. Preserve all local workspaces, documents, databases, templates, and account settings. Configure only `workspace_directory`, `default_language`, and `appearance` when supplied. Validate the workspace destination, ensure adequate disk space, and copy rather than move existing data unless migration is explicitly approved. Do not enable cloud sync or account login automatically. Verify application launch, workspace discovery, database readability, language and appearance persistence, and creation plus deletion of a temporary local page. Confirm the test remains local. Rollback restores backed-up settings, reverts any workspace path change, and removes only the application installed in this run, leaving user workspaces untouched. Finish with a structured summary of package source, workspace, language, appearance, migration actions, verification, approvals, and rollback.
