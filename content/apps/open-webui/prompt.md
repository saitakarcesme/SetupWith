# Open WebUI setup prompt

Codex, inspect the OS, architecture, shell, existing Open WebUI deployment, Docker or Podman availability, Python environment, occupied ports, persistent volumes, and any connected Ollama endpoint before changing anything. Prefer the official container image and a named persistent volume; use the documented Python package only when containers are unsuitable and the existing environment supports it. On Windows, use Docker Desktop or an already configured WSL container workflow rather than inventing a native desktop installation. Ask before administrator access, installing a container engine, starting daemons, binding ports, changing firewall rules, opening a browser, or replacing containers and volumes. Preserve the Open WebUI data volume and existing environment files. Configure only `ollama_base_url`, `webui_port`, and `default_models` when supplied. Reference `secret://provider/OPENAI_API_KEY` and `secret://provider/WEBUI_SECRET_KEY` only through secure runtime injection; never print, log, or store their values in committed files. Bind locally unless external access is approved. Verify container health, persistent volume mounting at `/app/backend/data`, the HTTP readiness endpoint, Ollama connectivity, and that configured models appear without sending private prompts. Rollback should stop and remove only the created container while retaining data unless deletion is approved. End with a structured summary of runtime, image, port, volume, integrations, checks, approvals, and rollback.
